# 战斗信息解析器与三档感知审计

- 日期：2026-07-17
- Agent/thread：`/root`
- 范围：实现不接 Agent 的纯程序战斗信息解析器，并检查关键信息遗漏与信息越界
- 状态：本阶段完成；尚未接入玩家请求

## 用户目标

把战斗原始信息先翻译成不带职业偏见的玩家语言，再让低、普通、高三档玩家分别感知约 25%、50%、75%。本阶段只做固定类型的代码解析和审计，不接入真实 Agent。

## 已完成

- 新增独立的 `battle-information-parser.js`。
- 只接收界面可见事件；隐藏事件直接拒绝。
- 支持战斗结果、场地效果、伤害、治疗、护盾、状态、技能、死亡、战利品、地图开放和角色开放。
- 敌人只按本场实际行为描述：
  - “表现出远程攻击的敌方单位”
  - “使用过治疗的敌方单位”
  - “使用过护盾的敌方单位”
- 不再把 `priest` 翻译成“后排治疗”，也不从职业名推断站位、固定职责或未来行为。
- 三档使用同一份按重要性排序的合法信息：
  - 低感知：25%
  - 普通感知：50%
  - 高感知：75%
- 三档结果严格嵌套：低感知看到的内容一定包含在普通档，普通档一定包含在高档。
- 把重复状态和技能合并为战斗级摘要，避免逐事件刷屏。
- 神话、稀有等装备品质翻译为玩家可读中文。

## 验证结果

固定 17 事件样本：

- 形成 14 条合法候选信号。
- 低、普通、高三档分别得到 4、7、11 条。
- 战斗结果、场地、死亡、伤害、治疗、护盾、状态、技能、战利品和地图开放全部形成对应信息。

真实存档 355 事件战斗：

- 352 条属于支持的可见事件，压缩成 22 条候选信号。
- 低、普通、高三档分别得到 6、11、17 条。
- 原来逐条出现的状态/技能已经合并，不再淹没角色贡献和战后奖励。

越界检查全部通过：

- 无临时敌人名和 ID。
- 无敌方内部 role。
- 无 `diagnosis`、`H`、`emotionDelta`。
- 无原始事件 ID。
- 无“牧师必在后排”等倾向性推断。
- 隐藏事件和内部换人实验、动作汇总没有进入玩家输出。

## 对“有没有漏掉关键信息”的判断

在解析器的合法候选层，没有漏掉当前存档实际出现的关键战斗类型。战斗胜负、可见场地、倒下角色、敌方伤害表现、我方角色贡献、治疗、护盾、状态、战利品和地图开放都有对应摘要。

感知较低的玩家会主动漏掉一部分信息，这是设计目标，不是解析缺失。战斗结果优先级最高；普通玩家已经能够看到主要角色贡献，保证后续角色印象仍有输入。

## 对“有没有多给或给得不合理”的判断

第一版审计发现状态和技能虽然都是可见信息，但逐项列出会过量，并挤掉战利品等更值得记住的信息。现已按敌我双方压缩成摘要。

当前输出仍会使用“远程攻击表现”这样的观察描述，但它只由本场可见箭矢、射击等表现产生，不会把敌人永久定义成远程职业。治疗、护盾同理，都使用“本场使用过”限定。

## 尚未完成

- 解析器尚未接到 `player-agent-loop.js`，所以现有真实 Agent 请求仍可能通过旧知识入口看到原始 diagnosis。
- 现有 `signal-concept-interpreter.js` 仍保留旧的“远程小怪/近战小怪”身份式概念；接入时需要决定是替换它，还是让本解析器成为其玩家输出层。
- 25%/50%/75% 目前按“压缩后的信号条数”计算，不是按注意力时间或信息量加权。作为第一版固定解析器可用，但以后可以让角色熟悉度、目标相关性和画面竞争共同影响排序。

## 推荐下一步

保持本轮不接 Agent 的边界。下一步若继续，先用解析器替换 `learnFromChallenge` 中原始 diagnosis 展开，再让决策和归因请求只读取解析后的信号，并运行现有玩家请求泄漏回归。
