# Agent 交接：过滤后的类型1因果知识

- 日期：2026-07-18
- Agent/任务：Codex `/root`
- 范围：把非角色信息过滤结果恢复成旧“主体-环境-行为-结果”知识
- 状态：隔离程序和真实22场验证完成；尚未替换正式类型1入口

## 用户意图

角色认知已经可用，但新模块输出的“本场胜利、出现场地、敌人用了护盾”等句子不能帮助决策。应恢复以前的类型1设计：主体、环境、行为、结果，并让过滤后的知识更有逻辑。

## 已完成

- 将 `received-information-organizer.js` 从“观察句子路由”升级为旧式类型1关系构建器。
- 信息筛选仍只决定玩家接收到哪些瞬时证据；最终输出必须满足“主体 + 环境 + 行为 → 结构化结果”。
- 删除 `observe_*`、`receive_*` 伪因果行为，以及把单句说明直接当结果的做法。
- 新增关卡挑战关系：具体四人队伍、具体关卡、挑战行为、胜负/存活/表现分。
- 新增通关后地图、掉落、角色解锁关系。
- 新增场地规则关系，并明确单场只记录场地与表现同时出现，不把一次胜负直接断言为场地造成。
- 新增敌方攻击、治疗、护盾、状态和额外技能关系；敌方只按可见行为命名，不泄漏临时身份或内部职业。
- 地图、实际掉落、角色解锁和持续场地规则改为必达事实，不受随机感知遗漏。
- 每条关系生成与旧正式知识库一致的合并键预览；正式接入后可继续使用旧样本数、结果分布和最多八条近期观察。
- 角色信号继续在形成类型1观察前分流，概率机会继续进入专用账本。

## 当前状态

例如最后一关会形成以下三条决策关系：

- 当前四人队伍，在第二章Boss关挑战Boss → 胜利、21.44秒、4人存活、表现分0.878。
- 当前四人队伍，在第二章Boss关通关 → 掉3件装备，但装备战力1250没有自动变化。
- 远程攻击型敌人，在第二章Boss环境攻击我方 → 可见伤害属于主要部分、观察11次、主要打灰鸦战士。

新模块仍不保存第二份知识库，只输出 `mergeKnowledgeObservation` 候选。正式旧类型1知识库没有被关闭或替换。

## 未解决

- 当前仍是隔离程序，尚未让候选调用正式旧知识库的合并入口。
- 这次只改战斗/通关产生的类型1关系；换装和换人动作仍由旧正式入口处理。
- 敌方行为目前按“远程、近身、治疗、护盾、状态”等可见行为模式泛化；不同敌人在同一关卡类型中表现相似时会合并，是否需要更细的玩家可见概念仍需后续观察。
- 场地关系目前明确标记为“可见规则与战斗表现同时出现”；要判断场地造成多少变化，仍需要重复对照，而不是单场归因。
- `105` 个键是否仍偏多，需要用户先看实际关系，再决定是否进一步按决策用途压缩。
