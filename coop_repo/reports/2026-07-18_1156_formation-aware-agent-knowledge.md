# Agent 交接：保留站位并由 Agent 使用历史知识

- 日期：2026-07-18
- Agent/任务：Codex `/root`
- 范围：纠正类型1关卡知识中的站位语义和职责边界
- 状态：隔离程序、精准测试和全量回归完成；尚未接入正式类型1入口

## 用户意图

同样四名角色交换站位可能产生不同结果，知识不能把两种站位合并。同时，历史战斗知识应由 Agent 阅读和使用；信息整理层只应提供完整事实，不能替 Agent 判断某条历史是否仍然适用。

## 对上一版的纠正

上一版报告 `2026-07-18_1126_encounter-cognition-snapshot.md` 有两处错误设计：

- 将四名角色排序后生成指纹，抹掉了站位差异。
- 新增程序化“历史知识适用性判断”，越过了信息整理层的职责。

本版本已撤销这两点。旧报告保留为历史记录，不能作为当前设计依据。

## 已完成

- 使用真实 `teamIds` 顺序作为站位1到站位4，不再按角色ID排序。
- 队伍知识指纹保留站位顺序；同样四个人交换任意两个站位会生成不同知识键。
- 角色认知快照按真实站位重新排列，修正了此前“角色认知矩阵按强弱排序”与“战斗站位顺序”混用的问题。
- 每个角色同时保存 `formationSlot`、永久角色身份、当时连续认知分、认知等级和证据数。
- 删除 `assessEncounterKnowledgeApplicability` 及其全部程序裁决规则。
- 认知分变化仍保存在每次观察中，但整理层不会输出“可直接预测”“只作历史背景”等结论。
- 类型1关系只说明用途：供 Agent 结合当时站位、角色认知和关卡环境理解这次胜负。

## 当前状态

现在 Agent 将来会看到类似：

```text
关卡：第二章Boss
站位1：灰鸦战士；当时认知分1.971；表现普通
站位2：烬火法师；当时认知分1.951；表现普通
站位3：晨祷牧师；当时认知分0.171；明显偏弱
站位4：林地游侠；当时认知分2.926；有点强
结果：胜利；21.44秒；4人存活；表现分0.878
```

如果站位1和站位2互换，会保存成另一种阵型的历史知识。角色以后变强或变弱时，程序只提供当时分数与当前分数，如何理解这段经历由 Agent 决定。

## 边界说明

这里讨论的是“类型1历史知识如何提供给 Agent”。独立的换人预期数值模块仍是之前已确认的代码算法，它负责生成预期数值；本次没有修改它。不能把两者混成“所有历史知识都由程序裁决”。
