# Agent 交接：战斗知识保存完整角色认知坐标

- 日期：2026-07-18
- Agent/任务：Codex `/root`
- 范围：把角色富集矩阵、前30%标尺和相对认知完整接入类型1战斗知识
- 状态：隔离程序、22场验证和旧系统回归完成；尚未接入正式 Agent 知识输入

## 用户意图

战斗知识中的“认知分”不能含糊。它应明确来自之前完成的角色强度富集体系，并同时保存角色矩阵位置、当时前30%标尺和角色相对标尺的位置，避免整体标尺移动后 Agent 无法理解角色当时为什么被认为强或弱。

## 已完成

- 类型1升级为 V7。
- 删除含义模糊的 `currentCognitionScore` 字段，改为明确的：
  - `cognitionMatrixPosition`：角色在富集强度矩阵里的位置。
  - `cognitionScaleBoundaryPosition`：该场战斗结束时全部已知角色的前30%标尺位置。
  - `cognitionRelativeToScale`：矩阵位置减去标尺位置。
  - `cognitionLevel` / `cognitionLabel`：相对距离翻译后的玩家认知等级。
  - `cognitionInTopThirtyPercent`：该角色当时是否位于标尺集合中。
  - `cognitionEvidenceCount`：该角色已有多少场强度证据。
- 上述数值全部直接读取旧角色认知模型的 `listCurrentStrengthCognition`，没有新造评分或重新计算标尺。
- 继续按真实站位1到4组织四名角色；同样四人换位仍形成不同知识键。
- 继续只向 Agent 提供历史事实，不恢复程序化历史适用性裁决。

## 当前知识示例

```text
当时前30%标尺：1.918
站位1 灰鸦战士：矩阵1.971，相对标尺+0.053，表现普通
站位2 烬火法师：矩阵1.951，相对标尺+0.033，表现普通
站位3 晨祷牧师：矩阵0.171，相对标尺-1.747，明显偏弱
站位4 林地游侠：矩阵2.926，相对标尺+1.008，有点强
挑战第二章Boss：胜利；21.44秒；4人存活；表现分0.878
```

这使 Agent 能区分“角色自身矩阵位置提高”和“全部角色变强导致整体标尺提高”，不会把单独的内部矩阵位置误当成最终玩家感知。
