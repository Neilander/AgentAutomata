结论：**反馈的保存、正式证据、即时GTE编译、checkpoint恢复和后续召回已经真实闭环**。但“召回是否改变最后选择”是另一层问题，不能由编译成功直接推出。

### 2. 单步选择前规划证明“会比较”，但真实两场没有因学习而改选

- 新choice可以枚举公开合法候选，在认知checkpoint fork中逐项设想到下一边界，再比较能源、研究、伤害、母舰等结果；个人已编译反馈可以改变候选预测与分数。
- 受控测试已证明同一公开状态下，compiled反馈能够改变候选评价并让learned与fresh选择分叉。
- 真实revision 7连续两场审计中，第二场125/125个边界都应用了反馈；598次候选应用里84个候选分数发生变化，但胜者分数改变0、改选0，两场行为完全一致。
- 单步玩家两场都到Round 11、研究0并因最大伤害失败；它比旧固定控制器多存活3轮，却失去研究推进，不能称为明确提升。

结论：学习确实进入预测和候选比较，但只看下一边界会系统性低估“先投入、后结算”的组合收益，多步规划是由真实失败证据导出的下一问题。

### 3. 经历事实与模糊Q轨迹已经分层，并支持有序多操作

- 每次通过可见性、正式提交和完整性闸门的经历形成独立`memoryId`，保存Q前、准确有序`operations[]`、Q后、证据和episode/ticket来源。
- 多次相似经历可以共同支持一条trajectory，trajectory通过`supportingMemoryIds[]`回指全部事实来源。
- GTE current行使用`Q前 + 有序操作序列`；系统同时支持：
  - 从Q前+操作正向预测Q后；
  - 从Q前+Q后反查trajectory及全部memory IDs；
  - 按memory ID还原精确经历。
- 单步只是长度1的`operations[]`；两步和三步按顺序整体保存，反向顺序不会混淆。
- 完整回归152/152通过；真实本地GTE两步烟测的正向查询和成对反查均返回同一memory ID。

结论：数据层已经能够表达并互查多步认知单元，但它不负责自动判断一段长经历应该在哪里切成一个认知单元，也不负责因果归因。

### 4. 多步轨迹唤醒政策已经厘清，但真实自然唤醒仍未观察

- 受控结构化实验把Q前、Q后和操作三条召回路线分开：
  - 从结果切入时只要求Q后触发侧符合；
  - 从场景切入时只要求Q前触发侧符合；
  - 从行为切入时只要求操作触发侧符合。
- 不再把三侧平均，也不要求三侧同时高分；非触发侧的差异不能在召回阶段压制联想，完整轨迹中的成本、副作用和来源仍全部保留给后续筛选。
- 已建立`REAL_USE_CHECKLIST.md`，用`PASS/FAIL/NOT OBSERVED/INVALID SAMPLE`区分自然召回、适用性筛选和规划收益。

结论：触发侧主导的机制在人工受控样本通过；**真实学习所得多步记忆在正式局面中自然进入Top-K仍是`NOT OBSERVED`**，不能用人工fixture替代这个验收。

### 5. 自动逐Q多步规划已经形成真实运行闭环

- 多步规划从“静态动作列表”升级为`Q0 → A1 → Q1 → A2 ...`：每一步在隔离认知fork中自动唤醒真实GTE五槽轨迹和JSON程序，生成的新Q是下一步唯一输入。
- 修复了旧方案的刻舟求剑问题：研究动作使紫船离开后，后续防空锚点会自动失效；换成防空→研究时，两步都能在各自最新Q上继续。
- 白骰重投成为一等随机边界：设想到重投后返回`paused_random`，禁止规划器伪造随机值或跨未知结果声明确定收益；live观察后丢弃旧后缀并从新Q重规划。
- 自动多切入口控制器从当前公开Q形成宏观意图和少量候选，每个候选走真实`imagineSequentialPlan()`；每次只执行最新Q下刚设想的第0步。
- fresh隔离玩家真实连续三回合通过：30个规划切点、72个候选、6次随机暂停后重规划、0手写中间Q、0计划内随机、0正式操作拒绝；相关回归188/188通过。

结论：自动Q链、候选设想、只执行最新一步、随机暂停和live重规划的运行机制已经可用；它仍是隔离实验控制器，尚未替换默认`planCurrentChoice()`。
