## 0. 先说最重要的结论

我们不是在做一个最优游戏机器人，而是在做一个**会像人一样看见有限信息、记住经验、产生联想、在脑内设想动作、犯错、复盘并逐渐学会游戏的模拟玩家**。

目前已经得到一套大体闭合的架构，也分别做通了注意力、五槽轨迹记忆、规则拆轨迹、对象激活、连续设想停止和抽象规则实例化等隔离模块。2026-08-19 又把问题1—6接成了一个可运行的最小单候选设想流水线，并完成隔离 Agent 微型盲测；这证明层间合同能够闭合，但还不等于已经接入正式玩家。当前最有价值的下一步是在 `fb2` 中用真实 GTE、真实已编译轨迹和153项 UFS 注意力逐端口替换微型同构件。

## 1. 研究目标与硬边界

最终希望得到这样的玩家循环：

```text
读教程 / 玩游戏
→ 只接收玩家真的能看到的信息
→ 形成有限而可能有误的认知
→ 面对目标时想起相关知识与动作轨迹
→ 在脑内预想几步后果
→ 判断是否匹配目标
→ 做出实际操作
→ 根据可见反馈修正知识、注意力和轨迹
```

必须长期坚持的边界：

1. 玩家不能读取隐藏数值、未来随机数、标准答案、引擎内部诊断或最优路线。
2. 允许玩家被随机事件误导，也允许预测错误；拟真比“永远正确”更重要。
3. 程序负责状态、合法性、结算和结构校验；AI负责理解、假设、选择与归因。
4. 向量相似度只负责提出联想候选，不能代替事实校验或规则执行。
5. 先做隔离小案例，通过后再接正式玩家；不要用完整长跑掩盖局部结构错误。
6. 不要为了胜率直接写搜索器或手工策略，然后把它叫作玩家认知。
7. 研究报告和给用户的说明默认使用中文。

## 2. 当前整体结构

下面这条是当前认可的主流程：

```text
【学习阶段】
玩家可见教程 / 新经历
    ↓
规则阅读器或经历抽取器
    ↓ 生成
五槽状态 q1 → 五槽状态 q2 → ...
    ↓
五槽轨迹记忆库（矩阵化语义坐标 + 连接强度 + 经历次数）

【一次决策与设想】
公开游戏状态
    ↓
可调注意力空间：决定这次真正注意到哪些状态项
    ↓
把局部对象与变化整理成当前五槽 q
    ↓
一次矩阵查询：唤醒若干相似的已记轨迹
    ↓
逐槽事实举证：排除高相似但不符合当前关系的候选
    ↓
抽象规则实例化程序：绑定当前对象、参数、目标集合与例外条件
    ↓
在 imaginedWorld 中试运行，不改 observedWorld
    ↓
连续设想控制器：继续粘连，或因选择、随机、未知、完成、注意力不足而停下
    ↓
与当前目标进行 match
    ↓
实际操作由正式游戏引擎结算

【反馈阶段】
玩家实际接收到的结果
    ↓
更新类型1因果知识、角色认知、概率账本、轨迹支持度
    ↓
复盘本次漏看了什么，调整特定动作的注意力预设
    ↓
必要时新增轨迹、错误轨迹、例外补丁或查阅规则出口
```

这条流程中，“思维动作”和“程序动作”必须分开：

- 思维动作是玩家记住和预想的状态变化轨迹；它可以模糊、缺参数、召回错误。
- 程序动作是引擎实际可执行的操作；必须有明确参数、合法性和确定的状态结算。

## 3. 五槽轨迹记忆：玩家究竟记住什么

玩家记住的不是固定字符串“放骰子后飞机移动”，而是一条由五个连续语义槽位组成的状态坐标：

```text
q = [
  affected_object,   # 受影响对象
  change_trend,      # 状态怎样变化
  cause_relation,    # 什么关系导致变化
  temporal_state,    # 准备发生 / 正在发生 / 已发生
  context            # 真实观察 / 假设 / 回忆 / 规则说明
]
```

每个槽位分别用本地 `GTE-multilingual-base` 编码为 768 维并归一化，五槽拼接后是 3840 维坐标。记忆保存为 `q → q_next` 的连接，而不是把整个句子写成一个硬规则。

已经验证：

- 可以从全新空实例开始记忆；不同实例完全隔离。
- 同一经历重复出现会增强 `observations/support`，不会无限复制同一行。
- 不同措辞能通过一次矩阵乘法召回相似轨迹。
- 保存后可以重新加载，并重建向量矩阵。
- 5000 条规模下可以运行。
- 跨领域模糊类比确实存在，但预测错误是允许且预期内的。

关键限制：embedding 对否定、角色关系和细微条件并不可靠。因此召回后必须用当前局部事实逐槽举证。例如“飞船经过箭头但最终停在别处”可能和“飞船停在箭头上”向量很像，但举证必须拒绝箭头横移。

## 4. 规则阅读：如何从教程生成轨迹

当前规则阅读器把一句规则拆成严格的五槽边，而不是一次生成整条答案链。

已经确认的处理方式：

- 参数关系：保留 `结束位置 = 开始位置 + 骰子点数` 之类的安全关系，不擅自填具体数字。
- 条件后果：`飞机下降` 与 `停在箭头后横移` 是两条轨迹；只有玩家后来注意到终点是箭头，第二条才会被唤醒。
- 随机结果：保存近期加权中心、常见范围和历史范围；经历会逐渐改变预期。
- 规则缺失：生成 `unresolved` 查询头，停下并查阅规则；不能用常识自动补完。
- 新后果：玩家第一次遇到陌生图标时停下，查到规则后再新增下一段轨迹。

当前 AI 草稿带原句引用，程序检查五槽完整性、来源和禁止补值。但还没有通过“另一个隔离 Agent 只读规则、自主稳定生成全部轨迹”的正式盲测。

## 5. 注意力：不是遍历整个世界

注意力模块的职责是：面对完整公开状态，决定玩家这一次实际清楚地看到什么。

UFS 当前被拆成 153 个稳定公开状态项：天空格、基地格、骰子、飞船、房间、资源和轨道等。153 不是人脑真有 153 个槽，而是当前程序版游戏的可审计状态原子。

一次动作的注意力由以下来源叠加：

- 默认注意：玩家平时会关注的状态。
- 动作预设：例如放骰子时强调目标列、同列飞船和预计经过的格子。
- 当前目标：例如保城时提高城市伤害相关状态。
- 显眼干涉：明显异常有机会打断原有注意链。
- AI 复盘调整：失败后给某一步增加或降低注意位置。
- 有限预算：连续激活度经过容量限制后，只有一部分状态进入后续设想。

当前模块已经支持按动作/阶段/目标增加、降低、沿关系扩展、撤销和审计。注意力等级越高，进入后续的状态项越多。

尚未解决或未标定：

- 激活常数和预算不是人体实验参数。
- 当前是确定性排序截取，没有模拟随机漏看和疲劳。
- “AI如何根据失败自动决定应该补看哪里”只有接口，还没接成正式复盘循环。
- 153 项注意空间尚未与连续设想中的注意力消耗共享同一个总预算。

## 6. 抽象轨迹如何落到当前对象：参数化小程序

五槽 Q 只表达抽象关系。例如记忆可以告诉玩家“同列飞船会下降”，但当前局面里必须进一步绑定：是哪一个骰子、哪一列、哪几架飞船、下降几格、终点是什么。

当前采用的方案不是每次让 LLM 从头自由发挥，也不是写死每种情况，而是一段**可增量修订的受限声明式小程序**：

- 触发当前适用的抽象轨迹；
- 从公开状态绑定对象和变量；
- 按关系筛选目标；
- 计算安全的局部参数；
- 输出对 imaginedWorld 的预测效果；
- 记录这次试运行实际读取了哪些状态路径。

规则出现例外时，AI不重写整个程序，而是依据新规则和失败反例追加来源受限补丁。当前隔离实验依次吸收防空、冻结、重型、加速和整组相对选择；旧例无回归，最终组合 400/400。

这证明的是：**“抽象 Q → 可修订临时程序 → 当前实例”这条架构可以闭合。**

随后补做的 `blind_rule_program_micro_v0` 让隔离子 Agent 只接收公开合同、逐轮规则和失败反馈，基础、冻结例外、整组最小值并列保留最终累计 10/10，旧例无退化，隐藏字段和越权状态读取为0。它证明微型合同下可以盲生成并增量修订；仍不能冒充 OS 级隔离，也没有证明任意自然语言规则都能稳定编译。

## 7. 连续设想与停止

原先的链条会无限继续。现在每一步后都有两道门：

1. 结构门：后果是自动、需要选择、随机、未知、明确完成中的哪一种。
2. 认知门：玩家是否还有足够注意力处理下一条轨迹的内部注意点。

规则：

- `automatic`：可以继续粘连。
- `choice`：需要玩家作新决策，当前设想暂停。
- `random`：只能保留范围或分布，不能编造唯一结果。
- `unknown`：知识不足，停下查规则或获取新经验。
- `complete`：这一分支明确完成。
- `attention_stop`：预算耗尽，尚未想到的后果不能进入结果。

熟悉轨迹消耗更少注意力，但不降为零。临时目标目前只用于调整并行后果的查看顺序，不是最终规划模型。

### 7.1 问题1—6最小组装已经跑通

新建的 `imagination_pipeline_v0` 把此前分散验证的前六个问题接成了同一条可执行链：

```text
候选放骰动作
→ 动作模式展开入口、空间注意和预期出口
→ 默认注意、动作影响、目标、显眼干涉与有限预算合成注意结果
→ 同一注意区域中的多个对象分别形成严格五槽 Q
→ 矩阵激活提出轨迹候选，关系门排除高相似但当前事实不符的候选
→ 盲测过的参数化程序绑定当前对象和数值
→ 只在 imaginedWorld 中提交预想效果，observedWorld 保持不变
→ 连续设想控制器因完成、随机、选择、未知或注意力耗尽而停止
```

完整微型案例已经跑通“放骰 → 同列非冻结飞船下降 → 停在箭头后横移 → 城市受伤 → 明确完成”。冻结对象被排除，“只是经过箭头”的高激活干扰轨迹被关系门拒绝；未进入注意的公开事实不能被 grounding 偷读。

## 8. 已有正式玩家认知系统，不要覆盖

在 MindToy 之前，项目已经完成了一套可执行玩家认知主线。新 Agent 不得因为最近在研究轨迹，就把此前成果替换掉。

### 8.1 三块认知并行

1. 角色认知：详细可见战斗表现进入角色矩阵、特点复核和相对标尺。
2. 非角色事件：主体 + 环境 + 行为 → 结果的类型1因果知识，以及概率机会账本。
3. 换人预期：读取更新后的角色认知、阵容、站位、装备和本场结果。

它们相互隔离，只允许单向组合。废弃的 `RECEIVED_INFORMATION_ROUTER_V2` 不能重新接入；正式边界见：

- `projects/western_fantasy_continent/design/ISOLATED_PLAYER_COGNITION_COMPOSITION_V1.md`
- `projects/western_fantasy_continent/PLAYER_MODEL_RUNTIME.md`

### 8.2 角色三套独立标尺

角色没有一个永久综合分，而是独立维护：

- 输出 `output`
- 保护 `protection`
- 团队增益 `buff`

每套使用同步相对矩阵和“认知人口前 30% 最低者为零点”的标尺。新增强角色会抬高标尺；加入很多弱角色也会让原本较弱者相对显得更强。某次换人时，Agent根据当前问题给三条标尺临时配比，程序计算本次预期；不能把临时配比保存成永久总强度。

入口：`projects/western_fantasy_continent/design/INDEPENDENT_CHARACTER_CAPABILITY_RULERS_V1.md`

### 8.3 反馈模块的边界

- `R`：实际结果本身好不好。
- `A`：实际结果相对预期好多少或差多少。
- `C`：主动调整后的自我确认；成功有明显自利归因，明显失败基本不应产生确认。
- `EVerify`：战前因果假设链是否被玩家可见证据支持、反驳或仍无法判断；它负责让玩家真正学到因果知识。
- `EDecision`：这次完成了多少有效思考步骤。
- `QDecision`：这些思考是在推进问题还是原地乱试。
- `Agency`：玩家是否看得到可信、可执行且付得起的解决路径；它是持续状态，不是每回合奖励。

`EDecision/QDecision/Agency` 的统一方案目前是设计完成、尚未正式接入。不要误称已实现。入口：

## 9. 高维空间与 MindToy 得到了什么

本地 GTE 的 768 维语义空间中确实存在治疗、护盾、控制、输出、位移等连续方向。单轴平均 AUC 约 0.846，但把多个未经校准的轴当概率连续相乘会放大误差，因此“有方向”成立，“每条轴都是准确属性概率”不成立。

高维符文目前最适合做两件事：

1. 根据一个模糊需求，快速激活可能相关的对象、概念或经验。
2. 根据当前局部变化，快速唤醒可能的下一段轨迹。

它不适合单独承担精确规则、否定关系、数值结算或最终真值判断。

此前 UFS 曾实现一个矩阵/beam 程序规划器，冻结评测胜率 58%。这证明程序版 UFS 地图和引擎可运行，也证明路线组合优于一步贪心；但它主要是算法搜索器，不是我们当前要的拟真人类玩家。用户已经明确否定把“写一个强策略算法”当成玩家模型主线。这个结果只作为引擎和规划对照，不能作为当前方案已经成功的证据。

## 10. 当前真正卡点

微型自主盲测和问题1—6最小接线已经通过。当前卡点不再是“这些层能不能接”，而是把同一条链逐端口升级为真实模块，同时保持认知边界：

1. 在 `fb2` 接入真实 GTE 五槽编码器与真实已编译规则轨迹，替换测试编码器和 fixture。
2. 接入已有153项 UFS 公开状态与可调注意力输出，替换微型注意实现。
3. 每替换一层都保持：未注意读取为0、observedWorld 不变、随机/选择/未知/完成/注意力停止边界不退化。
4. 再扩展放置以外的下降、挥砍和一般移动动作模式。
5. 全部通过后，把设想结果以影子模式挂到正式玩家决策旁边，先不改变实际行为。
6. 最后再进入问题7主动候选与问题8反馈学习；规划必须建立在上述设想单元上，不能另写全知搜索器。
