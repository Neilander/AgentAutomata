# 边陲村魔物战争：程序版

这是无前端的 v3 规则核心与正式模拟玩家接口。当前只保留金币、粮食、人口与行动力：刷装推动铁匠铺金币收入，农田产粮，金币用于市场与扩大征召，粮食在战前按所选编队投入。民兵一战需1粮、战士一战需3粮，部分训练/突袭另有固定军需；投入0粮时全队以20%生命、攻击和护甲出战，投入比例线性提升，满额达到100%。实际投入量进入战斗计划、确定性种子与权威结算；胜利扣粮，失败返还。敌据点被占领后会解锁原地建设位。英雄和每支已训练战士都拥有8个装备部位，可逐单位调整，也可一键按显示评分分配给英雄与战士；战士装备会真实进入突袭和最终战数值。未训练民兵也进入公开人物列表并提供真实技能与基础战斗数值，但8个装备槽明确锁定，且不会进入配装目标或生成装备动作。每个公开人物还提供由当前生命、主攻击、护甲、攻速与技能急速计算的整数战斗力，供编队界面横向比较；它不是装备评分。人物公开数据从正式技能与战斗规则生成数值详情，包括目标数、基础值、攻击倍率、伤害类型、持续时间、冷却和被动比例。战斗计划可接收经过容量校验的编队成员、站位与军粮投入；编队容量只要不超过本场上限即可向下兼容，并在结算时用同一部署重建权威结果。未提供编队时仍兼容原有自动集结流程。最终战入口只汇总玩家已经知道的敌我规模与装备覆盖情况，不公开隐藏胜率或解法。

新档初始背包临时提供一套稀有度展示：普通旧民兵剑，以及稀有头盔、史诗胸甲、传说戒指、神话护符、永恒手甲、黑金腿甲、炼狱战靴各一件。七件展示装备由正式生成规则创建，分别保留2、4、7、12、15、18、22条词条，因此会真实参与配装与战斗，而不是纯视觉占位。开场剧情阶段同样提供穿戴、卸下和一键配装动作，不需要先推进到经营阶段。黑金与炼狱目前仍只用于展示和规则预留；永恒已经可以通过远古遗迹最终挑战获得，但三者均未进入五档边林讨伐的普通掉落表。

第3日进入经营阶段后，地图会出现独立高危节点“远古遗迹”。关卡包含4单位封锁回廊战和8单位守秘者大厅战，两场敌人的单体强度都高于边林难度5；失败不会消耗行动力、粮食或推进剧情。只有打赢入口后，玩家才会发现被困数日的探险家小姐薇奥拉与魔剑导师艾琳。投入12粮可以让魔力枯竭的艾琳以虚弱固定单位参加下一战；保留补给并听薇奥拉复盘机关，则会绕开两组守卫但失去艾琳助战。最终胜利会救出并招募两人，且必定获得一件永恒“远古遗珍”。

玩家观察面现在单独公开 `town` 当前城镇对象，而不是把人口视为天然全图共享资源。灰谷村包含城镇名、当前人口/人口上限、今日行动/每日上限和繁荣数据。繁荣等级沿用原有行动门槛：0、40、70、100人口分别对应 Lv.1—4 与每日3—6行动；前期10—100人口每10人新增1个民兵单位。人口奖励和繁荣门槛以独立里程碑表公开，方便后续不同城镇改用不同规则。

边林讨伐现在有五档独立难度，并共享加权讨伐积分：难度N获胜一次增加N积分，累计5、20、90、200积分时依次解锁难度2—5。因此一直刷难度1仍能解锁全部难度，但挑战高难度会明显更快；解锁不会自动切换。每档都有独立且公开的掉落件数与稀有度表，高难度同时提高敌群规模、装备等级、稀有度和每轮掉落数。失败会保留战斗记录但不增加积分，也不消耗行动力或粮食，可以立即重试或切回低难度。

## 本地验证

```powershell
node verify-border-village.js
node verify-border-village-input-boundary.js
node verify-border-village-sealed-surface.js
node verify-border-village-winning-route.js
node verify-border-village-formal-playtest.js playtest\v3-open-novice-r2-session.json playtest\v3-open-novice-r2-visible-trace.json
```

验证覆盖核心规则、玩家输入封口、全日密封面，以及一条包含刷装产钱、即时建设、征召、训练、占领三个据点、原地建设和最终真实战斗的可胜路线。正式试玩审计还会逐轮核对：所选动作当时确实公开可用、每场战斗有时间线、每次结果都进入知识库、归因只引用公开证据、未来事件没有提前泄露。所有战斗必须先由共享战斗模拟器生成完整 `signals` 时间线，核心才接受结算。

## 正式模拟玩家

```powershell
node border-village-formal-player-cli.js init playtest\session.json <seed> 100 open_novice
node border-village-formal-player-cli.js request playtest\session.json playtest\request.json
```

之后交替提交一次 `decision` 和一次 `attribution`。模拟玩家只能看到 `request` 输出，不能读取会话存档、核心源码或设计文档。
