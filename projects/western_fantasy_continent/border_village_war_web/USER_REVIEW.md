# 玩家路径审查

## User frame

User: 第一次进入灰谷村第3日的玩家。  
Intent: 在有限行动中决定建设、招募、刷装或突袭，并为第7日备战。  
Prior knowledge: 已知敌军规模、粮食发挥区间、人口与民兵关系。  
Success state: 能完成一次经营、一次配装、一次突袭，并理解战后局势变化。

## Task path

### 1. 找到今天的目标

- User expects: 先看到还有几日、多少行动、敌我规模。
- UI must show: 顶部七日轨、外置行动力、左上战争牌。
- Action available: 点击任一带数字的地图节点。
- Feedback after action: 节点旁浮层只显示该地点合法行动。
- Recovery if wrong: 点击空白、关闭按钮或 Escape 退出浮层。

### 2. 建设或升级

- User expects: 看成本、完工时间、产量范围。
- UI must show: 空地三种建筑；已建建筑只显示自己的升级/经营动作。
- Action available: 就地按钮；铁匠打造压缩为部位选择。
- Feedback after action: 结果弹窗和节点状态同时更新。
- Recovery if wrong: 行动执行前可关闭浮层；执行后属于有意的不可撤销经营选择。

### 3. 手动配装

- User expects: 先选角色，再比较物品，知道替换/出售限制。
- UI must show: 全角色列表、定位、偏好词条、八部位、背包详情相邻。
- Action available: 装备、卸下、出售；不提供一键配装。
- Feedback after action: 对应部位即时变化，toast 近场反馈。
- Recovery if wrong: 可卸下或用另一件替换；跨角色转交会明确提示先由原使用者卸下。

### 4. 突袭与决战

- User expects: 知道投入多少粮、双方是谁、能否取消。
- UI must show: 三档补给、预计发挥、双方名单；不显示胜率。
- Action available: 取消或进入战斗。
- Feedback after action: 完整战斗后显示存活、倒下者、输出与局势变化。
- Recovery if wrong: 战前可以取消；开战后无跳过，失败是有意压力。

## Findings and minimal fixes

- Wrong priority：平铺所有经营动作会在第3日过载。已改为地图节点局部展开；市场出售放进当前物品详情；八个打造按钮压成下拉框。
- No recovery：装备原本只能替换，不能卸下。已在核心与前端补当前角色逐件卸装。
- Ambiguous result：战斗只显示存活人数时，不知道谁倒下。已在战斗结果中列出倒下者。
- Hidden action：决战全员集结与最后晨收原本直到第7日才知道。已常驻战争牌的折叠规则，并在程序观察中公开。
- State mismatch：隐藏底栏后战斗仍会留下空白行。已让战斗状态回收整块屏幕给正式战场。
- Disabled reason：已装备物品或集市购买力不足时，详情区说明为何不能出售；跨角色转交说明恢复步骤。

## Remaining risk

- 按用户要求没有启动服务器或浏览器，因此本轮只完成静态与程序验证，没有真实浏览器像素级检查。
- 页面面向桌面快速试玩，最小宽度1080px；没有为手机布局做额外压缩。
- 背包上限200件，网格可滚动但未做虚拟列表；简单DOM卡片在200件规模应可用，仍需真人浏览器体验确认。

## Do not change

- 不增加一键配装。
- 不显示胜率、内部倍率、掉率表或推荐答案。
- 不提供战斗跳过或直接结算。
- 不把地图重新拆成“地点列表/描述/行动”三个并列栏。

## 2026-08-05 独立军备浮窗审查

### User frame

User: 已经拥有多名英雄、战士和大量装备的玩家。
Intent: 快速找到一个单位当前穿戴的装备，与背包物品比较并完成替换。
Prior knowledge: 知道装备有8个部位，但不记得物品由谁穿戴。
Success state: 能从地图进入军备、切换角色、装备或卸下物品、查看技能和当前数值，并安全关闭返回地图。

### Task path

1. 从地图底部“队伍与装备”或左侧可配装单位方块打开军备；周围变暗，地图不再抢注意力。
2. 顶部确认当前位于“人物”页；在左侧人物页眉用上一页/下一页切换对象，队内在前、候补在后。
3. 在左侧确认角色名、定位、技能与8槽；点击已穿装备会在右侧选中同一物品。
4. 在右侧按“当前角色已穿、未穿戴、他人已穿”的顺序浏览；点击物品后在同区看到属性、所有者和可用动作。
5. 装备或卸下后，角色槽位、背包所有权标签和公开数值同步刷新；toast提供近场完成反馈。
6. 悬停技能操作行“一键全队”右侧的“数值”按钮查看覆盖面板；移开恢复立绘和技能。点击关闭或按Escape回到地图。

### Findings and minimal fixes

- State mismatch：切换角色后若仍保留上一人的选中物品，详情可能指向背包末尾的他人装备。已在切换角色时重置物品选择，默认选中按新角色排序后的第一件。
- Wrong priority：两排角色头像轴长期占用高度，但换装时玩家只操作一个角色。已改成顶部“编队/人物”分页和人物上一页/下一页，释放高度给立绘、八槽、技能与背包。
- Wrong priority：用放大的姓名汉字冒充立绘会先于角色和装备信息抢走注意力。已经移除汉字，只保留以后替换正式立绘的低对比占位。
- Information overload：八个装备槽同时写完整名称、评分和属性会把人物区切成八块文本板。槽位改为56px小方格，只常显部位图标、部位名和稀有度边框；悬停或键盘聚焦时再显示完整装备详情。
- Ambiguous information：原技能卡只有“稳定伤害”“小幅增伤”等描述，无法据此比较角色。常态卡只保留技能名和冷却，悬停或键盘聚焦后展示正式结算中的目标数、基础值、攻击倍率、伤害类型、持续时间与被动比例。
- Wrong hierarchy：技能槽位文字占据左上主位置、技能名落到下一行，造成左上像空位、名称像脚注。已固定为左上技能名、下一行技能类型、右上冷却。
- Excessive framing：技能区外框把四张技能卡又包成一张大卡，且立绘占用过高。已移除技能区外框，立绘区让出约5%高度；每张技能卡增高并恢复一行效果概述，精确公式仍按需展开。
- No recovery：他人穿戴物品不能直接转交。详情会写出当前所有者与“先由该单位卸下”，人物页的上一页/下一页提供恢复路径。
- Ambiguous result：换装后不能只弹文字。当前槽位、背包排序、所有权标签与战斗数值会一起由真实状态重绘。
- Wrong placement：完整数值不常驻挤压技能与装备；入口从人物区右下角移到技能操作行，紧跟“一键全队”，悬停后覆盖左区。

### Do not change

- 不把军备界面再拆成更多并列栏。
- 不在物品格中塞入完整词条；完整信息只显示于右侧同区详情。
- 不显示胜率、敌方隐藏倍率或“推荐装备”。
- 不允许绕过真实装备所有权直接从其他角色身上抢装。

## 2026-08-05 编队页用户路径审查

### User frame

User: 已拥有多名英雄与军队单位、准备整理出战方案的玩家。
Intent: 选择一支编队，把当前城池的成员拖入出战区，并判断队伍是否合法。
Prior knowledge: 知道跨城不能共同出战，但不需要预先知道每档编队容量。
Success state: 能选择编队、拖入/拖出成员、看懂超员或混城原因、筛选当前城池，并从错误状态恢复。

### Task path

1. 打开军备并切换“编队”；左侧首先看到2/4/8/20单位可用编队和40/100/200单位锁定项。
2. 点击一支编队；左侧选中态与右侧名称、单位数、所在城池同步变化。
3. 从右下候选区把成员拖到右上出战区；卡片立即移动，单位数与合法性同步刷新。一名英雄、一支10人民兵队或一支10人战士队都只增加1单位。
4. 若超员或未来出现混城成员，左侧对应编队行、右侧整个编辑区和原因文字同时变红。
5. 把成员拖回下方或直接点击卡片恢复；红色错误态立即消失。
6. 开启“筛选·灰谷村”；按钮显示激活态，候选标题显示剩余数量，空结果提示可以关闭筛选查看其他城池。

### Findings and minimal fixes

- Ambiguous result：最初只有编队标题变红，不符合“整队不合法”的反馈。已让整个右侧编辑区和出战区一起进入红色错误态。
- No recovery：拖错成员必须能立刻撤回。上下区域都接受拖放，点击成员卡也可在出战/候选之间移动。
- Hidden state：城池筛选可能让玩家误以为成员消失。已显示筛选后的候选数量，空结果明确提示关闭筛选。
- Terminology mismatch：初版把10人民兵队和10人战士队按10个编队名额计算，混淆了“单位内部人数”和“编队单位数”。现统一为每张成员卡占1单位，角色行仍保留“10人单位”用于说明其内部规模。
- State mismatch：第一章当前所有成员都位于灰谷村，正常流程不会自然制造混城案例；校验与红色状态已经实现，仍需第二章多城成员数据做真实触发验证。

### Do not change

- 不在超员或混城时自动踢人；保留玩家制造错误并自行修复的空间。
- 不隐藏40/100/200单位规格；锁定目标必须持续可见。
- 不加入“推荐阵容”或自动纠错，避免替玩家完成编队决策。

## 2026-08-05 编队站位用户路径审查

### User frame

User: 已经选好出战单位、希望安排前后排的玩家。
Intent: 看见当前阵型，把单位移到预期槽位，并回到编队管理。
Prior knowledge: 知道头像可以拖动，但不预先知道每种编队的阵地尺寸。
Success state: 能进入站位、辨认敌军方向、移动或交换单位、确认结果并退出；不用拖拽也能完成同一任务。

### Task path

1. 在“出战成员”标题右侧点击“调整站位”；右侧成员与候选列表变为阵地，左侧当前编队仍保持选中。
2. 通过顶部“敌军方向”和右侧“前线—后方”标尺判断排位；全部出战单位已经按原顺序进入槽位，剩余位置明确显示为空。
3. 把一个头像拖到空槽以移动；拖到另一头像以交换。头像、槽号与选中态立即重绘，近场提示说明发生了移动还是交换。
4. 无法拖动设备可先点头像，再点空槽或另一头像；再次点击已选头像可取消。
5. 点击“完成站位”回到出战/候选列表。若先前超出单位上限，“调整站位”保留为红色禁用按钮，并通过悬停说明必须先移出多余单位。

### Findings and minimal fixes

- State mismatch：站位编辑不能继续显示候选列表，否则“选人”和“排位”会争夺主区域。进入站位后右侧只保留编队标题、阵地与完成按钮。
- Hidden orientation：仅有槽位方格无法判断哪边是前排。阵地顶部常驻敌军方向，右侧标出前线到后方。
- No recovery：只支持原生拖拽会阻断触屏或精确拖动困难的玩家。增加“先选头像、再点目标槽”的等价路径，并允许再次点击取消。
- Ambiguous result：交换后不能只写入存档。目标头像立即互换，并用短提示区分移动与交换。
- Disabled-state reason：超编时阵地槽位不足，但入口不能消失。按钮改为红色禁用态，悬停直接说明先移出多余单位。

### Do not change

- 不把候选单位塞进站位阵地；编队成员选择和站位调整保持两个阶段。
- 不自动判断“最佳前排”或透露推荐阵型，初始只按玩家已有顺序放置。
- 不把10人民兵拆成10个槽位；一支民兵队始终只占一个站位槽。

## 2026-08-05 民兵人物页用户路径审查

### User frame

User: 想比较民兵、战士和英雄技能的玩家。
Intent: 从地图或人物翻页进入一支民兵，查看技能与数值，同时弄清它为什么不能穿装备。
Prior knowledge: 知道战士可以配装，但不确定民兵是否也可以。
Success state: 能找到每支民兵、查看4个真实技能及数值，并明确辨认所有装备动作都未开放。

### Task path

1. 点击地图左侧任一民兵头像，或在人物页翻到“民兵”；页眉显示具体民兵队名与民兵身份。
2. 左右八个装备槽仍在原位置，但全部带锁、降饱和并显示训练后才开放的原因；中央不再显示“装备评分0”，而是“民兵不能穿戴装备”。
3. 下方4个技能保持正常可读，悬停仍显示正式数值；“数值”覆盖层说明这些是民兵基础战斗数值。
4. “一键当前”变为红色“装备锁定”；右侧背包保留物品查看，但标题明确写明不能装备，物品详情不出现装备或卸下按钮。
5. 翻到英雄或战士后，原有配装操作恢复。

### Findings and minimal fixes

- Missing object：地图上已有民兵头像，但原人物列表只来自可配装单位，导致玩家无法查看民兵技能。新增独立的可查看人物列表，保留原可配装列表作为装备权限边界。
- Ambiguous permission：单纯禁用“一键当前”仍可能让玩家以为缺少资源。八槽、中央状态、当前按钮和背包标题同时显示装备锁定。
- State mismatch：民兵数值不能写成“已经包含当前穿戴装备”。覆盖层改为明确的基础战斗数值说明。
- Permission leak：为展示民兵而直接把它加入 `equipmentTargets` 会错误生成装备动作。民兵只进入 `characterTargets`，不会成为装备所有者或配装目标。

### Do not change

- 不为民兵生成空的假技能；始终读取正式民兵战斗模板。
- 不隐藏八个装备槽；锁定状态本身负责解释训练成长目标。
- 不允许从背包给民兵装备物品，也不让“一键全队”把装备分配给民兵。

## 2026-08-05 编队单位信息审查

### User frame

User: 正在比较候选单位并决定谁进入编队的玩家。
Intent: 先识别人和职业，再快速比较战斗力与是否同城。
Prior knowledge: 知道编队按单位计算，并会通过职业图标识别战场定位。
Success state: 每张成员卡和站位槽都能直接读到职业图标、姓名、城镇和完整战斗力，且没有“我/民/战”身份首字冒充职业。

### Findings and minimal fixes

- Wrong hierarchy：把战斗力铺满整张卡会丢失人物识别，也无法形成稳定的数值区域。改成长方形人物牌，上半区职业图标＋姓名＋城镇，下半区独立显示战斗力。
- Missing icon：上一版用职业文字或“我/民/战”代替职业识别。现复用战斗界面的正式职业图标表，并由核心公开 `roleKey`，不靠姓名猜职业。
- Scale risk：战斗力未来可能达到百万级。底栏保留横向宽度并完整使用千位分隔，不把数值缩写为含义模糊的“万/百万”。
- Ambiguous metric：装备评分不能代表生命、护甲与职业基础差异。新增由当前真实战斗属性生成的公开战斗力，换装后会重新计算。
- State mismatch：普通成员卡改了而站位槽仍显示名字，会形成两套识别逻辑。两种状态统一显示战斗力、职业、城镇。
- Hidden constraint：城镇不能只放在悬停标题里，因为跨城会让编队不合法。城镇在每张卡和已占用槽位上常显。
- Future asset gap：原来的人物牌没有给角色立绘留稳定位置。现固定为上方空白立绘区与下方信息区；未来替换正式立绘时不用移动姓名或战斗力。
- Excessive framing：职业图标自身已经足以承担识别，再套小方框会挤压姓名并制造无意义边界。成员卡与站位槽都改为无边框、无底板图标。
- Crowded metric：把战斗力作为独立窄底栏并使用较大数字，会让长数值显得被左右挤压。现把姓名移到同一信息区的上一行并靠左，战斗力标签和数值整体缩小。
- Asset confusion：职业图标放在立绘区中央仍会被理解成临时立绘。现让立绘区保持完全空白，把缩小图标居中压在上下区域分界线上，明确它是职业标识和视觉衔接，而不是人物图像。

### Do not change

- 保留姓名，但不恢复“我/民/战”身份首字；左侧只使用正式职业图标。
- 不把装备评分标成战斗力。
- 不隐藏城镇，即使第一章当前所有单位都在灰谷村。

## 2026-08-07 战前编队选择审查

### User frame

User: 已经建立多支不同规模编队，准备进入一场战斗的玩家。
Intent: 先知道本场需要什么队伍，再从自己的配队中选择一支，并确认实际参战成员。
Prior knowledge: 知道编队存在容量与合法性，但不需要记住哪类战斗对应几人。
Success state: 能在两秒内看到战斗类型和人数上限；较小编队可以参加更大战斗；容量兼容的合法队伍位于最前；点击其他队伍后详情与出战状态同步变化；真正上场的是所选队伍。

### Main path

1. 战前窗口顶部显示战斗类型与参战上限；训练额外说明固定参战的受训民兵。2人编队可以进入4/8/20单位战斗，但8人编队不能进入4单位战斗。
2. 左侧全部编队按“容量兼容且合法、容量兼容但不合法、超过人数上限”分组排序，同组内最接近人数上限的编队在前，不删除错误或超限队伍。
3. 点击任一编队，右侧更新容量、驻地、总战斗力、站位顺序、成员和敌方情报。
4. 容量兼容、合法且非空的编队都能进入军粮准备；粮食不足不会隐藏或阻断入口。
5. 按“开战”后窗口左滑到军粮页。点击大锅投入1粮，长按连续投入；右下角同步显示`x/X`和20%—100%发挥，允许清空或返回选队。
6. 进入战斗后，核心按照所选成员、站位和粮食投入生成真实战斗计划，并用同一部署重新验证结算。

### Do not change

- 不显示胜率、推荐队伍或敌方隐藏倍率。
- 不把不匹配或不合法编队从列表中隐藏。
- 不允许预览选择与真实出战阵容脱节。

## 2026-08-08 战前军粮注入审查

### User frame

User: 已选定一支合法编队、准备开战的玩家。
Intent: 直观看懂这支队伍一战需要多少粮，并决定本场实际投入多少。
Prior knowledge: 知道粮食是战争资源，但不需要提前理解倍率公式。
Success state: 能在编队页看到一战粮耗；按开战后自然进入独立准备步骤；会通过点击或长按大锅投入；能从`x/X`与百分比判断是否继续加粮；实际战斗强度与所见百分比一致。

### Main path

1. 编队列表与当前编队详情常显一战粮耗，避免到了最后一步才突然出现成本。
2. 选队页不同时承载粮食微调；按“开战”后整个内容左滑，建立“先选谁、再供给多少”的顺序。
3. 军粮大锅每次点击加1，长按以固定节奏连续增加；投满或粮仓耗尽后自动停止。
4. 右下角持续显示`已投入/满额`与发挥百分比。0粮为20%，满额100%；文字明确影响生命、攻击和护甲。
5. 玩家可清空投入，也可返回选队。粮仓不足时仍能以较低发挥出发，按钮不会消失。

### Do not change

- 不把粮食百分比包装成胜率，也不推荐“正确”投入量。
- 不在选队页同时放置加减粮食控件，避免重新造成信息过载。
- 不让前端独自计算一个装饰性百分比；必须由核心战斗计划返回并参与权威结算。
- 不在失败时扣除粮食；胜利后才按本场实际投入扣除。

## 2026-08-08 当前城镇与繁荣轨迹审查

### User frame

User: 正在经营灰谷村、未来会同时控制多个城镇的玩家。
Intent: 不离开地图就看懂当前城镇的人口、容量、行动与繁荣；需要规划时再查看人口未来会带来什么。
Prior knowledge: 知道人口能形成部队，但不需要记住40/70/100行动门槛。
Success state: 两秒内确认当前查看的是哪个城镇；不会把人口误解为全图共享；能指出当前人口/上限、行动力和繁荣等级；点击后能拖到未来节点，说出下一次单位奖励或繁荣奖励，以及是否被人口上限阻挡。

### Main path

1. 右上角城镇框同时显示“灰谷村、人口30/50、行动3/3、繁荣Lv.1”；人口必须同时出现当前值与上限。
2. 点击繁荣等级打开独立界面，当前城镇和三项核心状态在顶部再次确认。
3. 横向人口轨迹自动把当前里程碑放在靠前位置；玩家按住拖动、滚轮或方向键查看未来。
4. 10人口间隔节点显示“新增1个民兵单位”；40/70/100人口节点同时显示繁荣升级、每日行动+1和当次单位奖励。
5. 超过当前人口上限的节点不隐藏，而以虚线说明需要先提高容量。

### Do not change

- 不把人口继续放回金币、粮食的全局资源条。
- 不假设所有未来城镇都每10人口给单位；奖励必须来自城镇自己的里程碑数据。
- 不用横向表格塞入建筑、粮食和战斗信息；这个界面只解释人口、繁荣和直接收益。
- 不把每日行动上限误写成当前剩余行动；两者始终以`当前/上限`同时显示。
