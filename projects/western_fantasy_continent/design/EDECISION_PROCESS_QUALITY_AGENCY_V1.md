# EDecision、决策质量与掌控感统一方案 V1

- 日期：2026-07-20
- 状态：设计完成，尚未接入正式运行时
- 目标：保留旧版 `P×Q` 对“有效思考/卡住乱试”的区分，同时不重复计算现有的 R、A、C 和 EVerify。

## 一句话结论

不要把 EDecision 本身改成“正确决策分”或“掌控感分”。

应该拆成三层：

1. **EDecision**：玩家这次实际完成了多少有效思考步骤。
2. **QDecision**：这些思考是在推进问题，还是在原地乱试。
3. **Agency（掌控感）**：玩家是否看得到一条自己能执行、并且相信会影响问题的路。

即时决策过程反馈为：

```text
DecisionFeedback = 0.04 × EDecision × QDecision
```

其中 `EDecision` 为 `0..4`，`QDecision` 为 `-1..1`。  
掌控感单独保存为持续状态，不直接塞进 EDecision，也不把每次高掌控感都重复奖励。

## 一、各模块只回答一个问题

| 模块 | 回答的问题 | 能否读取战斗最终胜负 |
|---|---|---|
| EDecision | 玩家完成了多少步真实思考？ | 否 |
| QDecision | 这次思考是否有效、有区分度、不是死循环？ | 否 |
| Agency | 玩家现在是否看得到可信且可执行的解法？ | 规划时不读取；战后只通过新知识更新 |
| R | 实际结果本身好不好？ | 是 |
| A | 实际结果比预期好还是差？ | 是 |
| C | 玩家主动调整后，结果是否带来自我确认？ | 是 |
| EVerify | 战前提出的因果链是否得到玩家可见证据支持？ | 不读取胜负评价，只读取因果证据 |

这样可以避免“赢了一次”同时被 EDecision、R、A、C、EVerify重复当成同一件事奖励。

## 二、EDecision：只计算有效思考量

沿用旧版四步结构，但由程序验证，Agent不能自己填写分数。

### 四个顺序步骤

1. **发现问题**
   - 问题来自玩家实际接收到的信息；
   - 与当前目标有关；
   - 例如“敌方前排一直不死”，而不是设计者隐藏数值。

2. **提出有证据的原因**
   - 引用当前已检索到的知识、角色认知或本场可见证据；
   - 原因可以是错的，但必须是玩家当前有理由相信的；
   - 与已有强反证冲突时，必须明确承认冲突或说明为什么要复验。

3. **比较可执行行为**
   - 行为必须当前可用；
   - 至少说明它会改变什么，例如单点输出、保护、增益、装备倍率或站位；
   - 有两个选项时，二者必须产生不同的预期，而不是换一种说法描述同一动作。

4. **写出可验证假设**
   - 使用公开角色、技能和状态标识；
   - 写出完整因果链；
   - 有玩家能够看到的目标条件与验证期限。

### 计分

按顺序计算最长有效前缀：

```text
问题无效                              -> 0
只有问题                              -> 1
问题 + 有根据的原因                   -> 2
问题 + 原因 + 可执行行为比较          -> 3
问题 + 原因 + 比较 + 可验证因果假设   -> 4
```

后一步不能掩盖前一步无效。写出漂亮的假设，但原因没有任何玩家知识依据，仍然只能停在第1步。

简单而明显的选择只获得少量过程反馈，不因为“不够复杂”而受罚。复杂度不是价值，真实思考才是。

## 三、QDecision：判断是在推进还是乱试

EDecision=4只说明玩家确实完成了一套思考，不说明这套思考质量高。  
QDecision使用当前正式系统已经拥有的结构化数据计算，Agent不能自行打分。

### 五个正向分量

全部为 `0..1`：

1. **evidenceFit：证据贴合度**
   - 引用的知识真实存在；
   - 与问题、原因和行为方向一致；
   - 若知识互相冲突，决策有明确处理冲突。

2. **actionLeverage：行为杠杆**
   - 玩家选择确实会改变当前问题相关的量；
   - 例如缺保护时换坦克、缺单点时换游侠、换装提升对应角色的有效强度；
   - 不要求一定成功，只要求它有理由影响问题。

3. **testability：可验证度**
   - 假设目标会出现在玩家当前能接收到的信息档位中；
   - 验证期限明确；
   - 不能用玩家看不见的隐藏数值当目标。

4. **discrimination：区分度**
   - 结果能够区分至少两种解释或两种方案；
   - “不管发生什么都算我对”区分度为0；
   - 专门复验一条弱证据可以有很高区分度。

5. **revision：修正程度**
   - 相比上一次失败，是否改变了角色、装备、站位、环境、行为或因果链中的关键一环；
   - 第一次尝试使用中性值 `0.5`；
   - 改了无关内容不能算有效修正。

### 两个负向分量

全部为 `0..1`：

1. **deadRepetition：无意义重复**
   - 同一个问题；
   - 同一环境、队伍、装备和站位；
   - 同一行为与同一因果链；
   - 已有高置信度反证；
   - 没有新的证据、复验理由或关键修改。

   五项同时成立时接近1。只要出现真正相关的变化就应下降。

2. **incomprehension：无法形成解释**
   - 找不到任何有依据的原因；
   - 引用内容互相矛盾却不处理；
   - 行为和原因没有连接；
   - 假设不可观察、不可证伪或只是“再试试看”；
   - 玩家面对很多信号，但没有形成可用结构。

### 暂定公式

```text
positive =
    0.25 × evidenceFit
  + 0.25 × actionLeverage
  + 0.20 × testability
  + 0.15 × discrimination
  + 0.15 × revision

QDecision = clamp(
    positive
  - 0.75 × deadRepetition
  - 0.45 × incomprehension,
  -1,
  1
)
```

这些权重只是第一轮程序标尺，不是假装已经得到了真人心理常数。接入前必须通过隔离案例和影子运行校准。

### 决策过程反馈

```text
DecisionFeedback = 0.04 × EDecision × QDecision
```

例子：

| 情况 | EDecision | QDecision示意 | DecisionFeedback |
|---|---:|---:|---:|
| 完整、清晰、有意义的新方案 | 4 | +0.80 | +0.128 |
| 简单但合理的两步判断 | 2 | +0.65 | +0.052 |
| 写得完整，但基本没有区分度 | 4 | +0.10 | +0.016 |
| 强反证后完全原样重试 | 4 | -0.60 | -0.096 |
| 没形成任何决策 | 0 | 任意 | 0 |

这保留了当前 `0.04` 的尺度，也恢复了旧版 `P×Q` 最重要的性质：思考很多不一定舒服，卡住时越用力可能越挫败。

## 四、如何区分“科学复验”和“卡住乱试”

不能简单规定“重复就是坏的”。增加一个结构化意图字段：

```text
decisionIntent =
  solve         直接解决问题
  discriminate  区分两种解释
  replicate     复验弱证据
  explore       没有可靠知识时探索
```

Agent只能声明意图，程序仍然校验：

- `replicate`只有在旧证据较弱、样本少、场景有噪声或目标更精确时才成立；
- 已有强反证、所有条件完全相同，仅把意图写成`replicate`不能逃过deadRepetition；
- `explore`在确实没有可靠知识时合理，但连续多次不整理结果会逐步转为incomprehension；
- 改角色、装备、站位、环境或因果链关键步骤后，可以构成新实验。

## 五、Agency：掌控感是持续状态，不是EDecision分数

掌控感回答的是：

> “这个问题对我很重要，而且我现在看得到一条自己能做、付得起、也相信有效的路吗？”

### 旧方案中值得保留的结构

```text
GoalPressure =
  desire
  × perceivedGap
  × problemClarity

ROI(action) =
  causalConfidence
  × expectedImprovement
  × controllability
  / perceivedCost

Agency =
  GoalPressure
  × pathVisibility
  × saturate(max ROI(action))
```

自然语言解释：

- 问题很清楚、很想解决，但看不到任何路：不是高掌控感，而是高“卡住感”；
- 看得到一条便宜、可信、自己能执行的路：掌控感高；
- 路很确定，但要刷五天只提升10%：ROI低，掌控感仍低；
- 问题已经不重要：即使知道怎么做，也不会产生强烈掌控体验。

### 必须按范围保存

不要只有一个全局“我很有掌控感”的平均数。按下面的范围保存：

```text
问题类型 + 环境类型 + 行为类型
```

例如：

- 对“高血量前排”的“单点换人”掌控感；
- 对“我方暴毙”的“保护角色/站位调整”掌控感；
- 对“输出不足”的“换装提升”掌控感。

玩家可以很会配装，但完全不懂站位，这两种掌控感不能平均。

### 战前与战后更新

1. **战前**
   - 根据玩家当前知识和可见行为计算 `AgencyBefore`；
   - 形成一个清晰新方案后，可能出现 `AgencyPlanned` 上升；
   - 这表示“我现在知道该试什么了”，不是“我已经成功了”。

2. **战后**
   - 只通过EVerify产生的新因果知识重新计算 `AgencyAfter`；
   - 因果链被支持：该路径的可信度提高，Agency可能上升；
   - 因果链被反驳：该路径可信度下降；
   - 证据不足：不更新；
   - 随机赢了但原因不明：R可以很高，Agency不应自动提高；
   - 输了但局部因果链成立：R为负，但Agency可能提高，因为玩家学会了一部分机制。

### 卡住感

```text
Stuckness = GoalPressure × (1 - Agency)
```

它比“失败次数”更准确：

- 想赢、差距大、知道下一步怎么改：失败了但不一定卡住；
- 想赢、差距大、所有已知方法都被反驳：真正卡住；
- 不在乎这个目标：即使没路，也不会强烈挫败。

### 掌控感如何进入情绪

第一版不要把Agency绝对值每回合都加成快乐，否则玩家会靠重复一个已知解法无限领奖。

只记录两个变化：

```text
planningRelief = AgencyPlanned - AgencyBefore
learningControl = AgencyAfter - AgencyPlanned
```

最初先影子记录，不进入总情绪。验证成立后，才允许给“从混乱到知道该做什么”一个很小、会习惯化的正反馈；卡住感则进入长期挫败与换方案/放弃倾向。

## 六、完整结算顺序

```text
1. 玩家接收经过筛选的信息
2. 检索相关知识、角色三标尺和历史假设
3. 计算 AgencyBefore
4. Agent写问题、证据引用、备选行为、因果链和验证目标
5. 程序计算 EDecision 与 QDecision
6. 产生 DecisionFeedback
7. 执行战斗
8. R结算实际结果
9. A结算实际与预期的偏差
10. C结算主动调整带来的自我确认
11. EVerify用玩家可见因果证据确认/反驳/保持不确定
12. 更新因果知识
13. 重新计算 AgencyAfter 与 Stuckness
14. 用新知识进行下一次决策
```

关键顺序是：EDecision和QDecision不能偷看最终胜负；Agency战后只能通过更新后的玩家知识变化，不能直接把胜利当掌控。

## 七、必须覆盖的隔离测试

### A. 决策质量

1. 首次提出完整可验证的新方案。
2. 简单但合理的两步判断。
3. 用不存在的知识拼出完整链。
4. 行为存在，但与问题无关。
5. 假设目标处于玩家不可见信息档位。
6. 写得很完整，但所有结果都能解释成成功。

### B. 重复与修正

7. 强反证后，队伍、装备、站位、环境和假设全部不变。
8. 旧证据只有一次且很弱，明确进行复验。
9. 同队伍但更换站位。
10. 同角色但更换关键装备。
11. 更换一个真正影响当前问题的角色。
12. 只改了无关角色或无关措辞。
13. 保留前半段已确认链，只修正被反驳的最后一环。

### C. 掌控感与结果分离

14. 赢了，但实际是其他角色的大招造成，原假设没证据。
15. 输了，但“减速拖到大招”这条局部链成立。
16. 随机暴击意外获胜，没有任何战前假设。
17. 找到清晰的新方案，但还没有执行。
18. 问题重要、差距大，但没有任何可执行路径。
19. 路径确定但成本极高。
20. 同一套已知解法连续成功，Agency稳定但不重复产生确认奖励。

### 必须满足的方向

- 案例1的DecisionFeedback明显为正；
- 案例7为零或负；
- 案例8不能被误判为死循环；
- 案例9至13只有真正相关的变化才能恢复Q；
- 案例14中R为正，但EVerify与Agency不虚增；
- 案例15中R为负，但因果知识和Agency可以局部上升；
- 案例16只有R/A可能变化，EDecision、C和Agency不应凭空增加；
- 案例18的Stuckness最高；
- 案例20不允许靠Agency绝对值反复刷情绪。

## 八、建议开发顺序

### 第一步：隔离计算器

新建独立 `decision-process-quality` 模块，只读取现有正式数据的副本，不修改情绪、不更新知识。输出：

```text
EDecision
各步骤通过/失败原因
evidenceFit
actionLeverage
testability
discrimination
revision
deadRepetition
incomprehension
QDecision
DecisionFeedback
AgencyBefore / AgencyPlanned
Stuckness
```

先跑上面的20个确定性案例。

### 第二步：正式Agent影子运行

接到正式V27旁边，但不影响行为和情绪。对每次真实决策同时记录：

- 当前固定 `EDecision×0.04`；
- 新 `EDecision×0.04×QDecision`；
- 哪些决策被判为有效修正、复验或死循环；
- Agency和Stuckness如何变化。

人工检查误判，尤其检查Agent用漂亮文字骗过结构验证的情况。

### 第三步：只接入Q

影子结果稳定后，只把正式过程反馈从：

```text
0.04 × EDecision
```

改为：

```text
0.04 × EDecision × QDecision
```

R、A、C、EVerify全部保持不变，先验证“强反证后原样乱试”是否消失。

### 第四步：接入掌控状态

让Agency和Stuckness影响：

- 继续当前方案；
- 换方案；
- 随机探索；
- 暂时刷资源；
- 放弃或转移目标。

初期不把Agency直接加进总情绪。等行为方向验证正确，再校准极小的“找到解法”缓解反馈。

### 第五步：小case通过后再跑章节

先用固定战斗和固定知识验证方向，再让不同类型Agent跑第一章。不要一开始用长跑平均值掩盖公式错误。

## 九、这套方案解决什么

它能同时区分：

- **认真想了但猜错**：EDecision高，Q可以高，EVerify反驳并产生学习；
- **结果输了但学到了东西**：R负，EVerify和Agency局部提高；
- **结果赢了但不知道为什么**：R正，Agency不虚增；
- **弱证据下合理复验**：不是死循环；
- **强反证后完全原样乱试**：EDecision仍承认付出了思考，但Q变负，产生卡住体验；
- **改了真正相关的一环**：revision恢复，成为新实验；
- **看得到解法但还没成功**：Agency提高，不提前伪造R；
- **很想解决却没有路**：Stuckness升高。

## 十、仍需校准的内容

- Q各分量权重；
- `0.04`在加入Q以后是否仍处于合适尺度；
- 强反证需要多少证据和置信度；
- 哪些角色、装备、站位和环境变化算“真正相关”；
- Agency变化何时值得产生很小的即时缓解；
- 不同玩家类型对复杂决策、复验次数和成本的容忍度。

这些都应在程序小case和影子运行中校准，不能提前写成“人类固定常数”。
