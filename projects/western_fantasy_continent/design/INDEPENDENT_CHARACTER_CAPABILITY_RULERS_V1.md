# 角色三套独立能力标尺 V1

## 结论

角色认知现在并行维护三套完全独立的相对标尺：

- `output`：输出；
- `protection`：保护；
- `buff`：给队友提供的增益。

三套标尺都使用现有的同步矩阵求解和“认知人口前30%最低者为零点”规则。系统不求和、不平均，也不长期保存由三者合成的角色总强度。Agent必须先判断当前可见问题，再选择相关标尺。

## 可见证据

三套标尺只消费玩家已经接收到的角色事件：

- 输出：对敌方造成的有效伤害；
- 保护：有效治疗、可见护盾、已吸收/格挡伤害和明确防止的伤害；
- 增益：角色给其他队友施加的可见正面增益。

敌方减益和控制仍保留在角色特点知识中，不混入“增益”标尺。角色给自己的强化也不算团队增益。

如果一场战斗在某个维度没有任何已接收贡献，该维度矩阵完全不更新。系统不会把“本场没有展示”误写成“该角色能力很弱”。

## 更新结构

每个维度都独立保存：

- 角色当前位置；
- 证据场数和刚度；
- 本场角色间相对变化矩阵；
- 当前前30%标尺边界；
- 相对标尺位置、认知等级和排名。

一场战斗可以同时更新一到三套标尺。例如只有伤害信号的战斗只拉动输出标尺；出现治疗和团队加速时，保护与增益标尺才分别更新。

## Agent取用

正式决策请求中的 `characterImpressions` 按角色提供 `capabilities.output`、`capabilities.protection` 和 `capabilities.buff`。正式指令要求：

1. 先根据玩家可见信息判断问题；
2. 伤害不足时查看输出；
3. 生存不足时查看保护；
4. 需要放大队伍时查看增益；
5. 多个问题可以查看多条标尺，但不得长期合成一个角色总分。

历史战斗知识也保存当时的三套坐标，让Agent比较“当时的角色认知”和“现在的角色认知”。

## 换人时的临时配比

角色没有永久综合分，但一次具体换人必须形成一个具体预期。正式决策因此采用“Agent判断问题，程序负责数学”的临时配比：

1. 每个已知角色的一人换人候选，先向Agent展示输出、保护、增益三条独立差值和三个单轴情景；
2. Agent根据当前可见问题给出三个 `0–10` 的粗整数权重，至少一项大于零。例如生存压力为主、兼顾输出时可以给 `输出2 / 保护7 / 增益1`；
3. 程序把权重归一化，因此 `2/7/1` 和 `4/14/2` 表达同一个配比；
4. 程序用归一化权重对三条能力差做加权，再加上已有的、与当前环境有关的角色特点修正，得到本次换人的临时有效变化；
5. 这次临时变化映射成战斗表现预期，并和原始配比一起冻结到换人A账本，后续结算不能重新解释。

公式可以简写为：

```text
本次能力变化
= 输出权重 × 输出差
+ 保护权重 × 保护差
+ 增益权重 × 增益差
+ 当前环境下的特点修正
```

这里的配比只描述“当前问题需要什么”，不是角色新的永久属性。下一关的问题变了，Agent可以给完全不同的配比。

如果某个权重大于零，但对应角色缺少该能力的认知证据，程序返回“信息不足”，不把未知当成零，也不偷偷退回旧综合分。已经存在同关卡、同队伍、同装备的精确历史时，真实历史优先，不需要再用配比估算。

## 与A、C的边界

配比只修正“换人后预期战斗表现从哪里来”。已经通过的换人A曲线、确认感C、换装重算和新关惯性算法没有改动。Agent只提供当前需求配比，不能直接填写预期分、A、C或情绪强度。

如果冻结配比后又换装备，程序从已经冻结的混合战斗进度继续按装备总强度比例重算，并保留原配比。这个路径不再读取旧角色综合强度。旧的非配比兼容记录仍沿用原重算方式。

## 当前限制

- 保护目前使用玩家可见的治疗、护盾和明确减伤信号；没有可见归因的纯承伤不会自动算成保护。
- 增益目前使用可见团队正面状态的幅度或持续时间代理，不宣称已经完成真实人类标定。
- 三套标尺表达相对认知，不是客观战斗数值，也不是胜率。
- `0–10` 是便于Agent稳定输出的粗配比，不表示十分制评分；当前权重语义和认知到战斗表现的系数仍需真实玩家记录校准。
- 当前装备只提供总强度比例，没有把装备词条进一步拆成输出、保护、增益三条作用；因此换装是在冻结的混合预测上整体缩放。
