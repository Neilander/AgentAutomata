# 信息呈现档位契约 V2

状态：冻结  
代码标识：`information_presentation_tier_v2`  
唯一数值源：`game_data/combat-signals.js` 中的 `INFORMATION_PRESENTATION_CONTRACT`

## 目的

游戏和前端不需要给认知模型提交字号、颜色、动画长度等假精确参数。每条玩家可见信息只需选择一个稳定档位。认知模型再把档位与事件意义、玩家目标、相对幅度、同屏竞争、重复次数和玩家感知类型组合起来计算。

V2 将旧四档扩展为八档。主界面从 `0.40` 到 `1.00` 每 `0.10` 一档，方便复杂界面建立连续层级；另保留 `0.25` 的纯背景档。

## 冻结数值

| 代码 | 中文含义 | 呈现证据强度 | 强制接收 |
|---|---|---:|---|
| `background` | 纯背景 | 0.25 | 否 |
| `ambient` | 伴随信息 | 0.40 | 否 |
| `standard_low` | 次级常规 | 0.50 | 否 |
| `standard` | 常规 | 0.60 | 否 |
| `standard_high` | 重要常规 | 0.70 | 否 |
| `prominent` | 醒目变化 | 0.80 | 否 |
| `highlight` | 当前焦点 | 0.90 | 否 |
| `blocking` | 强制确认 | 1.00 | 是 |

这些数值不是最终接收概率。`blocking` 的核心区别也不是数值最高，而是界面必须停留、独占或要求玩家确认，因此程序会强制接收。

## 前端选择规则

### `background` 0.25

- 即使完全错过，也不妨碍玩家理解当前动作。
- 不单独占文字层，允许被其他反馈覆盖。
- 例：动作残影、很小的持续伤害、内部动作开始提示。

### `ambient` 0.40

- 单次可以错过，但会自然重复。
- 可见但不抢占主要信息区域。
- 例：普通技能名、普通掉落、低价值战斗动态。

### `standard_low` 0.50

- 玩家扫视主要界面时有机会读到的次级反馈。
- 与常规反馈共用区域，但视觉权重更低。
- 例：普通伤害、次要数值变化、非核心按钮状态。

### `standard` 0.60

- 正常阅读界面时应当清楚的普通反馈。
- 来源、目标、数值或状态至少有一项明确。
- 例：治疗、护盾、普通操作结果。

### `standard_high` 0.70

- 比普通反馈重要，但不应打断当前操作。
- 适合增加持续时间、尺寸或对比度，不能独占全屏。
- 例：重要状态变化、稀有掉落、装备成长、队伍调整结果。

### `prominent` 0.80

- 本区域的主要变化，应明显高于周围常规信息。
- 同一区域同一时刻应严格限制数量。
- 例：角色倒下、史诗奖励、重要入口开放。

### `highlight` 0.90

- 当前视线焦点；同一注意区域原则上只允许一条。
- 至少有一种独立构图、专属音效、镜头反馈或持续展示。
- 例：大招、关键场地机制、传说奖励。

### `blocking` 1.00

- 使用结算层、确认弹层或必须经过的奖励展示。
- 玩家必须确认，或界面必须停留到玩家主动继续。
- 例：最终胜负、新角色正式解锁、神话物品正式展示。

## 使用边界

- 不允许直接提交 `0.63` 之类的自定义数值。复杂界面通过八档组合，不通过每个页面私调参数。
- 信息的价值、伤害和稀有度不能自动等同于展示档位；档位描述“玩家怎样看见”，不是“设计师希望玩家得出什么结论”。
- 同屏出现多条信息时，认知模型仍会计算注意竞争。把所有内容都标成高档不会让玩家全部看见，只会破坏视觉层级。
- `highlight` 和 `blocking` 必须保持稀缺；`blocking` 不能用来修补普通信息表达不清。
- `action_summary` 与 `team_experiment_result` 是认知运行时内部结算语义，不属于玩家画面，绕过感官门槛且不会暴露给玩家解析器。

## 事件接口

```js
presentation: {
  visible: true,
  informationContract: "information_presentation_tier_v2",
  informationTier: "standard_high"
}
```

旧事件没有 `informationTier` 时，解析器暂按事件语义选择迁移默认档。新代码必须显式标记。

## 校准结果

同一条治疗信息只改变档位时：

| 档位 | 低感知 | 普通感知 | 高感知 |
|---|---:|---:|---:|
| `background` | 7.23% | 18.21% | 38.88% |
| `ambient` | 8.44% | 20.86% | 42.96% |
| `standard_low` | 9.36% | 22.78% | 45.74% |
| `standard` | 10.35% | 24.82% | 48.54% |
| `standard_high` | 11.45% | 26.97% | 51.35% |
| `prominent` | 12.64% | 29.25% | 54.16% |
| `highlight` | 13.93% | 31.63% | 56.93% |
| `blocking` | 100% | 100% | 100% |

表中 `blocking` 是强制接收后的最终结果。其未强制时的基础诊断概率仍连续上升。

真实 355 事件战斗中，非强制信息的长期平均接收率为：

| 玩家感知 | 长期平均 |
|---|---:|
| 低感知 | 24.23% |
| 普通感知 | 48.48% |
| 高感知 | 75.32% |

主界面等距方案的目标误差为 `0.000301`。单独对这一个战斗样本过拟合可把误差降至 `0.000161`，但会得到 `0.44 / 0.5333 / 0.6267 ...` 这类难维护数值，因此没有采用。冻结方案牺牲极小的样本拟合，换取明确、稳定的十进制层级。

同一条 `standard` 信息重复六次后，低/普通/高感知玩家至少接收一次的概率为 `37.70% / 70.91% / 94.37%`。五条常规伤害同屏拥挤时，注意可用度从 `1.0000` 降至 `0.4126`。

## 版本规则

- V2 数值不得因单个界面案例不好看而调整。
- 修改数值或增删档位必须升级契约版本，并重新运行真实战斗、重复、拥挤、三类玩家、信息越界和完整认知回归。
- 前端实现可以改变具体美术风格，但必须保持档位之间的注意层级、同屏容量和强制确认差异。
