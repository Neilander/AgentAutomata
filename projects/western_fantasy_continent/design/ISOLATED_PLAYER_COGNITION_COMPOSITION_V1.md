# 玩家认知三块隔离组合 V1

## 结论

角色认知、非角色事件知识和换人预期不再经过同一个统一路由器。三块各自维护自己的输入、算法和状态，只在换人预期读取资料时发生单向组合。

```text
同一场原始战斗
├─ 角色认知：详细可见战斗表现 → 角色强度矩阵、前30%标尺、特点复核
├─ 非角色事件：玩家接收到的胜负/敌方/场地/奖励/地图/概率 → 类型1与概率机会
└─ 换人预期：更新后的角色认知 + 四人阵容 + 装备 + 本场结果 → 换人历史
```

这三块不是先后覆盖关系。角色认知不会被非角色过滤器压缩或重算，非角色过滤器也不能写角色分数，换人预期只读取前两块的结果。

## `left-2` 是什么，怎么修

`left-2` 只是某一场战斗里的第二个站位，不是角色身份。每场战斗开始时，程序使用该场四名队员的可见名称建立一次性对应表：

```text
left-1 → 灰鸦战士 → hero_warrior
left-2 → 拒马民兵 → militia_barricade
left-3 → 皮鼓民兵 → militia_drum
left-4 → 草药民兵 → militia_herb
```

下一场如果站位变化，会重新建立对应表。进入角色认知的所有我方事件都改用永久角色 ID，原来的战斗站位只留在审计信息中。

程序：`experiments/player_agent_api_loop_v1/stable-character-event-adapter.js`

## 三块分别会产生什么

### 1. 角色认知

角色认知继续由旧模型完整计算：

- 每个角色当前在强度矩阵中的位置。
- 相对“前30%标尺”的距离。
- 当前认知等级，例如“表现普通”“有点强”“有点弱”。
- 群体输出、持续伤害、治疗等特点。
- 特点在后续战斗中的增强、下降或因证据不足而暂不修改。
- 当时队友整体偏强或偏弱的环境。

真实22场结果示例：

- 林地游侠：相对标尺 `+1.008`，当前“有点强”。
- 灰鸦战士：相对标尺 `+0.053`，当前“表现普通”。
- 烬火法师：相对标尺 `+0.033`，当前“表现普通”。
- 星釜炼金师：相对标尺 `-0.984`，当前“有点弱”。
- 赤潮狂战士曾形成“擅长群体输出”，也在后续战斗中出现群攻特点下降的复核记录。

### 2. 过滤后的类型1因果知识

这块先过滤玩家没有接收到的瞬时信号，再按旧类型1合同生成“主体 + 环境 + 行为 → 结构化结果”：

- 当时四人队伍及每人的矩阵位置、前30%标尺、相对标尺距离和认知等级，在某关卡挑战 → 胜负、存活和表现分。
- 玩家通关某关卡 → 地图开放、实际掉落或角色解锁；这些进度结果不归因给当时四名角色。
- 某个场地规则，在某关卡影响战斗 → 可见效果和同时发生的战斗表现。
- 某种可见敌方行为，在某类关卡攻击或支援 → 威胁档位、主要目标或可见效果。

相同关系使用旧知识库的合并键，可以累计样本和结果分布。地图、实际掉落、角色解锁和持续场地规则属于持续可见事实，不随感知档位随机漏掉。概率机会仍进入专用概率账本。

每次挑战观察都保存四人的真实站位顺序、矩阵位置、当时前30%标尺、相对标尺距离、认知等级和证据数。不同四人组合或同样四人交换站位，会形成不同的战斗知识；同样阵容与站位在不同认知阶段的结果则保留各自快照。这一层不替 Agent 判断历史结果是否仍适用，Agent 会同时看到当时事实和当前认知，自行用于决策。

它会提前移走所有我方伤害、治疗、护盾、状态和技能信号，不保存角色证据，不写角色矩阵，也不写换人历史。完整合同见 `TYPE1_FILTERED_CAUSAL_KNOWLEDGE_V1.md`。

程序：`experiments/player_agent_api_loop_v1/received-information-organizer.js`

### 3. 换人预期证据

这块不重新判断角色强弱，只保存本场用于以后比较的资料：

- 本场关卡和区域。
- 胜负与连续表现分。
- 当时四人阵容。
- 当时装备战力和装备组合。
- 本场角色认知更新后的四人强度位置和特点快照。

例如最后一场会保存：四人队伍为灰鸦战士、烬火法师、晨祷牧师、林地游侠；胜利；表现分 `0.878`；装备战力 `1250`；并附带这四人的最新角色认知。

## 真实22场验证

- 战斗：`22` 场。
- 角色场次：`88/88` 全部进入旧矩阵。
- 角色知识中残留 `left-*`：`0`。
- 成功对应的详细可见事件：`2219` 条。
- 达到特点复核门槛的证据：`80` 条。
- 其中高可靠证据：`42` 条。
- 可复核领域：治疗 `19`、群体输出 `38`、持续伤害 `23`。
- 换人历史：`22/22`，每场都保存四名角色的更新后快照。
- 类型1关卡挑战：`22/22`，每场保存四名角色的完整认知坐标；全部满足“矩阵位置 − 当时标尺 = 相对标尺距离”。

旧正式流程原先因身份不匹配，详细特点证据实际没有达到复核门槛。修正后，旧角色认知算法本身没有改，只恢复了它原本应该收到的详细证据。

## 当前接入状态

- `left-*` 永久身份修正已经接入正式角色认知入口。
- 三块的职责边界保持隔离，但已经在正式流程中按顺序组合：旧角色认知先更新，过滤器再生成非角色类型1关系，换人预期读取更新后的认知。
- 过滤后的类型1关系复用旧 `knowledgeBase` 和旧合并入口，没有第二套通用知识库。
- 角色详细事件不会被非角色过滤器压缩；它们继续只更新旧强度矩阵和特点复核。
- 正式 Agent 请求同时包含当前角色认知，以及历史战斗中四人按真实站位保存的认知坐标。
- 原始事件和内部诊断只保留在审计层；归因使用玩家可见的公开语义信号ID。
