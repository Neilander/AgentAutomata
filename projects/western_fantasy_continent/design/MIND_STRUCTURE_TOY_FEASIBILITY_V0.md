# 玩家思维结构 Toy：可行性与最小方案 V0

## 结论

这一步有道理，而且是 Decision 四个特征的上游基础，不是第五个反馈值。

当前 Decision 模型知道要度量：玩家投入了多少主动思考、解决了多少复杂问题、建立了多少秩序、表达了多少自我选择。但它还不知道玩家究竟在脑中操作了什么。`MindStructure` 补的是这一层：把玩家当前理解的局面压缩成一个可以尝试动作、预测后果、接受证据修正的主观小模型。

它不应复制真实游戏，也不应追求完整模拟人脑。它只保留当前决策真正用得到的关系。

## 文献对应

这套想法同时对应几条已有研究路线：

1. 心理模型理论：人会构造对可能世界的内部模型，并在模型里模拟结论，而不只是操作语言句子。
2. 认知地图：人不只会为空间建立地图，也会把抽象关系组织成可导航的图。
3. 世界模型：用于规划的内部模型不必复刻完整环境，只需保留与行动、奖励和价值预测相关的部分。
4. 部分可观察决策：玩家不知道游戏真相，只能维护带不确定性的主观状态，并通过行动同时获取结果和信息。
5. 资源理性规划：人不会展开所有可能分支，而会在有限时间和注意力下选择展开、跳过或剪枝哪些分支。

因此，`buildMindStructure → toy → attempt()` 是合理的工程抽象。但文献支持的是“人使用简化内部模型进行有限模拟”，不代表人脑真的存在一个与代码完全同构的 `attempt` 函数。

## 模块边界

```text
buildMindStructure(context, memory, profile) -> MindToy
estimate(context, requiredEstimates)          -> SubjectiveEstimates
attempt(toy, action, budget)                 -> Prediction
updateMindStructure(toy, observation)        -> UpdatedMindToy
```

### buildMindStructure

输入只能是玩家能够获得的上下文、既有知识、角色认知和玩家自身偏好。输出是玩家主观相信的结构，其中允许存在错误、缺失和不确定性。

Agent 不生成可执行代码。AI 从少量预设结构中选择，识别当前对象、行动、关系和需要估算的位置；另一次 AI 估算只根据玩家可见上下文和记忆填写主观价值、范围、概率、置信度和依据。程序负责校验、组装并运行 `attempt()`。否则每次输出的结构都不同，无法验证，也容易让 Agent 偷用真实游戏规则。

### MindToy

建议用带类型和置信度的图作为共同底座：

```text
MindToy M = (Z, A, R, B, G)

Z：玩家认为当前存在的状态、对象和变量
A：玩家当前看见或想到的行动
R：状态之间的规则、约束、因果或先后关系
B：每个判断的置信度和证据来源
G：当前目标、限制和个人偏好
```

这里的“图”不是只指地图。节点可以是地点、敌人、机关、资源、条件或未来状态；边可以是可移动、导致、依赖、互斥、先于等关系。

### attempt

`attempt()` 表示玩家在主观模型里试一下某个动作，而不是让真实战斗系统再打一遍。

```text
attempt(M, action, budget) -> {
  possibleNextStates,     // 可能后果，不强行只给一个答案
  predictedObservations,  // 玩家预计会看到什么
  goalDelta,              // 离目标更近还是更远
  violatedRules,          // 哪些已知约束会冲突
  informationGain,        // 即使没成功，这一步能排除什么
  trace                   // 实际展开了哪些节点、边、规则和分支
}
```

`budget` 限制玩家会展开多少分支、思考多深。它由玩家特征、当前精神状态和情境共同决定，不能让所有玩家都成为穷举规划器。

### estimate与有限知识

`estimate` 必须能运行在闭卷知识模式。此时模型自身常识不属于玩家知识：精确事实必须逐字段引用玩家知识卡；知识卡缺失就返回 `unknown`。允许基于有限知识推导主观判断，例如食物卡提供“咸香、油润”，玩家偏好卡提供“喜欢咸香、不喜欢油腻”，AI可以估算口味适配，但必须同时引用两张卡。

因此要区分：

- `exact_fact_or_unknown`：卡路里、GI、GL等明确数据只能原样读取或未知。
- `derive_only_from_cited_knowledge`：口味、风险和普通事件收益等主观估算可以推导，但只能使用列出的知识。

程序校验证据ID、字段绑定和原值，不能只靠提示词要求AI自觉遵守。

## 第一版预设四种复杂度模型

四种模型逐级增加结构，高阶模型可以复用低阶模型评分：

1. 单值排行榜：所有当前选项都能压缩成一个固定主观价值，不涉及顺序和状态变化。
2. 多价值排行榜：每个单步选项保留多个价值与特征，再根据玩家目标和偏好加权。
3. 地图模型：AI先估算地点价值，再由程序在位置、每日行动点、路径和前置解锁限制下生成路线，最后复用单值或多值排行榜给路线排序。未确认但玩家预感存在的地点可以保留在主观结构中，但不能直接当成已可执行地点。
4. 状态转移模型：行动改变未来状态和可用行动时，为每个行动分别建立主观状态转移分布，再进行多步预测。不是用一张不区分行动的混合矩阵。

模型选择原则是“最低充分复杂度”，不是信息或选项一多就自动升级。三个完全同分、无法获取额外信息的随机入口仍然只产生零个有效比较；少量选项只要行动会改变后续状态，也可能需要状态转移模型。

## 它如何让 Decision 特征可测

- EDecision：读取真实思考轨迹，如取用了多少关系、展开了多少分支、推进多深、进行了多少比较；不再用文本长度冒充思考量。
- QDecision：看一次思考是否减少了与目标相关的不确定、排除了矛盾，或找到此前未知的可行路径。
- Ordering：看玩家是否新增了正确的先后、依赖、空间路径或职责关系，使原本混乱的事项变得有序。
- ChoiceAuthorship：看最终选择是否来自多个可行分支之间的个人偏好取舍，而不是只有唯一正确解。
- AhaMoment（二层体验）：一次局部结构重组突然解释了多个旧困惑，或一条新关系让大量错误分支同时消失。

## 必须防止的错误

1. 不允许读取真实游戏隐藏状态；这是玩家模型，不是设计师答案。
2. 所有节点、边和规则都要带来源与置信度，防止 Agent 把猜测写成事实。
3. 预测必须允许多个分支及未知结果，不能强行确定化。
4. 不能每轮从零重建。初次建立或切换问题时调用 `build`，观察结果后用 `update` 局部修正。
5. 不能强迫所有行为都经过完整思考。习惯动作、直觉动作和低关注操作允许绕过或只建立极稀疏 toy。
6. 不能以“图看起来聪明”作为验证标准；要检查它是否预测了玩家行为、是否能被证据纠正，以及从轨迹能否稳定算出 Decision 特征。

## 最小隔离实验

第一轮不接正式玩家 Agent，也不接情绪收益：

1. 代码生成 `buildMindStructureAI` 和 `estimateAI` 的结构化请求，AI返回声明式 JSON。
2. 实现四种预设模型和受预算限制的 `attempt()` 解释器。
3. 先用冻结的 AI 合同响应验证数学结构、证据隔离和运行器。
4. 再让真实 Agent 对相同上下文生成结构与估算，验证它能否稳定选择最低充分模型。
5. 后续执行真实行动并输入观察，检查模型是否只根据新证据局部修正。
6. 从 `trace` 读取 EDecision、QDecision 和 Ordering 的原始事实，但暂时不计算爽感。

通过标准：同一真实局面下，不同认知玩家产生不同预测；预测不会泄露隐藏真相；错误认知能被观察逐步修正；有限预算确实导致不同搜索深度；三个 Decision 特征能从运算轨迹得到，而不是让 Agent 自评分。
