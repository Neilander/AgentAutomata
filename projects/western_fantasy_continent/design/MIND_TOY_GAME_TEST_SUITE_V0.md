# MindToy 基础游戏测试集 V0

## 目标

测试的不是 Agent 能否靠搜索器解题，而是它看到规则和局面后：

1. 自己形成了什么主观模型；
2. 每次提出了什么“思路”；
3. 一个思路激活了哪些少量候选或候选组；
4. 它为当前思路检索、估算了哪些信息；
5. 它为什么接受、修改或放弃这个思路；
6. 何时认为方案足够好并停止。

程序求解器只能用于事后验证真实状态、合法性和最优距离，不能替 Agent 构建 MindToy，也不能把后台搜索节点数算成玩家思考量。

## 选择标准

- 规则少，能把有限知识完整写入上下文；
- 状态和合法行动可由代码精确记录；
- 关卡可用固定种子或小尺寸复现；
- 难度可连续调节；
- 一个自然语言“思路”能够对应明确的结构操作；
- 不依赖大量类型知识、操作技巧或长期养成；
- 可以区分提出思路、局部展开、估算、行动和结果更新。

Simon Tatham 的 Portable Puzzle Collection 很适合作为来源：它包含大量小型单人谜题、公开规则、可调参数、游戏种子和源代码，可以生成可复现的小关卡。官方入口：<https://www.chiark.greenend.org.uk/~sgtatham/puzzles/index.html>

## 第一批：四个核心游戏

| 顺序 | 游戏 | 隔离测试的核心能力 | 典型思路操作 | 为什么适合 |
|---|---|---|---|---|
| 1 | Guess（Mastermind式猜码） | 假设、信息获取、证据更新 | 测试颜色是否存在、固定一个位置、用一次猜测切分候选 | 每次反馈都能精确判断一个思路排除了什么；颜色数、位置数和次数均可调 |
| 2 | Light Up | 约束推理、候选压缩、局部Aha | 从编号推出必放/禁放区域、找唯一覆盖点、检查灯光冲突 | 一个规则发现通常同时改变多个格子的可能性，最适合观察“一个思路产生一组候选变化” |
| 3 | Sokoban | 空间结构、Ordering、不可逆后果 | 给箱子分配目标、清理通道、避免死角、先移动阻挡箱 | 规则只有推一个箱子、不能推两个、不能拉，但顺序错误会造成死局，特别适合区分路线搜索和真正的规划思路 |
| 4 | Flood | 连续状态转移、短期规划、启发式切换 | 优先吞并最大边界、先接触某片区域、规划颜色序列 | 每步只有少量颜色选择，但选择会改变整个连通区域；适合观察同一思路如何产生两三条短序列，而不是枚举完整树 |

规则来源：

- Guess：隐藏颜色序列，每次返回颜色和位置的匹配数量，可调整颜色、位置、猜测次数与是否允许重复。<https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/guess.html>
- Light Up：放置灯泡照亮全部空格，同时避免灯互照并满足编号邻接约束；难度可设置为是否需要猜测。<https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/lightup.html>
- Sokoban：一次只能推一个箱子，不能推两个箱子，也不能拉箱子。官方规则页：<https://sokoban.jp/rule.html>
- Flood：每步改变左上连通区域的颜色，在有限步数内让全图同色；颜色数和允许步数可调。<https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/flood.html>

## 第一批的难度阶梯

每个游戏都只做三档，不直接上大关卡：

### Guess

- A：3色×2位、不重复；测试是否形成最简单候选集合。
- B：4色×3位、允许重复；测试是否提出“测试颜色”和“测试位置”两类不同思路。
- C：同一局面给有限知识玩家与错误规则玩家；测试 estimate 和证据更新。

### Light Up

- A：存在一个直接由编号决定的必放灯。
- B：一个思路同时排除多个格子，但仍需第二条思路继续。
- C：需要一次假设或回退；测试失败是否只修正局部结构。

### Sokoban

- A：一个箱子、一个目标，只有路径顺序。
- B：两个箱子，其中一个角落是明显死局。
- C：必须先暂时把箱子推离目标方向来清通道；测试是否产生新的策略思路。

### Flood

- A：每步存在明显最大扩张颜色。
- B：眼前扩张最大并非最终最好，需要两步思路。
- C：同一局面给低、中、高思考预算玩家；比较他们实际提出的颜色序列数量，而不是程序搜索量。

## 第二批：通过第一批后再加入

### Black Box

玩家向隐藏球场发射光线，根据吸收、反射和出口推断球的位置。它比 Guess 更接近主动实验设计：玩家不只选择一个答案，还要选择哪条光线最能区分当前假设。适合测试信息价值和 `EVerify`，但因果规则更复杂，不应作为第一个案例。规则：<https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/blackbox.html>

### Net

旋转网格块，使全图连通且无闭环。适合测试局部约束如何逐渐形成全局结构，以及“边界不能朝外”“避免闭环”等思路是否被复用。规则：<https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/net.html>

### 无猜测扫雷

只使用保证可纯推理求解的生成器。适合区分确定性推理、风险点击和信息展开；但玩家通常带有大量既有扫雷技巧，因此放在第二批。Simon Tatham 版本默认保证无需猜测，可以关闭该保证形成对照。规则：<https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/mines.html>

### Flip

点击一个格子会同时改变它和关联格子的亮暗状态，目标是全部点亮。它是非常干净的状态转移测试，且底层可表示为二进制线性系统；但熟悉数学解法的 Agent 可能直接求解而不表现普通玩家思路，所以作为状态模型压力测试。规则：<https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/flip.html>

## 暂时不作为首批

- 2048：有随机生成、长期启发式和大量玩家既有经验，难以先分清模型形成、习惯和运气；官方开源实现可留作后续随机状态测试：<https://github.com/gabrielecirulli/2048>
- Sudoku：Agent可能直接调用熟悉的解题术语和套路，测到的是预训练知识，不是我们要观察的模型形成过程。
- 国际象棋、卡牌构筑、肉鸽、RTS：规则知识、长程价值和类型经验同时进入，无法定位 `buildMindStructure` 或 `estimate` 的错误。
- 三餐、背包等组合优化：适合之后测试偏好和多价值，但不适合先验证“思路如何逐次产生”。

## 每局必须保存的原始输出

在运行任何程序求解器之前保存：

```text
01_initial_structure_raw.json
02_idea_01_raw.json
03_estimate_for_idea_01_raw.json
04_idea_01_evaluation_raw.json
05_idea_02_raw.json
...
```

每个 `idea` 至少说明：

```text
思路是什么
它对当前结构执行什么操作
它激活了哪些候选或候选组
为什么只关注这些候选
需要从有限知识中估算什么
预计什么结果会支持或否定它
```

验收时先看这些原始输出是否像人的逐步思考，再看行动是否合法或是否接近最优。不能用最终解对了反向证明 MindToy 正确。

## 推荐实施顺序

1. 先做 Guess A/B：最容易看清“一个思路切分一组可能”。
2. 再做 Light Up A/B：验证约束思路是否会批量压缩候选。
3. 再做 Sokoban A/B：验证空间规划、前置顺序和死局认知。
4. 最后做 Flood A/B/C：验证连续状态下多个思路和玩家预算差异。
5. 四个均通过后，才进入 Black Box、Net、无猜测扫雷和 Flip。
