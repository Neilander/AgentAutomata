# 过滤后的类型1因果知识 V1

## 核心修正

信息过滤器不再把“玩家看见了什么”当成最终知识。它只决定哪些瞬时信号被玩家接收；之后继续使用旧类型1合同，把证据整理成：

```text
主体 + 环境 + 行为 -> 结构化结果
```

相同关系使用与旧正式知识库一致的合并键。正式接入后，同一关系再次发生会增加样本数和结果分布，而不是增加一句流水账。

## 流程

```text
原始事件
→ 玩家可见语义与感知筛选
→ 分流角色信号
→ 按关系类型组合证据
→ 主体 / 环境 / 行为 / 结果候选
→ 旧 canonical_causal_knowledge 合并
→ 决策前按当前关卡、队伍和可选行为检索
```

角色伤害、治疗、护盾、特点等继续交给角色认知。概率机会继续交给概率账本。类型1不复制角色强度，也不维护概率估计。

## 当前关系类型

### 队伍挑战关卡

- 主体：当时四人队伍；每名角色同时保存本场更新后的矩阵位置、当时前30%标尺位置、相对标尺距离、认知等级和已有证据数。
- 环境：地区、具体关卡、当时四人的真实站位顺序。站位1到站位4按永久角色身份生成指纹；同样四个人交换站位会形成不同指纹。
- 行为：挑战该关卡。
- 结果：胜负、耗时、双方存活、战斗结束方式、表现分，以及独立保存在该次观察里的四人认知快照。
- 决策用途：把完整的历史战斗事实提供给 Agent，由 Agent 结合当时站位、角色认知和当前环境理解胜负。

角色认知数值不进入知识合并键。同样四个人以同样站位再打同一关，会累计在同一条知识下，但每次观察保留各自当时的完整认知坐标。同样四个人只要交换站位，就进入另一条知识，避免抹掉站位造成的差别。

这一层不判断哪条历史知识“仍然适用”，也不把历史知识标成“可用”或“只作背景”。它只保存并输出事实：当时关卡、四人身份、四人站位、每人的矩阵位置、共同标尺、相对标尺距离与等级，以及战斗结果。正式接入后，由 Agent 阅读这些知识，自行比较当前阵容和当前认知后做判断。

三个数值的关系固定为：

```text
相对标尺距离 = 角色矩阵位置 - 当时前30%标尺位置
```

矩阵位置来自之前的角色强度富集与四人联动更新；前30%标尺来自当时全部已知角色；相对标尺距离才是角色在当时玩家尺度上的位置。

### 通关后的地图推进

- 主体：玩家进度，不归因给当时四名角色。
- 环境：具体关卡和地图推进阶段。
- 行为：通关该关卡。
- 结果：开放了哪些节点。
- 决策用途：判断推进某关会开放什么。

### 通关后的实际掉落

- 主体：玩家进度，不归因给当时四名角色。
- 环境：具体关卡和掉落阶段。
- 行为：通关该关卡。
- 结果：实际掉落的名称、稀有度、部位、等级，以及装备战力是否自动变化。
- 决策用途：判断回刷收益，并理解“掉落进入仓库，不等于自动变强”。

掉落概率不从单次掉落直接推断，另交概率账本累计。

### 通关后的角色解锁

- 主体：玩家进度，不归因给当时四名角色。
- 环境：具体关卡和角色奖励阶段。
- 行为：通关该关卡。
- 结果：解锁了哪个角色；当前队伍不会自动变化。
- 决策用途：判断推进某关是否能获得新换人选项。

### 场地规则

- 主体：具体可见场地规则。
- 环境：地区、关卡和场地阶段。
- 行为：影响双方战斗。
- 结果：出现了哪些可见效果，以及同时发生的胜负和表现分。
- 因果边界：单场只记“场地规则与本场表现同时出现”，不把一次胜负直接断言为场地造成；重复对照后再增强判断。
- 决策用途：判断当前可用关卡中是否存在已经见过的场地风险。

### 敌方攻击与支援模式

- 主体：表现出远程、近身或尚不明确攻击方式的敌方单位；或表现出治疗、护盾、状态、额外技能的敌方单位。
- 环境：地区和关卡类型，例如第二章Boss。
- 行为：攻击我方、治疗敌方、保护敌方、施加状态。
- 结果：可见伤害档位、命中次数、主要目标、可见效果。
- 决策用途：判断敌方主要威胁、集火对象和需要针对的机制。

敌方主体只按可见行为命名，不读取临时敌人名或内部职业。

## 不再生成的假知识

以下内容可以作为中间证据，但不能独立进入类型1：

- “本场胜利。”
- “观察到敌人使用护盾。”
- “看见了地图开放。”
- `observe_*`、`receive_*` 之类把“看见”伪装成因果行为的关系。
- 单独的角色伤害、治疗或群攻证据。
- `diagnosis`、内部职业、临时敌人ID、内部实验结算。

## 真实22场结果

- 输入战斗：`22` 场。
- 形成类型1观察关系：`134` 条。
- 按当前合并键对应：`107` 个知识键。
- 有重复证据、可以累计的知识键：`17` 个。
- 关卡挑战认知快照：`22/22` 场，每场四名角色均有矩阵位置、当时标尺、相对标尺距离、认知等级和证据数。
- 关卡挑战关系：`22` 条。
- 通关后地图/掉落/角色解锁关系：`45` 条。
- 敌方攻击模式：`33` 条。
- 敌方状态：`17` 条。
- 敌方护盾：`10` 条。
- 敌方治疗：`3` 条。
- 场地规则：`3` 条。

持续可见事实完整性：

- 场地：`3/3`。
- 实际掉落：`21/21` 场。
- 地图开放：`15/15`。
- 角色解锁：`9/9`。

全部类型1候选都具备主体、环境、真实行为和结构化结果；`observe_*` / `receive_*` 数量为 `0`，以单句说明充当结果的数量为 `0`。

## 实际例子

```text
当时前30%标尺：1.918
主体：站位1 灰鸦战士（矩阵1.971，相对标尺+0.053，表现普通）
      站位2 烬火法师（矩阵1.951，相对标尺+0.033，表现普通）
      站位3 晨祷牧师（矩阵0.171，相对标尺-1.747，明显偏弱）
      站位4 林地游侠（矩阵2.926，相对标尺+1.008，有点强）
环境：第二章Boss关
行为：挑战第二章Boss
结果：胜利；21.44秒；4人存活；表现分0.878
```

```text
主体：玩家进度
环境：第二章Boss掉落阶段
行为：通关第二章Boss
结果：掉落3件装备；装备战力1250→1250，没有自动变化
```

假设这四个人过去打某关失败，当时某角色矩阵位置是 `1.2`、标尺是 `1.8`，所以相对标尺为 `-0.6`。后来他的矩阵位置升到 `2.5`，同时整体标尺也升到 `2.0`，当前相对标尺变成 `+0.5`。程序不会替 Agent 宣布旧失败失效，只会完整展示这两个时期的认知坐标。Agent可以看出“失败发生在角色相对偏弱的时候”，而不是只看到“A、B、C、D失败过”。如果四个人交换站位，则形成另一条带新站位顺序的战斗知识。

```text
主体：表现出远程攻击的敌方单位
环境：第二章Boss类型
行为：攻击玩家队伍
结果：可见伤害属于主要部分；观察到11次；主要打向灰鸦战士
```

## 当前接入边界

本模块仍是隔离验证。它输出与旧知识库一致的 `mergeKnowledgeObservation` 候选，但还没有替换正式类型1入口。正式接入时应复用旧知识库的样本累计、结果分布、最多八条近期观察和 Agent 知识输入，不创建第二个通用知识库，也不在整理层新增一套历史适用性裁决。
