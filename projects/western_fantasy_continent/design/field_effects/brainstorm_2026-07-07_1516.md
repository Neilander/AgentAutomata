# Field Effect Brainstorm 2026-07-07 15:16

Scope: design-only heartbeat round. No source code changes. Three subagents each proposed three field effects using only formal base roles and existing official mechanisms.

This round intentionally avoided:

- Existing implemented field families: frontline durability, caster skill windows, low-health brawl, backline hunt, DOT pressure, shield sustain, basic-attack frequency, control payoff.
- Earlier brainstorm directions: carry routing, multi-target pressure, status handling, mark economy, tactical window acceleration, lane formation, lone-front formation, death revenge, first-kill, last survivor, ultimate delay, cooldown tax, shield-break objective.

The prompt asked for new field effects that make the encounter's test readable. The three subagent lanes were:

- enemy ecology / threat structure;
- combat objectives / win-condition pressure;
- reward constraints / map hazards / diagnostic failure.

## Consolidated Pass Candidates

### 1. Guarded Captain

Status: pass as the clearest enemy-ecology candidate.

Core idea:

The enemy's highest-power unit becomes a captain. Nearby guards intercept part of the captain's incoming direct damage. The player should learn to dismantle the guard structure before tunneling the captain.

Suggested scope:

- Enemy only for player-facing encounters.
- Can be mirrored in a sandbox, but the readable version is an enemy ecology rule.

Suggested levels:

- L1: 1 guard redirects 18% of direct damage taken by the captain; captain damage +6% while guarded.
- L2: 1 guard redirects 30%; captain damage +10% while guarded.
- L3: 2 guards each redirect 22%; captain damage +8% per living guard.

Favorable teams:

- Warrior or berserker teams that can clear nearby bodies.
- Mage / alchemist area-pressure teams that damage guard and captain together.
- Balanced teams that can swap from guard clear into captain finish.

Counter / risk:

- Pure single-target assassin or ranger teams may feel their damage is leaking unless the guard link is visually obvious.
- If guard numbers are too high, it collapses into a shield-break or frontline-durability variant.
- Guards should not become tougher; they only redirect captain damage.

Player understanding signal:

- The captain has visible guard lines.
- Hitting the captain also damages a guard.
- When guards die, the captain's health drops much faster.

Difference from existing effects:

- Not `Iron Oath`: it does not make frontliners harder.
- Not `Shield Echo` or `Glass Aegis`: there is no shield loop. It changes target priority through enemy ecology.

Validation:

- Check whether teams with guard-clear tools improve more than pure tunnel teams.
- Track captain damage taken before and after guards die.

### 2. Decapitation Writ

Status: pass as the clearest objective candidate.

Core idea:

One enemy is declared the writ target. The player must kill that target within a timer. Success weakens the enemy team; failure creates an enemy counter-push. This teaches focus priority rather than generic damage.

Suggested scope:

- Enemy only.
- Target should be the highest physical/magic output unit or a declared encounter unit, not simply highest HP.

Suggested levels:

- L1: target must die within 18 seconds. Success gives enemy team power -12% and skill haste -10% for 6 seconds. Failure gives enemy team power +10% for 6 seconds.
- L2: 16 seconds. Success: power -18%, skill haste -14% for 7 seconds. Failure: power +16% for 7 seconds.
- L3: 14 seconds. Success: power -26%, skill haste -20% for 8 seconds. Failure: power +24% for 8 seconds.

Favorable teams:

- Ranger single-target teams.
- Assassin access teams.
- Warrior front pressure that can reach the target.
- Mage burst that can help finish the target.
- Priest / bard shells that keep the focused damage dealer alive long enough.

Counter / risk:

- Knight / priest / bard protection can make the writ target too hard to remove.
- If the selected target is a tank, the field becomes a raw stat check.
- Needs a strong visual distinction from mark economy and first-blood rules.

Player understanding signal:

- The target has a visible writ flag and countdown.
- Killing other enemies does not complete the objective.
- On success, enemies visibly lose momentum; on failure, they visibly surge.

Difference from existing effects:

- Not `Hunter Fog`: it does not grant backline access.
- Not `Quarry Sigils`: there is no stacking mark resource.
- Not `First Blood Writ`: only the declared target matters.

Validation:

- Check whether focus teams improve more than broad pressure teams.
- Track target time-to-death and post-window fight outcome.

### 3. Last Spark Fuse

Status: pass as the strongest diagnostic-failure candidate.

Core idea:

Every few seconds, the lowest-health-ratio unit receives a fuse. If that unit is healed or stabilized above a threshold before the fuse expires, the team receives a short reward. If not, the fuse explodes and weakens that unit. This teaches emergency recovery and weak-link protection.

Suggested scope:

- Both teams for sandbox validation.
- Player-facing encounters can use both-side rules if the UI clearly shows both fuses.

Suggested levels:

- L1: every 12 seconds, lowest-health-ratio unit is marked. If it returns above 45% HP within 4 seconds, its team gains received healing +6% for 5 seconds. Failure: target takes 7% max HP damage and power -6% for 5 seconds.
- L2: every 11 seconds, threshold 50%, reward received healing +9% and skill haste +4% for 5 seconds. Failure: 10% max HP damage and power -9% for 5 seconds.
- L3: every 10 seconds, threshold 55%, 3.5-second timer, reward received healing +13% and skill haste +7% for 6 seconds. Failure: 13% max HP damage and power -13% for 6 seconds.

Favorable teams:

- Priest emergency healing.
- Alchemist steady repair.
- Bard rhythm support.
- Knight / warrior teams that keep the marked unit alive through the fuse.

Counter / risk:

- If thresholds are too high, it becomes a forced-healer field.
- If the reward is too large, stable teams snowball too hard.
- Needs clear countdown and fail/success visuals.

Player understanding signal:

- The low-health unit receives a fuse countdown.
- A successful save creates an obvious relief reward.
- Repeated explosions tell the player the team lacks emergency healing, damage intake control, or weak-link protection.

Difference from existing effects:

- Not `Shield Echo`: it is not a generic sustain multiplier.
- Not `Purging Rain`: it does not process status pressure.
- Not `Blood Moon` or `Last Candle`: it tests low-health rescue, not low-health offense or last survivor.

Validation:

- Track fuse success rate.
- Compare teams with priest/alchemist/bard support against pure damage teams.
- Ensure the field creates diagnostic failures rather than only longer fights.

### 4. Twilight Rite

Status: pass/record as an enemy objective variant.

Core idea:

One fragile enemy backline caster/support becomes a ritual core. The core periodically heals the enemy team and pulses damage onto the player team. Killing the core stops the ritual.

Suggested scope:

- Enemy only.
- The core should be a backline `priest`, `bard`, `warlock`, `alchemist`, or `mage` when available.

Suggested levels:

- L1: core HP -18%; every 8 seconds enemy team heals 3% max HP and pulses `core power * 0.25` damage.
- L2: core HP -25%; every 7 seconds heals 4.5% and pulses `core power * 0.35`.
- L3: core HP -32%; every 6 seconds heals 6% and pulses `core power * 0.45`.

Favorable teams:

- Assassin and ranger target access.
- Mage burst.
- Alchemist pressure that can reach the core.

Counter / risk:

- If the ritual is not visually obvious, it feels like invisible enemy healing.
- It overlaps with protect/kill-objective space, so keep it as a distinct "fragile ritual core" subtype.

Player understanding signal:

- A ritual circle and cast timer.
- Enemy team heals and player team is pulsed when the rite completes.
- Killing the core removes the circle.

Difference from existing effects:

- Not `Shield Echo`: the healing comes from a fragile objective, not a team sustain stat.

### 5. Unbroken Tithe

Status: pass/record as a reward-shaping rule.

Core idea:

The player receives extra reward if no unit dies. If the first death happens, the contract breaks and the remaining units receive a short survival compensation so the rule is not only punishment.

Suggested scope:

- Player only.

Suggested levels:

- L1: no-death reward +8%; on first death, remaining allies received healing +8% for 6 seconds.
- L2: no-death reward +15%; on first death, remaining allies received healing +12% and armor +8% for 7 seconds.
- L3: no-death reward +25%; on first death, remaining allies received healing +18% and armor +14% for 8 seconds.

Favorable teams:

- Balanced, low-collapse teams.
- Priest / bard / alchemist support shells.
- Teams that spread damage intake instead of betting everything on one fragile carry.

Counter / risk:

- If reward is too high, the player may over-prefer conservative teams.
- Does not change fight tactics as strongly as `Decapitation Writ` or `Last Spark Fuse`.

Player understanding signal:

- A no-death contract indicator.
- First death breaks the contract with a visible event.
- Repeated near-misses tell the player which unit is the weak link.

Difference from existing effects:

- It affects reward and diagnosis, not combat power identity.

## Record / Risky Candidates

### Covered Artillery

Reason to record:

- The fantasy is good: front units protect a dangerous backline artillery unit.
- It overlaps with `Hunter Fog` and `Decapitation Writ` unless implemented as a very specific "remove cover to weaken artillery" rule.
- It requires good target telegraphing to avoid feeling like random low-HP sniping.

### Dawn Holdout

Reason to record:

- It teaches team survival until a timer.
- It risks becoming "drag the fight" unless the timer reward is very short and the post-timer signal is strong.
- It overlaps with no-death / full-team-integrity lessons.

### Ember Reliquary

Reason to record:

- Protecting a neutral object is a useful objective direction.
- Current combat UI/engine may not support a non-attacking object cleanly.
- It is better as a later tutorial encounter after ordinary team combat is more stable.

### Rune Quake

Reason to record:

- Map hazard is valuable, but current movement and grid hooks are uncertain.
- If implemented as random damage, it becomes unfair noise.
- Keep as future map-system direction, not an immediate field-effect candidate.

## Duplicate / Rejected Items

- `Covered Artillery` is too close to `Decapitation Writ` if the solution is "kill the dangerous backline target first." It should only survive if the cover-removal signal is the main lesson.
- `Dawn Holdout` and `Unbroken Tithe` both test team integrity. `Unbroken Tithe` is cleaner as a reward rule; `Dawn Holdout` is cleaner as a timed survival tutorial. Do not generate more generic "survive until timer" variants next round.
- `Ember Reliquary` and `Twilight Rite` both use an objective unit. `Twilight Rite` is simpler because the objective is an existing enemy role; `Ember Reliquary` needs a new neutral object.
- `Rune Quake` is not rejected, but it should wait until map / tile / movement support exists.

## Empty / Underexplored Directions

Worth asking for next:

- Economy-encounter fields where the reward changes based on combat behavior, but the combat remains fair.
- Boss-phase fields with a readable phase rule that does not require new skills.
- Enemy weakness-discovery fields where a visible resistance or vulnerability flips after a simple condition.
- Build-diagnosis fields for damage type mismatch, such as "physical wall with visible magic weakness," if the combat UI can show damage type clearly.

## Recommended Priority

1. `Last Spark Fuse`: best diagnostic tool. It teaches whether the team can rescue its weak link.
2. `Decapitation Writ`: best objective rule. It teaches focus priority and target choice.
3. `Guarded Captain`: best enemy ecology rule. It teaches dismantling a threat structure.
4. `Twilight Rite`: good follow-up once objective visuals are ready.
5. `Unbroken Tithe`: useful reward-shaping rule, but lower priority than combat-readable objectives.
