# Map Cognition Iteration V1.1: Prison Seen Before Camp Key

- Time: 2026-07-09 18:10 UTC heartbeat
- Basis: revision of V1 after two independent review passes
- Status: recommended next baseline

## Why V1 Needed Revision

V1's direction was correct, but both review passes found the same timing risk:

```text
If Camp A is cleared before the player has seen or failed Prison A, camp becomes a generic side reward, not a remembered key.
```

Therefore V1.1 changes the first chain from:

```text
M4 unlock camp -> M5 unlock prison -> prison failure -> camp/farm wake-up
```

to:

```text
M4 reveals prison desire/threat -> Prison A can create failure memory -> Camp A becomes visible equipment key -> Prison A retry -> character -> low-pressure role proof -> process wall
```

## This Iteration's Target Concepts

Still only:

```text
关卡战斗 -> 装备 -> 换装备 -> 战力 -> 监狱/角色 -> 营地装备钥匙 -> 角色上阵 -> 主线过程墙验证
```

Do not introduce:

```text
场地效果, 稀有度深层, 词条, 辅助角色克制, 细分职业, 藏品
```

Rarity may appear visually as "better reward color", but should not require optimization knowledge yet.

## Revised Map / Node Design

### M1: 狼径巡哨

Purpose:

```text
Teach that levels produce rewards.
```

Reward:

```text
one plain equipment piece
```

Cognition update:

```text
concepts +装备
behaviors +换装备
```

### M2: 破篱小队

Purpose:

```text
Give immediate low-pressure validation for equipping.
```

Tuning:

```text
With one equipped item, player sees about +10% power.
```

Cognition update:

```text
concepts +战力
knowledge +装备能提高战力
first impression: equipment gives small stackable gains
```

### M3: 哨塔杂兵

Purpose:

```text
Repeat challenge/equip loop and establish "many small equipment gains stack".
```

Reward:

```text
ordinary equipment
```

### M4: 旧塔求援

Purpose:

```text
Introduce prison/character as a visible treasure before camp is consumed.
```

Reward / unlock:

```text
Prison A becomes visible and challengeable.
Camp A becomes visible but framed as "旧塔军械补给".
```

Player-facing map implication:

```text
旧塔监狱关着一名可招募角色；附近强盗营地囤着攻坚装备。
```

Cognition update:

```text
concepts +监狱 +角色 +强盗营地
behaviors +挑战监狱 +挑战营地
knowledge:
  - 监狱打过能救角色
  - 营地给更好的装备
```

Why this order works:

```text
The player can see the treasure before consuming the key.
Camp A can now be interpreted as a preparation route, not just random side loot.
```

### Prison A: 旧塔监狱

Unlock:

```text
after M4
```

Difficulty:

```text
Before Camp A: likely fail, but not hopeless.
After Camp A core reward or enough farming: likely succeed.
```

Failure memory:

```text
failed_object: Prison A
baseline: first prison attempt power
primary attribution: 战力不足
secondary attribution: 装备还不够
wake condition:
  current_power >= baseline * 1.3 starts retry wake-up
  current_power >= baseline * 2.0 guarantees retry
on retry fail:
  refresh baseline
```

Important:

```text
Do not expect the player to attribute this failure to "need a role" yet.
The player does not have evidence that roles change outcomes.
```

### Camp A: 旧塔军械营地

Unlock:

```text
visible after M4, ideally highlighted after Prison A failure
```

Role:

```text
equipment key for Prison A
```

Reward:

```text
high-level white equipment + one blue item
target total useful power gain: +30%-50%
```

Knowledge update:

```text
if one equip action or camp reward package raises power >=30%:
  update equipment belief from "small stackable gains" to "some equipment sources create large jumps"
```

### Prison A Success

Reward:

```text
first rescued character
```

Recommended character:

```text
simple, visible function; avoid subtle counterplay.
Examples:
  - 牧师: makes party lose less HP
  - 游侠: safely hits backline/low-HP enemies
  - 盾民兵: gives obvious extra front body but weaker than knight
```

Cognition update:

```text
behaviors +调整队伍/上阵角色
knowledge +监狱能给角色
first impression: new characters are usable pieces, but exact role value still needs proof
```

### M5: 回路清剿

Purpose:

```text
Low-pressure role trial after rescued character.
```

Design:

```text
Easy enough that the player can win with or without the new character.
If the new character is used, combat should visibly improve one simple metric:
  - less HP lost
  - faster cleanup
  - safer backline
  - one enemy dies earlier
```

Knowledge update on success with new character:

```text
knowledge +角色能改变队伍功能
```

If player does not use the character:

```text
new behavior remains unexecuted; next no-cost opportunity should continue nudging use.
```

### M6: 碎盾拦截

Purpose:

```text
First process wall after role trial.
```

Lock:

```text
mainline progress blocked by a slightly harder fight
```

Keys:

```text
Key A: use rescued character after low-pressure proof
Key B: farm/equip enough to brute force
```

Heterogeneous solution check:

```text
Character use changes team function.
Equipment brute force raises raw power.
These are different-quality solutions.
```

Failure attribution:

```text
If no character rescued:
  primary: 战力不足
If character rescued but not used:
  primary: 战力不足
  wake: unexecuted no-cost behavior "上阵新角色"
If character used and still fails:
  primary: 战力不足
  secondary: 队伍功能还不够, but do not over-teach composition yet
```

### M7-M10 And Boss A

Purpose:

```text
Consolidate equipment + character basics.
Boss A is synthesis, not first character tutorial.
```

Do not introduce field effects yet unless they are purely cosmetic or clearly marked as later content.

## Lock-Key Chain

```text
Prison A visible treasure creates desire.
Prison A failure creates failure memory.
Camp A equipment wakes Prison A retry.
Prison A success gives first character.
M5 proves character use at low pressure.
M6 process wall validates character or equipment brute force.
```

## Final Review Merge

Agent A severity:

```text
serious for V1 ordering
```

Agent B severity:

```text
minor for structure, but confirms same key timing risk
```

Merged judgment:

```text
V1 should not advance as-is.
V1.1 resolves the major cognitive timing issue by making prison/character visible before camp key consumption.
```

## Rollback / Advance Decision

Severity after V1.1:

```text
minor
```

Decision:

```text
Do not advance to rarity or field effects yet.
Next pass should validate V1.1 and, if stable, introduce rarity only as reward quality difference.
```

## Skill Update Decision

Potential skill addition identified:

```text
Static lock-key validity is not enough.
A key is cognitively a key only if the player has seen, anticipated, or failed the corresponding lock before consuming it.
```

This pass does not edit the skill yet. Next pass should decide whether to append this as a rule to `lock-key-cognition.md`.

## Next Iteration Suggestion

V2, if V1.1 passes:

```text
Introduce rarity as "reward quality expectation":
  ordinary drops are small stackable gains;
  camp/branch rewards can contain visibly better color/quality;
  do not teach affix optimization yet.
```
