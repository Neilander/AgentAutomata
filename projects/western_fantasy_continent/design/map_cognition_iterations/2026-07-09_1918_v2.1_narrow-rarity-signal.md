# Map Cognition Iteration V2.1: Narrow Rarity Signal

- Time: 2026-07-09 19:18 UTC heartbeat
- Basis: V1.2 accepted for implementation-test
- Status: next active design slice after V1.2 implementation-test

## Purpose

Introduce rarity only as:

```text
reward quality expectation
```

Do not introduce rarity as:

```text
optimization
affix count
build-specific item choice
hard key
equipment system lesson
```

## Required Precondition

V1.2 must be implemented or represented such that:

```text
Prison A is psychologically first.
Camp A is weak/medium preparation clue before Prison A failure.
Camp A becomes strongly highlighted after Prison A failure.
M5 role proof does not compete with equipment or rarity teaching.
```

If these conditions fail, do not run V2.1. Fall back to V1.3:

```text
Camp A preview-only until Prison A failure.
```

## New Concept

```text
蓝装
```

Optional internal concept:

```text
稀有度
```

Player-facing first impression:

```text
Blue rewards are usually more worth checking than ordinary rewards.

blue is required
blue has more affixes

```

## Lock-Key Relation

Rarity is not a lock/key layer yet.

```text
Lock: Prison A failure, attributed to power/equipment.
Key: Camp A equipment package.
Signal: blue reward color helps player expect Camp A package is higher quality.
Treasure: first character from Prison A.
```

Bad interpretation:

```text
Blue item unlocks Prison A.
```

Correct interpretation:

```text
Camp A gives better equipment; some of it is blue; the resulting power gain wakes Prison A retry.
```
