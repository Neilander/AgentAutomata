## Updated Default Implementation Rule

Use hardened V1.3 behavior for the first implementation-test:

```text
After r1_main_4:
  r1_prison is available and focused.
  r1_bandit is visible as preparation preview.
  r1_bandit is not challengeable yet.
  r1_main_5 is not challengeable yet.

After first r1_prison attempt:
  r1_prison fails / retreats.
  r1PrisonFailed = true.
  r1_bandit becomes challengeable and highlighted.
  auto-challenge stops.

After r1_bandit clear:
  r1_prison becomes retryable.

After r1_prison clear:
  r1_main_5 unlocks as role process proof.
```

This is less elegant than soft-ordering, but it better protects the first cognitive loop.

## Revised Lock-Key Chain

```text
r1_main_4 clear
  -> desire: save prisoner
  -> visible preparation: military camp preview

r1_prison first attempt
  -> lock experienced directly
  -> failure memory: power/equipment insufficient

r1_bandit challenge
  -> key action becomes available after lock
  -> reward: 2 high-level white + 1 blue

r1_prison retry
  -> treasure: rescued character

r1_main_5
  -> proof: character changes battle process
```

## Why This Order Fits The Cognition Model

Known default behavior before M4:

```text
continue mainline
```

Known solution concept:

```text
equipment increases power
```

New desire concept:

```text
Prison contains a rescuable character
```

Therefore:

```text
If mainline and Camp are both fully actionable, the player has two known/easy ways to avoid the new desire.
The implementation must temporarily remove or soften those bypasses until Prison failure memory exists.
```

## Concrete Implementation Checklist

State:

```text
state.flags.r1PrisonFailed = false by default
```

Node requirements:

```text
r1_prison requires r1_main_4
r1_bandit requires r1_main_4 plus r1PrisonFailed for challengeability
r1_main_5 requires r1_prison
```

Display:

```text
r1_bandit remains visible after r1_main_4 even when not challengeable.
Before failure, status text should read "预备线索" or "等待攻坚目标".
After failure, status text should read "可挑战".
```

Challenge flow:

```text
attemptNode(item):
  if shouldFirstFailPrison(item):
    mark r1PrisonFailed
    log failure
    select/focus r1_bandit
    return { type: "failure" }
  clearNode(item)
  run after-clear hooks
  return { type: "clear" }
```

Auto challenge:

```text
autoChallenge stops immediately on { type: "failure" }.
```

After-clear hooks:

```text
on clear r1_main_4:
  select/focus r1_prison

on clear r1_bandit:
  select/focus r1_prison

on clear r1_prison:
  select/focus r1_main_5
```

Links:

```text
For r1 only:
  main_4 -> prison
  main_4 -> bandit
  prison -> main_5

Do not draw:
  main_5 -> prison
```

Rewards:

```text
r1_bandit:
  2 高等级白装 + 1 蓝装

r1_prison:
  林地游侠

r1_main_5:
  no rarity teaching
```
