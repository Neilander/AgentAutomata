## Map / Node Design Implemented

### M4 After-Clear State

After `r1_main_4` clears:

```text
r1_prison:
  visible
  available
  selected/focused

r1_bandit:
  visible
  preview-only
  status: 预备线索
  not challengeable

r1_main_5:
  not available
  requires r1_prison clear
```

### Prison First Attempt

First attempt at `r1_prison`, before Camp is cleared:

```text
does not clear Prison
sets state.flags.r1PrisonFailed = true
logs: 战力还不够，也许附近的军械能帮助攻坚。
selects/focuses r1_bandit
auto-challenge stops immediately
```

### Camp Key

After Prison first-fail:

```text
r1_bandit:
  becomes challengeable
  desc: 旧塔军械也许能帮你重新攻进监狱。
  reward: 2 高等级白装 + 1 蓝装
```

Camp before Prison first-fail is not a consumable reward. It is only a visible preparation clue.

### Prison Retry And M5

After `r1_bandit` clears:

```text
r1_prison:
  becomes retryable
  selected/focused
```

After `r1_prison` clears:

```text
r1_main_5:
  unlocks
  selected/focused
  desc: 救出林地游侠后，观察新角色如何更早处理后排威胁。
```

## Lock-Key Chain

```text
r1_main_4 clear
  -> desire: save the prisoner / get a character

r1_prison first attempt
  -> lock: cannot save them yet
  -> failure memory: power/equipment insufficient

r1_bandit
  -> key: equipment package after the lock is felt

r1_prison retry
  -> treasure: 林地游侠

r1_main_5
  -> process proof: character changes battle process
```

## Failure Memory

```text
failed_object: r1_prison

    - 军械营地也许有攻坚装备
attribution:
  primary: 战力不足
  secondary:
    - 装备还不够
wake_conditions:
  prototype: clearing r1_bandit immediately wakes Prison retry
  later numeric model: current_power >= baseline * 1.3 starts retry chance
```
