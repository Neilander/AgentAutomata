## Map / Node Design

### M5: Role Process Proof Buffer

M5 remains a low-pressure proof node.

Purpose:

```text
Let the player notice that the rescued character can change battle process.
Do not give a blue reward here.
Do not mention rarity here.
```

If battle/team wiring is not available, M5 can still use explicit node text, but the risk rises:

```text
"救出林地游侠后，观察新角色如何更早处理后排威胁。"
```

### M6: First Milestone Reward Quality Signal

M6 is not a hard lock. It is a milestone reward beat after role proof.

Node role:

```text
process level + reward-quality marker
```

Suggested node text:

```text
旧路哨塔。守军更完整，首次击破会掉落一件蓝装。
```

Reward:

```text
1 蓝装 + normal small rewards
```

Do not say:

```text
蓝装更强
蓝装有更多词条
你需要蓝装
稀有度决定词条数量
```

The intended first impression is weaker:

```text
"harder / milestone nodes often have more check-worthy rewards."
```

## Lock-Key Chain

This pass should not create a new hard lock. It should stabilize the reward-quality layer.

```text
M5 role proof
  -> knowledge: roles can change battle process

M6 milestone challenge
  -> treasure: first clear blue reward
  -> knowledge: milestone/harder nodes may give better-quality rewards

Future lock, not this pass
  -> a later process wall can ask the player to combine role process + better reward checking
```

Why no hard lock now:

```text
The player just learned Prison/Camp/Role.
Adding a second forced failure immediately would make the tutorial feel mechanical.
M6 should be a positive reward-quality beat, not another wall.
```

## Failure Memory

M6 should ideally be clearable with either:

```text
use the rescued character and current equipment
or
brute force via extra farming/equipment
```

If M6 fails, record a soft failure memory:

```text
failed_object: r1_main_6
baseline_state:
  known_concepts:
    - 装备
    - 战力
    - 角色
    - 蓝装
  known_knowledge:
    - 装备能提高战力
    - 角色可能改变战斗过程, if M5 was perceived
    - 蓝装通常更值得检查
attribution:
  primary:
    - if M5 role proof was perceived: 战斗过程/角色使用不足
    - otherwise: 战力/装备不足
  secondary:
    - 装备还可以提升
wake_conditions:
  - equipping a new blue or visible power gain can wake retry
  - using the rescued character can wake retry if M5 proof was perceived
```

Important:

```text
Do not force M6 failure just to teach blue.
Blue is a reward signal here, not the key to a lock.
```
