# 民兵、装备与锁钥循环迭代报告

- 日期：2026-07-10
- 范围：独立 `/map_progression_lab/` 第一地区
- 方法：每轮单项改动后，由两名知识受限玩家 Agent 试玩；主 Agent 分析报告后继续修正
- 边界：未接回佣兵小镇；未修改正式职业技能或基础数值

## 目标链

第一地区现在验证以下体验链：

1. 两名完整英雄与四名功能极端的民兵建立英雄稀缺感。
2. 主线 1-3 提供低压战斗与早期白装。
3. 监狱首次形成约 11% 幸运通过、约 89% 失败的角色目标。
4. 失败后继续主线 4-5，发现一次性军械营地。
5. 营地集中提供攻坚装备，完成后不能重复刷。
6. 再战监狱并营救游侠；游侠不会自动入队。
7. 玩家手动用游侠替换弓民兵，Main 7 用真实伤害贡献验证角色价值。
8. Boss 失败后重刷最近主线，取得可见装备提升，再次验证成长。

## 实现结果

- 新增共享角色名单：2 名完整英雄、4 名极端民兵，以及监狱奖励游侠。
- 新增正式装备运行时：8 个部位，等级提供基础数值，稀有度控制词条数量，按职业需求自动配装。
- 调整第一地区拓扑：监狱在 Main 3 后出现；营地在 Main 5 后出现；Main 6 同时要求 Main 5 与监狱完成；Main 7 是游侠验证关。
- 新增队伍整备浮窗，营救后由玩家明确换人；换下角色的装备会重新分配给当前出战队伍。
- 人类路径使用实时战斗画面；Agent 路径秒算并输出报告。二者共用 `CombatSimulation`、阵容、场地、随机种子和掉落种子。
- BattleView 改为固定时间步累积，避免帧率改变战斗结果。
- 战斗中重置会取消旧回调；刷新中断会持久化为一次撤退，不发奖励，也不会重复计败。
- Boss 只有敌方全灭才算通关；时限结束一律视为失败。

## 玩家 Agent 发现并推动的修正

1. 初版监狱是绝对墙，装备提升没有作用：改成高质量民兵关，并把营地放到失败后的自然路径。
2. 游侠曾自动替换角色：改为名单解锁与手动换人。
3. Page 与 cognition seed 不同，同一状态会出现相反胜负：统一战斗与掉落 seed。
4. 波次预览会串入正式战斗：正式开战与离开战斗页时清理预览计时器。
5. 实时贡献统计读取错误阵营字段：同时接受 `left` 与 `ally`。
6. Boss 时限血量判胜与“击败首领”冲突：Boss 改为必须歼灭。
7. Boss 首败目标不够明确：未获得可见提升前，目标改为重刷最近主线。
8. 监狱失败记忆没有写出硬钥匙：明确为推进到 Main 5 并完成一次性军械营地。

## 最终双 Agent 验收

- Agent 1 扫描 200 个种子：所有 Boss 胜利均为歼灭；首败后 113 个样本全部进入 Main 10 刷取路径；30 步内没有卡死。
- Agent 2 严格按 `observe()` 目标完成两条独立流程，分别 15、16 步通关；监狱失败链、手动换游侠、Main 7 贡献与 Boss 首败链全部成立。
- 最终结论：本轮无阻断问题，通过。
