# 动作—注意力链 V0

这是一个完全隔离的最小原型，用于验证以下认知单元能否跨游戏工作：

```text
注意力区域
→ 用条件筛选目标
→ 规则把后续原子动作粘到当前动作上
→ 动作改变世界或改变待执行动作参数
→ 新动作产生下一片注意力区域
→ 在自己决策、他人决策、随机结果、知识缺口或链条结束处停止
```

它不接入正式玩家 Agent，也不替代现有 `one_turn_match_v0`。旧 Match 是“拿到完整合法行为集合后逐项向前演算”；本原型研究的是，一个动作如何依据空间关系主动观察并展开出后续动作。

## 通用表示

- 空间：最小空间单位与有方向、可分类的连接。
- 注意力区域：空间单位、区域内部连接、通往区域外部的连接。
- 筛选器：在区域里沿连接查找实体或空间单元；V0支持全选、首个、按字段首个、每条方向上遇到的最近对象。
- 原子动作：移动、放置、移除、翻开、创建、伤害、计算、调整，以及已知结果和不可继续模拟的边界。
- 粘接规则：`当前动作/结果满足条件 → 生成注意力区域 → 筛选目标 → 追加后续动作`。

## 三个案例

1. 车吃子：从车的位置沿四个正交方向观察，只看每个方向遇到的第一个棋子；友军会挡住后面的敌军。
2. UFS放骰：放骰后观察同列飞船，检查下降路径；AA规则只把待执行移动量减一，不直接改变世界。漏掉它后，主链仍顺畅运行，但飞船落到爆炸格并伤害城市。
3. 打牌触发事件：打出卡牌后，同一条规则自然粘出“翻开事件”和“放置指示物”两个动作；翻开后遇到他人决策，模拟明确停止。

## UFS自然语言规则首次编译

`ufs-rule-ai-compile-v0.js`保存了本轮人工AI编译实验：输入只有8句玩家可见规则与公开空间结构，AI先写出解释，再把它们编译成9条声明式粘接规则，交回同一个通用运行器执行。

这次真实规则编译纠正了旧小案例的一个错误：防空修正来自骰子所放的防空房，不是飞船下降路径上的某个天空格。测试覆盖普通房、防空房、1点骰归零、同列多飞船、箭头后二次落点检查、母舰额外下降但不结算行效果、骷髅立即失败、城市伤害与飞船返航、白骰在确定性连锁结束后进入随机边界。

真实规则也补出了四项通用基础设施：

- 注意动作把被注意实体当前所在空间作为锚点传给下一条规则。
- 条件支持标签包含与排除，数值调整支持上下限。
- 后续动作可标记为链尾执行，使确定性连锁先于随机或决策边界完成。
- 已知胜负是独立终点，不应伪装成知识缺口。

## 接入程序版 UFS

`ufs-engine-chain-adapter-v0.js`把同一个注意力链运行器接到了`standard-engine.js`：

- 放置工人骰仍完全交给正式引擎结算，适配器不重写房间、飞船或城市规则。
- 正式结算结果同步成注意力世界，后续实验规则再从结果中筛选对象并追加动作。
- 扩展规则是可插拔的。本轮示例为“每次移动一架飞机后，随机再移动另一架飞机”；若它落入爆炸格，又可粘接“相邻列飞机移动”。
- 规则声明顺序可以颠倒；真正的执行顺序由`动作 → 结果 → 满足下一条规则`决定。删掉中间规则后，下游连锁不会凭空触发。

这验证的是一个真实的一回合可玩切片，而不是完整玩家策略：程序版UFS负责世界真相，注意力链负责玩家脑内可组合的局部流程。实验规则造成的额外移动目前由适配器执行，不自动套用正式引擎未公开的全部飞船落点副作用；需要哪项副作用，应继续作为显式规则粘接。

## 子 Agent 逐句盲编译

`glue-action-contract-v1.md`把一个可粘接单元固定为：规则来源、触发条件、注意力区域与筛选、产生的原子动作、调度方式。`glue-program-v1.js`负责拒绝未定义字段、错误上下文路径、硬编码示例实体和不受支持的动作。

盲测子 Agent 只能依次读取R01到R08，不能读取旧编译答案、正式引擎或隐藏行为测试。第一轮合同过松，结构通过但行为仅3/12；AI发明了`pending_action`、`resolutionMode`、`.contains`等运行器不认识的接口。收紧每种Action的精确输入/输出，并明确`compute → notice → adjust → execute`的可修正参数模式后，第二轮首次达到11/12。唯一失败是注意力区域只进入列首、没有沿天空向下扩展；只反馈“同列第二架没移动”后，子Agent局部补充`sky_down`连接，最终18/18通过。

18项包括完整行为、规则倒序、拆除中间规则和逐句前缀增长。这说明在当前UFS片段里，AI确实能依据规范把自然语言规则逐句粘成可执行临时程序；也说明合同必须是封闭且可机器检查的，只有宽松JSON外形并不足够。

## 当前边界

- 已完成一次由当前AI人工解释并编译8句UFS规则的正向案例；尚未接入独立模型调用，也没有证明跨模型、改写措辞和重复运行时稳定。
- V0验证确定性执行骨架，不模拟真实玩家的注意力容量、漏粘概率或熟练化。
- 多条规则当前按优先级生成动作；还没有冲突消解、取消尚未执行动作或并行时序语义。
- 已能驱动程序版UFS的一次真实放置并在结果后粘接扩展规则；还不是会自行决定放哪颗骰子的完整玩家。
