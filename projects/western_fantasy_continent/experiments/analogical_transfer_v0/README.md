# 单例模糊类比迁移 V0

目标不是找出几乎相同的旧记录，而是验证：只看过一个源场景后，能否在换对象、换领域、换措辞和角色强弱互换的目标场景中，通过模糊向量检索取回正确源轨迹，并把源轨迹的结果重新绑定到目标角色。

每个因果家庭只有一条源经历。实验比较：

1. 只编码原始当前画面；
2. 编码原始前后变化；
3. 临时角色槽位归一化后只编码当前画面；
4. 临时角色槽位归一化后编码前后变化。

槽位只表示“同一个参与者在轨迹各步中的身份连续性”，脆弱、坚硬、失效、接触、越过阈值等决定性内容仍是自然语言，由GTE连续空间判断。取回源轨迹后，`{actor}`、`{target}`等槽位替换成目标角色，从而输出目标自己的后继状态。

本实验不验证AI能否从原始战报自动抽出槽位；那是下一层解析问题。这里单独检验模糊类比和角色重绑定有没有增益。

## 冻结结果

每个因果家庭只有一条源经历。23个开发案例选择了`normalized_transition`，之后42个留出案例只运行一次：

- 总体39/42（92.9%）；
- 已知规律跨场景迁移31/32（96.9%）；
- 换领域10/11、换对象9/9、失效条件覆盖2/2、困难反例8/8、角色强弱互换2/2；
- 完全陌生规律拒绝8/10；
- 取回旧结果但不重新绑定时，目标角色落地率0%；重新绑定后为96.9%。

四种表示在同一冻结集上的对比：

| 表示 | 正确 |
|---|---:|
| 原始当前画面 | 27/42 |
| 原始前后变化 | 19/42 |
| 角色归一化当前画面 | 34/42 |
| 角色归一化前后变化 | 39/42 |

这证明模糊向量有用的条件不是“把更多原始句子塞进去”，而是先保持临时角色的对应关系，再比较变化结构。完整不可覆盖结果见`artifacts/frozen_results.json`。

限制：角色槽位和归一化描述目前由实验数据预先提供，尚未验证AI能否从真实战报稳定生成；后继状态由取回轨迹的槽位模板重新绑定，不是用向量算术凭空生成。
