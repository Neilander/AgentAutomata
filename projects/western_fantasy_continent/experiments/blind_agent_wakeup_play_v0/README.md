# 规则记忆驱动动作粘连：两阶段盲测 v0

## 想验证什么

暂时不实现自动注意力。先让 AI 遍历规则并手动分配注意力，形成可复用的动作、注意力预设与粘连记忆；随后只给初始动作和场景事实，观察它能否自行想起后续动作并执行到自然终点。

## 两阶段隔离

1. 阶段 1：子 Agent 只读 `rules/R01.txt` 至 `R08.txt`，生成并冻结 `outputs/phase1_memory.json`。
2. 阶段 2：阶段 1 冻结后才创建 `scenarios.json`；同一子 Agent 只读冻结记忆和场景，生成 `outputs/phase2_predictions.json`。
3. 预测提交后才创建 `hidden_expected.json` 并运行 `evaluate_predictions.js`。
4. 另一个 Agent 独立复核规则闭合性、场景提示强度、注意力因果性和评分风险。

文件时间顺序：阶段 1 记忆 00:02:14，场景 00:03:40，阶段 2 预测 00:06:26，后置期望 00:07:34。

## 结果

- 程序评分：7/7 个最终状态精确正确。
- 严格语义复核：5 个无歧义正确，2 个条件正确。条件是接受“箭头横移到城市命中格”也构成城市命中；当前 R07 字面只写了“下降到天空区域下方”，接口尚未闭合。
- 覆盖：箭头递归到城市、防空零移动、母舰落骷髅、爆炸无即时效果、白骰随机停止、路径格不误触发、双飞船分支。
- 没发现阶段 1 记忆针对具体场景硬编码；场景也没有列完整动作链。

## 结论边界

这证明了：显式规则记忆可以在这些小场景中充当动作之间的“胶水”，所以“先由 AI 手动 assign 注意力，之后再迭代自动注意力”的路线可作为 MVP 继续。

这没有证明：输出的注意力轨迹真的因果性地驱动了推演。阶段 2 一次读到了完整场景，理论上仍可能先得出答案、再补写注意力说明。场景还使用了“箭头格”“城市命中格”等强语义标签，测试的不是从原始视觉里发现机制。

## 下一次最小补强

改成分步遮罩执行：Agent 先提交下一关注对象，环境只返回该对象的局部信息，并将请求—返回—唤醒动作写入不可回写日志。这样才能区分“注意力驱动推演”和“答案后回填解释”。同时在预测前由独立方冻结场景、期望及哈希。
