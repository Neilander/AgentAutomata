# 两阶段盲测独立严苛审查

## 审查范围与证据边界

本审查只以题目指定的 8 条规则、两阶段说明、`scenarios.json`、两阶段输出、`hidden_expected.json` 与 `programmatic_evaluation.json` 为实验证据；未读取评分器实现，因此只能审查可见评分契约和评分结果，不能确认评分代码实际如何计算各布尔项。

有一个必须披露的独立性瑕疵：仓库级 `AGENTS.md` 要求工作前读取 `coop_repo/LATEST.md` 及其当前报告，这与本任务“不要读取其他 UFS 实验”的隔离要求冲突。执行仓库协议时，当前交接记录暴露了另一个 UFS 实验的汇总指标和实现概述。它没有包含本盲测的 7 个场景、预测或答案，本审查也未据其修正任何判断；但严格说，本次审查员并非处于完全无外部 UFS 先验的洁净环境。后续若要把审查本身当作正式独立复核，应在不加载仓库交接记录的隔离工作区重新做一次。

## 总结判定

- 对照后置的 `hidden_expected.json`，7 个预测的 `finalState` 均逐字段精确一致，规则 ID、记忆 ID 和最少步数也均满足可见期望；`programmatic_evaluation.json` 所报 7/7 与文件内容相符。
- 仅按 R01–R08 的自然语言语义独立判断，5 例可无保留判为正确；`arrow_to_city_recursive` 和 `two_ships_split_consequences` 的最终状态是**有条件正确**，条件是接受场景中的“城市命中格”本身等价于 R07 的“下降到天空区域下方并击中城市”。R07 没有明说横向箭头移动到一个天空位置 ID 也构成“下降到天空区域下方”，因此这两例存在规则—场景接口缺口，不能把 7/7 表述成毫无歧义的纯规则推导。
- 场景没有直接列出完整后续动作链或其后果，阶段 1 记忆确实提供了关键的动作连接；但场景包含高度语义化的触发标签、箭头目标、母舰下一位置，甚至一个明确的 `rightSideAction`。所以实验验证的是“由显式环境线索唤醒已整理的规则记忆并串链”，不是从弱线索中自主发现潜在动作。
- `attentionTrace` 在成品层面完整、顺序总体符合阶段 1 的预设；但现有文件无法证明这些注意力选择在生成预测时被 AI 因果性地、逐步地手动分配。它同样可能是得到答案后的回填解释。`attentionWasExplicit: true` 只能支持“输出里有显式轨迹”，不能支持“轨迹真实驱动了推演”。
- 没看到阶段 1 记忆中出现任何场景 ID、具体初始状态或最终答案，且本地文件时间显示记忆早于场景、预测早于隐藏答案；这些都是反对直接硬编码的弱证据。它们不是密封执行记录或不可篡改时间戳，不能排除同一作者事后协调场景、预测、期望和评分器。

## 后续动作是否由阶段 1 记忆唤醒

### 成立的部分

`scenarios.json` 每例只给出一个 `initialAction`，没有给出 `nextActions`、动作序列、伤害数值、飞船返回、母舰下降后禁止右侧动作、骷髅行判负、爆炸格无即时效果或白骰重投等完整执行指令。以下关键连接只能从阶段 1 记忆取得：

- 放骰 → 整列飞船下降以及防空房减值；
- 移动完成 → 只看终点而不结算路径；
- 箭头终点 → 横移 → 把目标格当作新终点递归结算；
- 母舰下降格 → 母舰下降 → 跳过右侧动作 → 检查骷髅行；
- 城市命中 → 伤害 1 → 飞船返回等待区；
- 白骰 → 未放置骰子重投 → 在未知结果前停止。

阶段 1 记忆本身没有场景 ID、坐标、初始生命或预期最终状态，内容是对 R01–R08 的一般化整理。按成品内容判断，后续链不是直接从场景的动作列表照抄出来的。

### 必须降格表述的部分

场景并非只给“原始物体状态”，而是给了强语义线索：

- `feature` 直接写有“向右箭头格”“城市命中格”“母舰下降格”“骷髅行”“爆炸格”；
- 箭头目标列和目标位置被直接给出；
- 母舰的 `nextPosition`、`nextPositionFeature` 已给出；
- `rightSideAction: 获得1科技` 是一个在场景中被直接列出的后续动作，只是规则要求本链不得结算它。

因此，“场景完全没有直接列出任何潜在后续动作”这一强说法不成立。更准确的说法是：**场景给出触发特征和动作所需事实，但没有给出应否执行、完整后果和递归链；这些控制关系来自阶段 1 记忆。** 特别是“母舰下降格”和“城市命中格”已经把动作语义编码进标签，降低了纯记忆检索难度。

## 注意力轨迹审查

### 成品轨迹的合规性

7 例都有按顺序编号的 `attentionTrace`，每项包含关注对象/区域、关注原因、观察结果及唤醒记忆。其顺序总体遵守阶段 1 预设：

- 先看骰子、列与防空房，再更新本列飞船；
- 只结算最终停留格，路径格仅在用于排除时被查看；
- 箭头后主动转向目标格并再次检查；
- 母舰下降后查看新行与骷髅标记，同时明确右侧动作可见但不结算；
- 多飞船场景先识别两个终点，再分别处理箭头/城市与爆炸格分支；
- 白骰场景在确定飞船终点后查看未放置骰子，并在未知重投结果处停止。

没有发现把路径格当终点、零移动仍触发下一格、母舰右侧动作被误结算、爆炸格被虚构效果或随机结果被提前猜出的情况。

### 不能由现有证据证明的过程主张

`attentionTrace` 是预测文件内的事后结构化文字，不是原始逐步交互日志、模型 token 轨迹、工具调用记录或被强制的“先分配注意力、后读取局部状态”的执行记录。场景在阶段 2 一开始整体可读，输出者理论上可以一次读完全部字段、先算出答案，再补写一条看似合理的注意力轨迹。

而 `hidden_expected.json` 没有逐步注意力期望，`programmatic_evaluation.json` 只给出 `attentionWasExplicit: true`，没有说明验证了哪些语义和先后约束。因此本实验最多证明“AI 提交了符合格式且语义合理的显式注意力叙述”，不能证明“AI 的内部推演确实由这些手动注意力分配所驱动”，更不能把它等同于神经网络内部注意力机制的可观测证据。

若要验证“手动遍历”而不仅是叙述，应让执行器分步只暴露被选中的局部：Agent 先提交下一关注对象，环境再返回该对象内容，并形成不可回写的事件日志。这样才可排除全局读取后回填轨迹。

## 硬编码、泄漏、自导自演与评分器风险

### 有利证据

- 阶段 1 记忆覆盖 R01–R08，但不包含 7 个场景的 ID、坐标或最终状态，结构也可用于同类新场景；未见明显的逐测试题硬编码。
- 文件系统时间显示：`phase1_memory.json`（00:02:14）早于 `scenarios.json`（00:03:40），`phase2_predictions.json`（00:06:26）早于 `hidden_expected.json`（00:07:34），随后才是评分结果（00:07:42）。这与所声明的两阶段顺序一致。
- 最终状态采用精确对象比较，而不是相似文本评分；这是当前评分中最有约束力的部分。
- 输出没有简单激活全部规则：例如防空房例未激活 R05，路径城市例未激活 R07，表面上体现了选择性。

### 高风险或未排除项

1. **后置答案导致自导自演风险高。** `hidden_expected.json` 明示 `createdAfterPredictionSubmission: true`，并使用预测文件中已有的精确记忆 ID。即使时间顺序真实，答案也是看过提交后才建立，缺少预测前的承诺哈希、独立出题者签名或不可变基线。后置答案可以无意或有意适配预测。

2. **同一实验包缺少职责隔离证据。** 从允许读取的文件看不出规则作者、场景作者、阶段 1 Agent、阶段 2 Agent、期望作者和评分器作者是否独立。若由同一 Agent/会话连续完成，便是自生成题、自答、自建答案、自评，7/7 的证据强度会明显下降。

3. **时间戳只是弱证据。** 本地 `CreationTime`/`LastWriteTime` 可修改，也没有内容哈希链或外部时间戳；它们支持但不能证明没有回看、重写或泄漏。

4. **场景可能按已生成记忆定制。** 目前时间反而显示场景晚于阶段 1 记忆。这有助于证明记忆没有针对既存场景写答案，却允许出题者挑选恰好被该记忆覆盖的案例。它不是真正预先冻结的留出集，也不能测试记忆对独立分布的泛化。

5. **记忆召回评分主要是字符串成员资格。** 可见期望要求若干 `requiredMemoryIds`，但没有证明这些记忆在推演中发挥因果作用。提交者可在知道 ID 后把所有非禁止 ID 填入列表；多数案例甚至没有 `forbiddenMemoryIds`。本次输出看起来克制，但评分设计本身容易被投机。

6. **规则召回也有相同问题。** `requiredRuleIds`/`forbiddenRuleIds` 只能验证标签集合，不能验证规则的应用位置和方向。多数案例的 `forbiddenRuleIds` 为空；复制所有规则 ID 在其中五例可能仍通过该项。

7. **`continuedLongEnough` 可能被填充步骤绕过。** 期望只提供 `minimumActionSteps`。例如“检查爆炸格无即时效果”“检查母舰新行”等观察/判定也被写入 `actionTrace`，可以通过增加无状态变化的检查步骤满足长度，步数本身不是动作链正确性的可靠代理。

8. **显式注意力检查看起来过弱。** 可见期望没有正确注意对象、顺序或唤醒关系；评分结果只报告一个布尔值。除非未提供的评分器实现另有严格逻辑，否则很可能只能检查轨迹非空/字段存在，无法识别答案后回填、错误关注顺序或虚假因果叙述。

9. **最终状态虽是精确比较，ground truth 仍有语义缺口。** 两个箭头到城市的期望直接接受了未由规则闭合的“横移即城市命中”解释。评分器精确地检查了一个可能由答案作者自行补全的规则接口，因此“精确”不等于“语义无争议”。

10. **执行隔离没有审计日志。** 两阶段说明写了允许读取范围，但现有产物没有文件访问日志、独立进程/上下文证明、冻结哈希或不可修改的阶段提交记录，无法证明 Agent 实际遵守了读取限制。

综合判断：未发现产物内容中的**明显场景级硬编码**，但后置期望、同包自评分、无密封执行和弱过程检查使“答案泄漏/自导自演”仍然是**未排除的高影响风险**。不能仅凭 7/7 宣称已经排除了这些风险。

## 这个结果能证明什么

在接受“城市命中格”接口解释、并相信阶段顺序与读取限制确实执行的前提下，本实验可以证明：

- R01–R08 可以被整理成不含具体测试状态的通用动作 schema、注意力预设与胶水记忆；
- 该显式记忆足以支持这 7 个小型、确定性或明确停止边界场景中的多步串链；
- 产出的 7 个最终状态与后置期望精确一致；
- 输出能够正确处理本组中的零移动、只结算终点、箭头递归一次、母舰立即失败、无即时效果、随机停止边界和双飞船分支；
- Agent 能生成一份与这些推演相符、对象级显式的注意力说明。

这是一个有价值的**可行性演示**：显式规则记忆可以作为行动之间的胶水，使只给初始动作的场景继续运行到自然终止。

## 这个结果不能证明什么

本实验不能证明：

- 注意力轨迹真实地驱动了推演，而不是答案后的解释；
- AI 内部产生了可类比神经激活的注意力或记忆唤醒机制；
- 阶段 1/阶段 2 的文件读取隔离实际得到强制执行；
- `hidden_expected.json` 独立于预测制定，或评分器没有按预测调适；
- 对未见、对抗性、噪声化或换措辞场景具有泛化能力；
- 对箭头链循环、多级箭头、多个母舰/城市效果、效果顺序冲突、城市致命阈值、不同防空点数、多列并发等未覆盖边界正确；
- 能从不带“箭头格/城市命中格/母舰下降格”等强语义标签的原始视觉或低层状态中发现动作；
- 记忆 ID 的列出就是该记忆对答案产生了因果贡献；
- 7/7 的小样本结果可外推为 UFS 或一般游戏推理系统的可靠性、鲁棒性或可扩展性。

## 建议的最低补强

1. 在阶段 2 前由独立出题者冻结场景和期望，发布内容哈希；期望不能在看到预测后创建。
2. 分离规则/场景作者、预测 Agent 和评分作者，至少保留独立会话 ID 与不可修改的提交时间线。
3. 把“城市命中格”的触发语义写进规则，或把场景改成明确的“箭头目标位于天空区域下方并击中城市”，消除两例接口歧义。
4. 用交互式遮罩环境验证注意力：先提交关注对象，后获得局部信息；禁止一次读完整场景并回填轨迹。
5. 评分器校验每一步前置条件、状态转移和注意顺序，而不仅是最终状态、ID 集合和最少步数；为规则/记忆增加禁止滥报或精确集合检查。
6. 增加预测前冻结的对抗留出：同义改写触发词、无关特征干扰、箭头非城市目标、多级/循环箭头、顺序敏感的多飞船后果，以及“没有可唤醒动作”的负例。

## 最终意见

将本结果称为“在 7 个自包含样例上，显式阶段 1 记忆支持了正确的阶段 2 串链，后置评分为 7/7”是合理的。将其称为“已严格证明 AI 在盲测中通过手动注意力和记忆唤醒自主发现全部后续动作，且无硬编码、泄漏或自导自演”则证据不足。

严苛口径下的结论是：**产物质量良好，5 例语义闭合、2 例条件正确；行为可行性得到支持，但盲性、过程因果性与独立评分尚未被证明。**
