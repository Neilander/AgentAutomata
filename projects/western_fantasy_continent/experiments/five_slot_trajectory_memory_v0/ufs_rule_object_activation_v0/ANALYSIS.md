# 结论：向量适合唤醒候选，不足以单独完成精确对象绑定

本实验用真实离线 `GTE-multilingual-base`，测试10个案例、21种自然语言说法。程序没有实现“同列”“白色”“最终落点”等关系判断；它只编码一句查询和当前对象描述，再做一次矩阵点积。正确答案只在打分完成后参与评测。

## 两种候选范围

- 全局混合对象：飞船、骰子、图标、轨道等一起参与。成对排序准确率79.76%，已知正确数量时整组完全正确47.62%。
- 注意力池：上一层注意力先限定为本动作需要扫描的对象类别，例如天空飞船，但保留所有同类错误对象。成对排序准确率84.92%，已知正确数量时整组完全正确66.67%。

注意力池更接近实际接线位置。它证明注意力范围本身很重要，但仍不能把向量相似度当成精确逻辑执行器。

## 用户原始例子

查询“骰子放在第三列，注意与这颗骰子处于同一列的所有飞船”时：

- A（第3列飞船）：0.731
- B（第3列飞船）：0.712
- C（第4列飞船）：0.689
- D（第2列飞船）：0.673

所以在已经限定为飞船的注意力池内，A、B确实都排在C、D之前；三种改写均保持这个结果。但若把参照骰子本身也混入全局候选，它会因为与查询字面高度相似而排到0.855，说明必须尊重上一层注意力范围，不能让所有153项无差别竞争。

## 耗时

- 模型加载：2.04秒。
- 57条不同对象描述首次建缓存：3.03秒，摊销53.21毫秒/条。
- 新查询在线编码：中位91.16毫秒，P95 110.98毫秒。
- 5~6个缓存候选的一次矩阵激活：中位0.0087毫秒。
- 缓存矩阵规模：10项0.010毫秒、100项0.031毫秒、1000项0.393毫秒、1万项2.086毫秒、10万项15.685毫秒（中位数）。

因此速度瓶颈不是矩阵检索，而是新文本的向量编码。对象不变时应缓存，只给发生变化的对象重新编码。

## 接线判断

正确结构不是“纯向量直接决定绑定对象”，而是：

1. 注意力模块先限定当前扫描池。
2. 一次矩阵乘法给同类对象排序，唤醒一小批候选。
3. 对候选做关系举证/校验，例如列号相等、终点图标、距离阈值。
4. 高激活但校验失败的情况进入反馈，形成更具体的区分轨迹。

这不是退回遍历全部规则。矩阵仍然一次性完成模糊唤醒；精确校验只作用于很小的候选组，并负责向量模型天然不擅长的数值、否定和关系约束。
