# 交互式注意力遮罩 v1

## 目的

验证一个比“事后写注意力轨迹”更强的流程：Agent 每一步必须先提交关注对象，环境才返回那一小块事实；相应动作只能在事实已揭示后的下一轮执行。

## 主实验结果

- 6 个预冻结场景，10 轮交互。
- 22 次关注、22 次动作、0 次环境拒绝。
- 6/6 最终状态与预测前冻结的期望精确一致。
- 12 项冻结输入哈希未变，10 轮请求—响应哈希链闭合。
- 轨迹确实表现为：基地格 → 列内飞船 → 下降 → 关注终点 → 唤醒后续动作；箭头、母舰、双飞船分支都跨轮继续。

## 严苛结论

**遮罩协议通过；注意力或规则记忆的因果证明不通过。**

环境成功强制了外部顺序“先关注、后看见、再动作”，这是相比 v0 的真实进步。但案例 ID、局部特征和动作 operation 强语义对应，例如 `arrow → follow_arrow`、`city_hit → resolve_city_hit`。因此机械接口策略没有被排除。

## 机械消融对照

`mechanical_baseline.js` 明确不读取规则、Agent 记忆或期望，只按响应字段名映射下一 operation。结果同样是：

- 10 轮
- 0 次拒绝
- 6/6 最终状态正确

这说明主实验的成功不能归因于阶段 1 规则记忆；当前接口本身已经编码了足够多的答案。

## 已发现的环境/评分缺口

- 案例名直接暴露主题，如 `mothership_skull`、`white_random_stop`。
- 响应包含 `landingMustBeCheckedAgain`、`newRowMustBeChecked` 等下一步提示。
- 过程 `expectedSequences` 在 transcript 后才写入评分器，没有预测前冻结。
- 评分器信任 `runtime/private_state.json`，没有从初态重放全部命令。
- `finish_case` 没检查 `descentResolved`；白骰重投也可在未下降时被提前尝试。
- 环境、评分器、记忆和哈希链没有外部提交锚。
- 第 8 轮人工提示“尚有分支不能提前结束”略带引导；不过 Agent 在第 7 轮已主动声明保留 ship-b，因此不改变该分支是否被想起的事实。

## 下一版必须同时满足

1. 案例使用不透明 ID。
2. 观察返回原始/中性的局部事实，不返回下一步提示。
3. 动作使用不透明或通用低层操作，不能与 feature 一一同名。
4. 提供多个可关注对象和无关诱饵，不能让关注路径只有唯一接口。
5. 预测前冻结环境、评分器、过程不变量、场景、终态期望和哈希。
6. 评分器从密封初态重放 transcript，不信任 runtime。
7. 同时运行有规则记忆 Agent、无记忆 Agent 和机械基线：只有前者显著更好，才能支持规则记忆的因果贡献。
