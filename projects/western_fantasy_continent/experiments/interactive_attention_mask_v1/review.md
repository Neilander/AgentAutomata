# 独立严苛审查：交互式注意力遮罩 v1

## 结论先行

**结论：协议执行层面通过，注意力因果性层面仍不足以通过。**

当前产物可信地显示：这名 Agent 在 6 个小型、强结构化案例中，按接口要求先发出关注命令，收到局部事实后才在下一轮执行相应动作；10 轮请求—响应链在当前文件集合内闭合，6 个最终状态全部精确命中，且没有被环境拒绝的命令。这比上一版“一次读完整场景后再写注意力轨迹”明显更强，因为关键事实的可见时间和动作可执行时间已被环境分隔。

但它仍不能证明“Agent 的内部注意力真正驱动了动作回忆或规划”。公开案例名、局部特征名、动作操作名和环境返回字段泄漏了大量一一对应的解题语义；一个不理解 UFS、只会按接口名称配对并满足前置条件的机械策略，很可能得到相同轨迹。评分器还存在后验拟合和不重放环境的严重证据缺口。因此，6/6 应解释为**这套有限状态接口被无误走通**，不能升级为“注意力机制成立”或“动作粘连记忆具有因果作用”。

## 1. 冻结哈希、10 轮链与 6 个终态

### 已核验成立

- `FROZEN_MANIFEST.md` 列出的 12 个文件（阶段 2 协议、公开开局、8 条规则、密封案例、密封期望）的当前 SHA-256 均与清单及 `evaluate.js` 中的常量逐项一致。
- 本地修改时间顺序与“先冻结、后作答”叙事相容：密封期望为 00:25:34，冻结清单为 00:26:03，Agent 记忆为 00:29:30，第一轮请求为 00:30:34，最后一轮响应为 00:38:21。
- 独立重算 10 轮链得到：每轮 `requestHash` 都等于对应请求文件的 SHA-256；每轮 `responseHash` 都等于去掉自身哈希字段后的响应核心哈希；第 2–10 轮的 `previousResponseHash` 都正确指向前一轮；最终哈希 `26cabc8c...` 与运行时状态记录一致。
- 共有 22 个关注命令、22 个动作命令、0 个拒绝。6 个案例均标记完成，当前运行时终态与 `sealed/expected.json` 逐字段精确一致：
  - `arrow_city`：飞船返回等待区，城市 3→2；
  - `air_defense_zero`：零移动，状态不变；
  - `mothership_skull`：母舰下降到 r1 并判负；
  - `path_not_endpoint`：只结算 r2 爆炸格，r1 城市命中不触发；
  - `white_random_stop`：飞船链完成后重投，随机结果保持未知；
  - `two_ship_split`：一艘箭头后命中城市，另一艘停在爆炸格。

### 证据边界

这些哈希只证明“当前文件彼此自洽”，不是不可抵赖的预提交。冻结清单、环境代码、评分器、Agent 记忆、运行时状态均未被外部时间戳、签名或仓库提交锚定；拥有写权限的人可以整体重建文件和哈希链。文件时间也可修改，只能作辅助证据，不能单独证明真实生成先后。

尤其重要的是：`evaluate.js` 的本地修改时间为 00:39:01，晚于最后一轮响应 00:38:21；其中用于判定“关注—动作序列精确一致”的 `expectedSequences` 不在预测前冻结清单内。因此，**最终状态期望确实表现为预测前冻结，但过程序列评分标准没有表现为预测前冻结**，存在看完 transcript 后再把实际序列写成满分标准的后验拟合可能。

## 2. 是否真的先关注、后见事实、再动作

就当前 transcript 的可观察时序而言，答案是**是**：

- 第 1 轮关注基地格，第 2 轮关注列内飞船，第 3 轮才执行列下降；
- 第 4 轮关注下降终点，第 5 轮才跟箭头、降母舰或确认无立即效果；
- 箭头横移后第 6 轮再次关注新终点，第 7 轮才结算城市命中；
- 母舰下降后第 6 轮关注新行，第 7 轮才宣告骷髅判负；
- 白骰案例第 6 轮关注未放置骰子，第 7 轮才重投；
- 双飞船案例第 8 轮关注第二艘飞船终点，第 9 轮才确认爆炸格无立即效果。

环境对这些关键动作检查了此前披露标记，且每个活跃案例每轮只允许一个命令，所以当前记录中不存在“同一轮先看再做”或“未看局部特征直接做关键动作”。这是真实新增的程序性约束。

但应严格限定表述：它证明的是**外部协议顺序**，不是内部注意力因果。请求中的 `reason` 和 `expectedWakeup` 没有被环境或评分器验证，完全可以事后写成漂亮解释；也没有反事实实验显示删除 `agent/memory.json`、打乱记忆 ID 或换成机械策略后成绩会下降。

## 3. 语义泄漏与“机械按接口走”风险

泄漏很重，足以构成主要混淆变量：

1. 公开案例 ID 直接暴露答案主题：`arrow_city`、`air_defense_zero`、`mothership_skull`、`path_not_endpoint`、`white_random_stop`、`two_ship_split`。Agent 在看任何局部事实前已知道每局要验证什么。`mothership_skull` 几乎直接给出终局，`path_not_endpoint` 直接提示忽略路径，`white_random_stop` 直接提示随机停止边界。
2. 局部特征与动作操作是一一同名映射：`arrow`→`follow_arrow`，`city_hit`→`resolve_city_hit`，`mothership_down`→`lower_mothership`，`skull`→`declare_loss`，`plain/explosion`→`resolve_no_immediate_effect`。这更像 API 分派题，不需要复杂规则回忆。
3. 环境动作结果继续给出程序提示，例如 `zeroMovementMeansNoLandingEffect`、`landingMustBeCheckedAgain`、`newRowMustBeChecked`、`rightSideActionResolved:false`、`newValues:"unknown"`。这些字段不仅报告局部状态，还直接提示下一步或停止条件。
4. 所有案例前 3 步完全同构，之后分支数极小；协议又列出全部合法关注命令和动作命令。一个机械基线可以采用“基地→列→下降→看飞船格→按 feature.kind 选择同名动作→无 pending 时 finish”的策略，无需使用阶段 1 记忆。

因此，当前实验没有排除“Agent 只是机械按接口走”。要排除它，至少需要：不透明案例 ID；不透明或中性操作 ID；返回原始局部事实而不是下一步提示；加入无关/诱饵关注对象；用未见同义改写或组合场景；并实际运行一个不读规则/不读记忆的机械基线作对照。

## 4. 相比上一版多证明了什么，仍不能证明什么

### 多证明了

- 局部事实不再一次性暴露，Agent 必须主动选择关注对象才能获得信息。
- 关键动作有环境级披露前置条件，当前记录确实跨轮满足“先关注、后动作”。
- 密封最终状态在作答前已有哈希，相比上一版“预测后再建期望”更能抵抗终态标准向答案适配。
- 多飞船分支、路径/终点区分、箭头递归复查、母舰新行复查与随机停止都在同一交互状态机中实际走通，而不只是自然语言宣称。

### 仍不能证明

- 不能证明自然语言 `reason` 或 `expectedWakeup` 是动作产生原因，而不是动作决定后的解释。
- 不能证明 `agent/memory.json` 对成绩有因果贡献；没有记忆删除、错误记忆、ID 重命名或机械基线对照。
- 不能证明 Agent 理解了 UFS，而非把自解释的 feature 名映射到自解释的 operation 名。
- 不能证明对弱标签、同义改写、噪声、诱饵、未见组合、长链、视觉输入或开放动作空间的泛化。
- 不能证明阶段 1/2 的读取隔离真实发生；当前只有文字禁令，没有独立访问审计或文件系统权限隔离证据。
- 不能证明哈希链未被有写权限者整体重建，也不能证明运行时状态由 transcript 唯一重放得到。

## 5. 环境实现与评分器漏洞

### 高风险

1. **评分器不重放环境。** `evaluate.js` 直接信任 `runtime/private_state.json` 的终态，只检查请求中的 operation 序列、响应哈希链和冻结文件哈希；它没有从 `sealed/cases.json` 加载初态并逐命令重演，也没有验证每条 response 的内容是否真由对应 request 和环境逻辑产生。运行时状态、响应链和序列可以分别被协调伪造后仍通过。
2. **过程标准后验可调。** `expectedSequences` 写在未冻结、且时间晚于 transcript 的 `evaluate.js` 中。这使“序列精确命中”无法作为预注册证据。
3. **关键执行件未冻结。** `masked_env.js`、`evaluate.js`、`agent/memory.json`、`PHASE1_INSTRUCTIONS.md` 和 `FROZEN_MANIFEST.md` 本身都不在冻结校验范围；无法证明实验过程中运行的是当前看到的环境版本，也无法证明记忆未被事后编辑。
4. **哈希链无外部锚。** 链只在目录内部自洽，没有签名、提交哈希、只追加日志或第三方时间戳；其防误改价值有限，不能抵抗整体重写。

### 中风险与具体实现缺口

5. `finish_case` 没有检查 `descentResolved`。灰骰案例在初始状态就可能直接结束；`air_defense_zero` 的初始终态恰好等于期望，环境本身会接受“第一轮直接 finish”。当前硬编码序列评分挡住了这条捷径，但环境协议并未真正封死。
6. `reroll_unplaced_dice` 同样不检查 `descentResolved`。白骰案例可先关注未放置骰子，再在尚未执行飞船下降时重投，因为初始 `pendingLanding` 为空。当前序列评分仍是唯一阻挡。
7. `follow_arrow`、`resolve_city_hit`、`resolve_no_immediate_effect` 只校验当前位置已披露及格子类型，不校验该飞船是否确有待结算落点；`reroll_unplaced_dice` 也没有“一次性”保护。现有案例没有利用这些口子，但状态机约束不完整。
8. 评分器不校验请求 schema、`reason`、`expectedWakeup`、命令 kind 与 operation 的语义配对，也不逐项核对 request/response 一一对应；关注理由质量和所谓“唤醒记忆”实际没有进入通过条件。
9. 精确硬编码唯一序列会把“满足规则但关注顺序不同”的有效策略判错，同时又因序列与答案同源而高估当前策略；这不是稳健的过程评分。

## 最终判定

- **产物一致性：通过。** 12 项当前冻结哈希匹配，10 轮当前链闭合，6/6 终态精确一致，0 拒绝。
- **交互遮罩执行：通过。** 当前轨迹确实做到先提交关注、收到局部事实、再于后轮动作。
- **预注册严谨性：部分通过。** 最终状态期望较好地预冻结；过程序列、环境、评分器和记忆没有可靠预冻结。
- **注意力驱动动作的因果证明：不通过。** 强语义泄漏、无机械基线、无记忆消融、理由不评分，使“机械接口遍历”与“规则记忆被注意力唤醒”无法区分。

最严谨的对外表述应是：**v1 证明了一个带局部披露前置条件的有限状态交互协议可以被 Agent 无误完成；它尚未证明内部注意力或动作粘连记忆是成功的原因。**
