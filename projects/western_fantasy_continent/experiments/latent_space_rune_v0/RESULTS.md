# GTE 高维符文 V0 结果

## 结论

GTE 的 768 维空间里确实能提取出多条有用的连续语义方向，但当前不能把九条方向的分数直接当作独立、准确的角色属性概率，再连续相乘完成多轮猜测。

换句话说：**“空间中存在方向”初步成立，“直接用这些方向可靠锁定元素”尚未成立。**

## 实测

- 模型：`Alibaba-NLP/gte-multilingual-base`，CPU，完全离线加载。
- 候选：40个虚构角色；坐标只来自机制描述。
- 维度：768。
- 语义轴：9条。
- 语义轴平均 AUC：`0.846`。
- 真值坐标猜测：40/40，Top-1 `100%`。
- GTE 坐标猜测：Top-1 `10%`，平均目标名次 `8.525`。
- “不治疗但能阻止死亡”反向检索：Top-8 中6个正确，精度 `75%`。

各轴 AUC：

| 轴 | AUC | 判断 |
|---|---:|---|
| 直接治疗 | 0.964 | 清楚 |
| 护盾 | 0.989 | 清楚 |
| 减伤 | 0.753 | 有信号但不稳定 |
| 强制阻止死亡 | 0.487 | 基本没有有效区分 |
| 控制 | 1.000 | 清楚 |
| 爆发输出 | 0.882 | 较清楚 |
| 持续输出 | 0.993 | 清楚 |
| 位移 | 0.947 | 清楚 |
| 禁止治疗 | 0.599 | 很弱 |

## 为什么平均 AUC 不低，最终猜测却很差

每条轴单独看时，排序大多有意义；但当前程序把轴分数校准成概率后连续相乘。轻微误差经过九轮相乘会不断放大，甚至出现获得真实反馈后“有效候选数量反而增加”的情况。

此外，40个角色依靠九条属性组合才能唯一识别。只要“阻止死亡”和“禁疗”两条轴不可靠，许多组合就会被投到错误位置。

因此问题不在多维猜测框架：真值坐标已经证明框架能工作。当前问题主要位于“文字向量 → 可用于推断的属性坐标”这一层。

## 同词异义结果

- “锁血 = 致命伤保留1点生命”：阻止死亡分高于禁疗分，正确。
- “锁血 = 禁止敌人恢复生命”：模型仍把阻止死亡分排得更高，错误。

这说明完整描述已经能产生一定上下文差异，但“锁血”的游戏先验仍会压过局部定义，不能只依赖单个整句向量。

## V1 方案

1. 一个属性不再只用一条正负方向，改成多个语义原型：机制定义、战斗结果、反事实、典型使用场景。
2. 把角色拆成多个机制向量，而不是把所有能力压成一个角色平均向量；角色坐标由机制向量集合计算。
3. “未知”与“低值”分开。低可信轴不参与强排除，只降低一点权重。
4. 提问价值同时考虑切分幅度和该轴可靠性，避免优先使用当前不可靠的轴。
5. 反馈更新先保留版本空间，再做软排序；不再把九个未经校准的概率直接相乘。
6. 加入相同词语、相反游戏定义和随机技能名三组对照，检查模型究竟在读当前定义还是吃词语先验。

在接玩家模拟前，至少需要满足：关键轴 AUC 均不低于 `0.85`、两种“锁血”都分流正确、反向检索 Top-8 精度不低于 `0.875`、40目标 Top-1 不低于 `0.80`。
