# 局部变化唤醒实验结果 V0

## 结论

变化箭头可以作为“下一条动作—注意力预设”的候选唤醒键，但不能单独拥有最终触发权。

正确结构是：

1. 程序注意力先确认真正受到作用的局部对象；
2. 只为该对象形成局部前后变化箭头；
3. 用这个箭头匹配该对象记忆中多次经历形成的触发箭头原型；
4. 唤醒最接近的下一条预设；
5. 再由空间、状态和规则条件进行二次校验。

## 关键结果

- 直接使用整幅场景箭头时，“飞船下降并碰到炸弹”首先被识别成下降，而不是接触；场景中同时存在多种变化，不能压成一根箭头。
- 注意力先切出“危险装置未接触 → 被下降飞船碰撞”后，关系识别由初版2/6提升到5/6。
- 当前状态点直接加关系箭头再找终点不稳定，常常仍最接近“未变化”；GTE是编码器，不是任意坐标的解码器。
- 改成“当前局部变化箭头 → 已学触发箭头原型”后，6/6已学case正确唤醒：碰撞炸弹、改写主语的矿车碰撞、飞船进入箭头格、炸弹受热、观察炸弹、移走炸弹。
- 6个不该唤醒的case通过5个：不在同列、只从路径经过、距离未知、未知符文、未学过的受潮都保持不唤醒；“炸弹被涂蓝”错误唤醒碰撞链。

## 严格解释

这不是一套可靠的规则触发器，而是一套可行的联想候选生成器。它已经能回答“现在发生了这种变化，我过去学过的哪段后果最像”；它还不能回答“这段后果一定发生”。错误涂色案例证明，只有相似度阈值仍会产生牵强联想。

因此在UFS里应当是：飞船下降的路径注意力确认落点对象；若落点是炸弹，再用局部接触箭头唤醒爆炸预设；爆炸是否真的成立、影响多大，继续由已读规则和程序演算确认。

## 当前风险

- 触发预设只覆盖炸弹与箭头格，样本很小。
- 每个预设只积累2至3条例句，尚未测试错误经验、遗忘和路径依赖。
- 0.35相似度与0.08领先差是探索阈值，没有经过独立校准。
- 未知变化拒绝仍不可靠，必须保留规则条件二次校验和“保持疑问”出口。

## 动作粘合真实接入验证

第二轮不再只统计向量分类，而是把召回结果送入现有`imagination_v2`动作运行器：召回器选择允许参与匹配的胶水，原运行器负责检查落点标签、执行动作并继续展开后果。

六项运行结果全部符合预期：

- 消融组没有召回器：动作链停在`ship_descend`。
- 飞船落到炸弹：`ship_descend → trigger_bomb → damage_city`，城市HP确实从3变为2。
- 随机追加移动落到炸弹：复用同一个`ship_descend`和同一条炸弹胶水，得到相同三步链。
- 飞船落到箭头格：选择另一条胶水，得到`ship_descend → ship_shift_right`，飞船位置确实横移。
- 炸弹只在下降路径中、不是终点：链条停在`ship_descend`，没有爆炸。
- 飞船落到未知符文：没有已学预设，链条停在`ship_descend`。

向量原始召回在6个case中为5/6；“炸弹被涂蓝”仍错误联想到碰撞。但把召回作为候选，再用`contact + endpoint_overlap`事实校验后，胶水选择达到6/6，错误候选没有进入动作链。

这证明它对动作粘合的实际价值不是取代胶水条件，而是从大量记忆预设中唤醒少量可能相关的胶水；精确状态事实再决定是否真正粘上。
