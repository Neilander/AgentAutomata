# 玩家情绪生成模型案例协议 V2

## 1. 验证对象

验证的是：

```text
客观事件 + 玩家档案 + 历史
→ 固定事件影响公式
→ 生理/化学动力学
→ 多情绪输出
```

不验证“程序能否从一段文字中认出 angry、afraid、ashamed 等词”。任何直接把自然语言叙述送进情绪分类器的结果，都不能作为本模型成绩。

## 2. 每个案例必须拆成三份

### 来源事实 `source`

只保存：

- 来源名称、链接和精确位置；
- 情绪发生前可核查的事实；
- 每条事实的独立编号；
- 同一人物或作品的来源组编号。

### 冻结输入 `input`

只保存：

- 引用了哪些来源事实；
- 客观事件字段；
- 事件发生前已经存在的玩家档案和历史；
- 输入整理者；
- 是否看见过答案；
- 冻结时间和内容哈希。

`input` 中禁止出现 `emotion`、`goldEmotion`、`actualEmotion` 等答案字段。内容冻结后再改一个数，哈希校验必须失败。

### 真实答案 `gold`

单独保存：

- 来源实际自报或明确描写的情绪；
- 是即时还是稍后状态；
- 答案证据的位置和类型；
- 答案整理者和揭晓时间。

来源没有报告数值强度时，强度必须记为未知，不能凭“非常害怕”自行换算成 0.9。

## 3. 两类案例不能混用

### 发现集

开发者或输入整理者已经看过答案。

用途：

- 发现公式缺项；
- 找到错误分流；
- 检查时间顺序和共存情绪。

不能：

- 报盲测准确率；
- 证明模型能预测陌生真人；
- 因为调参后命中就称为泛化。

### 封存盲测集

要求：

1. 输入整理者看不到 `gold`。
2. 输入与答案由不同的人整理。
3. `input` 先冻结并生成哈希。
4. 模型预测结果也先冻结。
5. 之后才能揭晓 `gold`。
6. 同一人物、同一作品或同一事件只能出现在一个数据分组中。

即时情绪允许看前三位，稳定情绪允许看前两位；同时报告第一位命中率、覆盖率和额外错误情绪，不能只报“答案曾经出现在长列表里”。

## 4. ISEAR 的正确用途

本地已整理 7,343 条 ISEAR 第一人称材料，并按人物隔离为：

- 训练发现材料：5,068 条；
- 开发材料：1,228 条；
- 封存材料：1,047 条。

这些原始叙述不能直接送给本模型。正确流程是：

1. 独立整理者只读事件事实，且看不到自报情绪。
2. 整理者使用固定结构记录目标、风险、选项、结果、责任、社会关系和信息缺口。
3. 冻结结构化输入。
4. 事件影响程序只读取结构化事实。
5. 预测冻结后再读取自报情绪。

ISEAR 是在指定情绪提示下回忆事件，存在提示偏差；即使严格处理，也不能作为唯一验证来源。其事后问卷可以用于诊断中间变量，但不能反过来伪装成事件发生前已经知道的输入。

若叙述明确写着“想不起事件”“不适用于我”，且自报强度为 0，则它没有任何可供事件生成模型推断的输入。封存轮次若预先约定保留，仍必须计入该轮主分母；同时应单列“有可观察事件”的有效成绩。后续正式数据集应在冻结前把它标成 `no_observable_event`，不能把隐藏的问卷题目类别当成模型应该猜中的答案。

## 5. 文学、影视、纪实和新闻

- 文学和影视中的作者明确描写，与真人第一人称自报分开统计。
- 新闻转述、当事人直接引语、同时期行为证据分开标明。
- 同一人物或同一作品的多个片段不能跨训练和测试。
- 仅有研究者解释、没有来源直接证据的情绪，不能作为高等级答案。
- 已经被开发者读过的作品全部进入发现集，永远不能重新包装成盲测。

## 6. 当前状态

- 事件输入、内容哈希、答案隔离和封存时序已有程序校验。
- 已建立 9 个真实来源发现案例，覆盖文学、NASA 第一人称访谈和纪实材料。
- 这些案例已经用于发现并修正“异常=奖励落空”“危险解除=普通兴奋”“慢性压力按事件重复累加”等错误。
- 已完成三轮逐次封存验证：每轮按人物来源组隔离，先冻结结构化输入、模型源码哈希和预测，再揭开该轮答案；共 76 条严格叙述，其中 68 条有可观察事件。
- 三轮使用了逐步修正的不同模型版本，因此只能分别报告或作为“顺序预测成绩”，不能合并冒充一个固定版本的大盲测。
- 同一开发者兼任了答案不可见的事件整理者，尚未达到独立双人盲标标准；剩余 946 条封存输入仍未用于模型开发。
- 正式玩家 Agent 尚未接入或修改。
