# 多维感知找解闭环 V0

这个隔离实验回答两个分开的疑问：

1. 玩家产生“要活下来”等模糊需求后，768维语义空间能否从有限可用队伍中快速召回更可能解决问题的候选？
2. R与EVerify把新经验写入价值地形后，下一次选择是否比不学习更好？

它不修改正式玩家Agent，也不计算Decision或情绪。

## 最小闭环

```text
真实战斗失败
→ 只用可见生命、存活人数和时长形成四类低精度需求之一
→ 在16支当前可用队伍中按语义相似召回8支
→ 需求匹配与当前价值共同激活3支
→ 旧MindToy multi_ranking只比较这3支
→ 真实战斗
→ 普通感知筛选结构化因果证据
→ 旧causal-chain matcher产生EVerify
→ R更新具体队伍；确认或有效证伪才更新概念方向
→ 同一敌人后续案例继续使用该玩家记忆
```

玩家可用的16支队伍由固定种子从50队中选择，不读取隐藏胜率。这样避免每次都能直接使用数据集中存在的万能强队。

## 空间中的两种传播

- R是完整队伍结果，只在该队伍坐标的近邻形成局部锚点。
- EVerify确认的概念不是一个要求队伍贴近的点，而是一个切分方向。概念对50队的余弦相似度先转成相对激活：30百分位以下为0、90百分位以上为1，中间连续变化，再把价值传播给高激活队伍。

后者是本轮的重要修正。原本直接对“概念向量—队伍向量”使用小半径距离核，在真实768维空间中几乎没有影响。

## 不确定性

本轮把两类不确定性分开保存：

- `epistemicConfidence`：附近证据质量是否足够，随证据质量增加而上升。
- `outcomeVariance`：结果本身是否波动。

因此稳定五五开可以具有高认知信心和高结果波动，不再把随机性误当成“玩家什么都不知道”。

## 验证边界

- 50队坐标来自排除胜负命题的能力知识快照。
- 历史价值只读取原六支敌队的玩家可见结果。
- 测试敌队为 `ironWall`、`purgeAttrition`、`frostTrapField`、`cavalryBreak`、`martyrFrontline`，不在原六敌队中。
- 隐藏判卷为50队×5敌队×12种子，共3000场；选择程序不读取这些胜率。
- 但第一轮看到隐藏结果暴露“万能队总可用”后，测试协议改成每局16支可用队伍。因此最终结果是开发验证，不再算严格封存盲测。
- 需求形成只有4个程序规则，其中93/124案例都是生存需求，不能代表完整自然语言思考。
- MindToy结构由代码固定为最低充分的多价值排行榜，不是本轮AI生成；本轮只验证有限比较和证据边界。

## 运行

使用 `run-local.ps1`：离线生成GTE输入、3000场隐藏真值、124个失败案例的7种方法对照，然后执行结构断言。
