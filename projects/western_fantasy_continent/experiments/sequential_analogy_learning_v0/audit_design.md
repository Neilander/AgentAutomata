# 1 万条顺序学习实验：冻结与反作弊审计设计

## 1. 这次实验究竟要证明什么

要证明的不是“一个分类器能拟合生成器标签”，也不是“语言模型本来就知道玻璃撞墙会碎”。要证明的是：

> Agent 每次只读新增的 100 条完整经历并留下自己的记忆；之后面对从未见过的新主体、新措辞或新领域，只根据已经读过的经历，对后续结果作出越来越可靠的预测。

正式学习上限为 5000 条，即 50 个 checkpoint。每个 checkpoint 新增学习 100 条，再在从未用于学习、也永不回流学习的 100 条上评测。只有连续多个 checkpoint 达到 80%，才叫“稳定 80%”。

矩阵检索、向量编码和槽位重绑定可以帮助 Agent，但它们只能是记忆工具。只要结果是由 Python 根据隐藏因果标签直接查表或推导出来，就不算 Agent 学会了。

## 2. 10,000 条数据的冻结结构

### 2.1 固定分配

- `learn_stream`：5000 条，预先打乱并冻结为 `L001...L050`，每块 100 条。
- `eval_stream`：5000 条，预先打乱并冻结为 `E001...E050`，每块 100 条。
- 第 `n` 轮只能让学习者看到 `L001...L00n`；只在 `E00n` 上评测。
- `E` 中的任何输入、标准答案、错误分析和判分反馈，永远不能进入后续学习记忆。
- 不从“所有未读样本”临时随机抽测试，因为这样前一轮测试样本以后可能成为训练样本，造成隐性回流。

可额外做 0 条记忆基线，但它不能占用或重复正式的 50 个评测块；最好另生成一个只作诊断的 shadow 集，且不计入正式 10,000 条。

### 2.2 一条轨迹的要求

每条应包含：

- 1–3 个真正参与因果关系的主体；背景里偶然提到的名词不计主体。
- 1–2 次相互影响；两次影响必须有明确先后或组合关系，不能只是把两句无关事件拼起来。
- 1–2 个结果状态变化。
- 原始自然语言输入。
- 供训练时阅读的完整结果。
- 仅供审计器使用的隐藏结构标签：主体槽位、交互图、因果族、结果状态差分、难度切片、生成模板族。

正式预测输入必须在结果发生之前截断，只给“主体、当前状态和已选择/正在发生的相互影响”，不能出现结果或结果的同义改写。

### 2.3 先分组、再冻结，不能随机按行切分

如果先生成“玻璃剑撞钢墙”“冰剑撞铁墙”等姐妹样本，再随机按行分训练/测试，测试只是看过模板后的换名复读。必须按生成家族分组：

- `causal_family`：真正的因果规律，例如“脆弱施力者撞坚硬目标，施力者损坏”。
- `surface_template_family`：句法与叙述骨架。
- `entity_lexicon_family`：主体名称和属性词集合。
- `interaction_topology`：1/2/3 主体怎样连接、两段动作怎样衔接。

训练和测试可以共享需要迁移的 `causal_family`，否则无法从旧经历类推；但不能共享相同的 `surface_template_family + entity_lexicon_family`。正式集还应含跨领域、角色互换、近似反例和上下文覆盖，防止只靠名词相似。

### 2.4 建议的每个 100 条评测块组成

每块都保持相近难度，避免某轮恰好简单导致“稳定 80%”假象：

- 30 条：同因果、换主体和换措辞。
- 20 条：同因果、换领域。
- 15 条：主体角色互换或作用方向相反。
- 15 条：两次交互的组合/链式结果。
- 10 条：高表面相似但结果不同的困难反例。
- 10 条：当前记忆没有充分相似规律，正确行为应为“不确定”。

1/2/3 主体与 1/2 次交互也要在每块内近似平衡。未知规律不应要求 Agent 凭空猜中结果；它们单独考察正确拒绝。

## 3. 生成器反作弊

### 3.1 生成过程必须留档

冻结以下信息：模型名、系统提示词、生成提示词、温度、随机种子、每批原始返回、后处理脚本版本、最终数据哈希。10,000 条必须在学习开始前全部完成和冻结，不能看学习曲线后补简单题。

### 3.2 不能把生成器标签送进学习者

以下字段只放在独立的 `secret` 文件，由评测进程读取，训练/预测进程无权读取：

- `causal_family_id`
- `template_family_id`
- `difficulty_slice`
- `gold_result`
- `is_answerable_from_memory`
- 任何“正确来源经历 ID”

尤其禁止在文本里出现“未知规则”“困难反例”“属于破碎类”“答案是……”等提示。上一版实验已经出现过一次“未知规则”字样泄漏，这次要用自动扫描阻断。

### 3.3 模板重复审计

冻结前至少做四道检查：

1. 去掉主体名和数字后的规范化文本完全重复率必须为 0。
2. 训练—测试间相同模板族交叉数必须为 0。
3. 对所有输入做 n-gram/编辑距离近重复检测；高度相似对进入人工或独立 Agent 复审。
4. 用 embedding 查训练—测试最近邻；相似度异常高的样本必须确认是合理的困难反例，而不是同模板换名。

不能只靠 embedding 去重，因为 embedding 对同义改写本来就会相似；它只是报警器。

### 3.4 防止自然常识掩盖学习

如果全是“玻璃撞钢墙”，模型不读任何记忆也能猜中。正式集应同时包含两轨：

- `semantic`：现实语义合理的跨对象/跨领域类推。
- `novel_convention`：虚构材料、虚构装置或与常识不同但内部一致的规律，只有读过经历才可能预测。

两轨必须分别报告。零记忆、打乱记忆、错误记忆三个对照若与正式记忆表现接近，就说明成绩主要来自预训练常识，不是顺序学习。

## 4. “AI 读 100 条并记录”必须怎样实现

### 4.1 主实验必须有真实 Agent 阅读环节

每轮逻辑上读 100 条；受上下文限制可拆为 5×20 或 10×10 次模型调用，但在本轮评测前必须全部完成，在评测后不能再修改这 100 条的记录。

Agent 应从原始完整经历生成自己的记录，例如：

- 临时主体槽位及其关系。
- 结果发生前的条件与变化趋势。
- 观察到的结果状态差分。
- 不确定点。

程序可以校验 JSON 格式、建立向量和矩阵、保存记忆，但不得根据隐藏标签替 Agent 生成记录。若采用规则程序直接把原始样本解析成标准槽位，该结果只能算“理想解析器上限”，不能作为用户要求的主实验。

### 4.2 预测也必须由 Agent 作出

正式预测流程应是：

1. Agent/其前置解析器读取没有结果的测试输入。
2. 记忆系统只用“原因侧”信息生成 query，矩阵取回相似旧经历。
3. Agent看到有限条取回记忆，输出结构化结果或“不确定”。
4. 独立评测器读取 secret 标准答案判分。

矩阵 Top-1 是哪条记忆可以作为诊断，但不能直接把该记忆的隐藏标签当答案输出。应保存 Agent 实际看到的内容，才能判断它是否真的使用了经验。

### 4.3 最危险的 embedding 泄漏

训练记忆必须严格拆成：

- `key_embedding`：只编码结果发生前的条件、主体角色和相互影响。
- `value_memory`：Agent 读到的结果记录，只有检索后才作为经验显示。

绝不能把完整的“原因 + 标准结果”编码成检索 key；也不能把结果词放进测试 query。否则相似度可能直接按答案聚类，得到虚假的高分。

### 4.4 完整句子不是学习证据

如果系统输出“冰晶钻头在反作用力下断裂，钛合金墙保持完整”这种顺滑句子，可能只是模板渲染。主指标只看规范化状态变化，例如：

```json
[
  {"entity": "actor", "attribute": "integrity", "change": "major_decrease"},
  {"entity": "target", "attribute": "integrity", "change": "unchanged"}
]
```

自然语言句子只能作为展示层，不参与主分数，也不能据此宣称 Agent 理解了结果。

## 5. 指标和“稳定 80%”的预注册定义

### 5.1 主指标

`decision_accuracy`：

- 对可由已读记忆推断的样本，只有完整预测对所有结果状态差分才算 1 分；主体、方向、结果类型任一错均为 0。
- 对尚无充分经验的样本，只有输出“不确定”才算 1 分。
- 100 条取平均。不能用同一模型做宽松自然语言裁判。

同时必须报告：

- `answerable_exact_accuracy`：可回答样本的严格结果准确率。
- `unknown_rejection_accuracy`：未知规律的正确拒绝率。
- `coverage`：Agent 实际给出结果而非弃权的比例。
- `wrong_confident_rate`：高置信但错误的比例。
- 按 1/2/3 主体、1/2 交互、跨领域、角色互换、链式、困难反例分别切片。
- 多数类基线、零记忆基线、打乱记忆基线。

必须同时给每轮 100 题的二项分布置信区间；单轮 80/100 的波动仍很大。

### 5.2 稳定停止条件

在第一次正式运行前冻结为：

> 最近连续 5 个 checkpoint 的 `decision_accuracy` 均不低于 0.80，且这 500 条合并准确率不低于 0.80；同时 `answerable_exact_accuracy` 不低于 0.80、`unknown_rejection_accuracy` 不低于 0.70、任何核心难度切片不低于 0.65。

最早在读完 500 条后停止。第一次达到单轮 80%不能停；80%、79%、84%也不能叫稳定。若到 5000 条仍不满足，就报告完整曲线和失败原因，不能放宽口径。

建议另外报告最近 5 轮的最高—最低差和线性斜率，但不把“看起来平了”作为主观停止条件。

## 6. 每轮不可违反的隔离顺序

1. 加载冻结配置与文件哈希，校验未变。
2. 只把本轮 `Lnnn` 的 100 条完整经历交给阅读 Agent。
3. 保存 Agent 原始输出、结构化记忆和对应训练 ID。
4. 锁定本轮记忆快照。
5. 只把 `Ennn` 的无结果输入交给预测 Agent。
6. 预测全部完成后，独立评测器才读取 `Ennn` 的 secret 答案。
7. 保存逐题 query、检索候选、Agent 可见证据、预测、金标准和分数。
8. 只把汇总分数交给外层停止器；学习 Agent 不得看到逐题答案或错误分析。
9. 未满足预注册停止条件则进入下一轮，但 `Ennn` 永不进入学习流。

如果人在中途看了测试失败并修改 prompt、相似度阈值、槽位规则或数据，整次正式运行立即失效。调试只能在独立 dev 集完成；修改后需要重新冻结配置并用未曝光的正式集运行。

## 7. 必须自动执行的审计断言

- 10,000 个 ID 唯一。
- 学习 ID、评测 ID 完全不相交。
- 任何已评测 ID 永不出现在后续学习快照。
- 训练/测试模板族无交叉；实体词族按预注册规则隔离。
- 预测输入不含 gold result 及其直接同义短语。
- `key_embedding` 的源字段白名单不含结果字段。
- 预测进程不能读取 secret 文件路径。
- 每轮学习记忆数只增加 100，不多也不少；不得跨轮预读。
- 每轮恰好评测新的 100 条，50 轮内不重复。
- 数据、配置、prompt、代码哈希和每轮记忆快照完整可复现。
- 生成结果类别不过度失衡；必须报告多数类猜测准确率和 macro-F1。

## 8. 结果如何解释，避免自娱自乐

可以宣称“顺序经历学习有效”，至少要同时看到：

- 正式记忆明显优于零记忆与打乱记忆。
- `novel_convention` 随读入条数上升，而不是从第 100 条开始就异常高。
- 跨主体、跨措辞和跨领域切片均提升，不只是同模板样本。
- 角色互换与困难反例没有被表面相似系统性误导。
- 记忆覆盖增加能解释提升：同类经历出现次数增加时准确率上升，但不是 Python 读取隐藏 family ID 后直接命中。
- Agent 的最终预测能追溯到它实际读过并检索出的经历。

以下结果只能算诊断，不能算主实验成功：

- 程序用生成器的 `causal_family_id` 查表输出答案。
- 人工标准化好 10,000 条后只测矩阵最近邻。
- 训练 key 包含结果语句。
- 测试错误在后续轮次变成训练数据。
- 只报告总体分，不报告未知、困难反例和链式交互。
- 生成器反复复制少量句式，训练测试只是换主体名。
