# 顺序类比学习：1 万条冻结数据集设计

## 1. 这套数据到底要验证什么

目标不是验证程序能否记住某个标签，也不是让模型从题干里猜一个固定类别，而是验证下面这条学习链：

1. Agent 读到一批带结果的自然语言经历；
2. Agent 自己把经历整理成可检索的临时角色与状态变化记忆；
3. 面对没见过的新对象、新措辞或新领域，系统只靠已读经历找结构相似项；
4. 把旧经历的结果重新绑定到新对象，并预测新结果；
5. 随着已读经历从 100 增至 5000，预测曲线应当逐渐上升，而不是第一轮就靠题目泄漏达到高分。

因此，数据生成器可以知道答案，但学习器绝不能看到 `family_id`、隐藏规则、人工角色槽位、变换类型或评测答案。

## 2. 每条数据的公开结构

每条经历包含：

- 1～3 个主体；
- 1～2 次相互影响；
- 初始状态；
- 发生的相互影响；
- 最终结果（训练经历公开，评测题隐藏）；
- 可选的环境条件，但不能直接写出规律名称。

示例公开训练经历：

```json
{
  "id": "opaque-8f2a",
  "before": "冰晶钻头正在高速旋转，前方是没有裂纹的钛合金舱壁。",
  "interaction": "冰晶钻头正面顶上舱壁，并继续加压。",
  "result": "冰晶钻头从尖端崩裂，舱壁仍保持完整。"
}
```

示例公开评测题：

```json
{
  "id": "opaque-e31c",
  "before": "玻璃切割轮高速旋转，前方是完整的钢制闸门。",
  "interaction": "切割轮正面撞上闸门，并继续施力。"
}
```

学习器必须输出结构化结果，便于不用另一个 LLM 主观打分：

```json
{
  "effects": [
    {"subject": "玻璃切割轮", "change": "破裂"},
    {"subject": "钢制闸门", "change": "保持完整"}
  ],
  "confidence": 0.84
}
```

中文完整句可以同时保留作展示，但计分只比较隐藏标准答案里的“目标主体＋状态变化”，允许事先冻结的同义谓词，如“破裂/崩裂”。

## 3. 隐藏评测结构

每条公开记录旁边有一条只供生成审计与评分使用的隐藏记录：

```json
{
  "opaque_id": "opaque-e31c",
  "family_id": "F037",
  "variant_id": "F037-V82",
  "roles": {
    "actor": "玻璃切割轮",
    "target": "钢制闸门"
  },
  "gold_effects": [
    {"role": "actor", "predicate": "break"},
    {"role": "target", "predicate": "remain_intact"}
  ],
  "transformations": ["cross_domain", "paraphrase", "new_entities"],
  "negative_pair": null,
  "split": "eval",
  "seen_family": true
}
```

隐藏文件绝不能进入：

- Agent 的批次阅读上下文；
- 向量编码文本；
- 检索索引；
- 预测提示；
- 置信度计算。

`id` 必须是随机不透明 ID，不能包含家族序号或 train/eval 字样。

## 4. 不是“换名词”的 120 个因果家族

由 Agent 先创作 120 张“因果家族卡”，而不是程序员手写结果表。每张卡只在生成侧保存，至少包含：

- 不变的因果骨架；
- 1～3 个角色及其关系；
- 触发结果所需的关键条件；
- 一个只改关键条件就会翻转结果的近似反例；
- 可以跨越的至少 3 个领域；
- 角色互换后会怎样；
- 两次相互影响如何串联或竞争；
- 允许的结果谓词及同义表达；
- 哪些变化不能安全类推。

推荐领域池：物理碰撞、通路与阻挡、容器与泄漏、能源与阈值、信息与控制、权限与锁定、资源竞争、治疗与保护、环境传播、队伍协作。避免只生成“各种炸弹碰撞后爆炸”。

### 4.1 必须覆盖的变化类型

同一家族的训练与评测实例之间，至少同时改变下列两项，不能只换名词：

1. **跨领域类比**：例如“脆工具撞硬障碍”从工坊迁移到太空维修；
2. **角色互换**：脆弱的是工具还是目标，结果主体随角色变化；
3. **近似反例**：表面词汇极像，但关键条件缺失或相反；
4. **组合因果**：第一次作用改变条件，第二次作用才产生结果；
5. **措辞与叙述顺序变化**：先说目标、先说结果风险、使用代词等；
6. **主体数变化**：同一规律从两主体扩为第三个中介或受影响者；
7. **交互次数变化**：一次直接作用与两步传递/竞争；
8. **失效、免疫或阈值边界**：同类机制在临界条件两侧得出不同结果。

### 4.2 近似反例必须成对生成

每个共享家族至少有一组最小差异对：两条题目大部分文字相似，只改变一个决定性事实，结果随之改变。例如：

- “吸入腐蚀气体”与“隔窗观察腐蚀气体”；
- “越过压力阈值”与“接近但未越过阈值”；
- “钥匙插入匹配锁孔”与“钥匙贴近锁孔但未插入”。

这样可以防止模型只靠名词共现或主题相似做题。

## 5. 精确的 10000 条冻结划分

总计 120 个因果家族：

| 家族用途 | 数量 | 每家族训练 | 每家族评测 | 总训练 | 总评测 |
|---|---:|---:|---:|---:|---:|
| 共享家族 | 100 | 45 | 45 | 4500 | 4500 |
| 仅训练家族 | 10 | 50 | 0 | 500 | 0 |
| 完全未知家族 | 10 | 0 | 50 | 0 | 500 |
| 合计 | 120 | - | - | 5000 | 5000 |

作用：

- 4500 条共享家族用于观察“见过少量经验后能否跨实例类推”；
- 500 条仅训练家族防止训练集完全围绕评测家族量身定制；
- 500 条未知家族检验模型会不会把所有陌生事件强行套进旧经验；这部分正确行为应当是低置信或拒绝，而不是瞎猜。

### 5.1 50 个顺序批次

训练与评测各切成 50 个冻结批次，每批 100 条：

- 每个训练批次：90 条共享家族＋10 条仅训练家族；
- 每个评测批次：90 条共享家族＋10 条完全未知家族；
- 共享家族用轮转表均匀分布，不能让某几个家族连续扎堆；
- 每轮先读 `train_batch_N`，再只测试 `eval_batch_N`；
- 评测题及答案永不回流到记忆；
- 第 N 轮结束后，累计记忆恰好为 `100 × N` 条。

这种划分在第 50 轮刚好用完全部 5000 条训练和 5000 条评测，不重复抽样，也不会因为测试过同一道题而虚高。

## 6. Agent 真正负责什么，程序只负责什么

### 6.1 Agent 生成侧

为了避免“程序提前知道答案”，生成分两层，均由 Agent 完成：

1. **家族作者 Agent**：创作 120 张因果家族卡；
2. **实例作者 Agent**：按卡片批量创作自然语言事件与结果，并主动制造跨领域、角色互换、近似反例和组合因果。

建议每次生成 25～50 条，而不是一次要求 10000 条。每批采用不同随机种子、领域配额和表述约束，最后合并。生成时 Agent 同时产出公开记录和隐藏标注，但二者立即写入不同文件。

### 6.2 程序生成侧

程序不得创造结果，也不得根据家族 ID 推导答案。程序只做：

- JSON schema 校验；
- 主体数、交互数、结果字段完整性检查；
- 重复与近重复检测；
- 领域、家族、变化类型配额检查；
- 按预先冻结的种子分配 train/eval 与批次；
- 将公开与隐藏文件物理分离；
- 计算 SHA-256 哈希并冻结清单。

若为了节省成本由程序对 Agent 模板做名词替换，那只能算烟雾测试，不能作为本实验的正式 10000 条结果。

## 7. 防止生成阶段本身泄漏

1. **先生成家族完整实例池，再划分**：实例作者不知道某条最后属于训练还是评测，避免专门把简单题给评测集。
2. **实体与表述隔离**：同一共享家族的 train/eval 使用不相交的实体词表、领域组合和句式模板。
3. **家族标签不进公开文件**：公开训练经历甚至不显示“这是同一种规律”。
4. **近似反例跨 split 分布**：不能让所有正例在 train、所有反例在 eval。
5. **未知家族不与共享家族同义改写**：独立审计 Agent 检查语义重合。
6. **冻结后再写学习器**：至少先冻结 eval 文件与哈希，再进行任何阈值和检索参数调整。
7. **最终批次不用于调参**：若需开发，另生成不计入 10000 条的 pilot/dev 数据。

## 8. 建议的数据分布

主体数：

- 1 个主体：20%（自变、环境作用、阈值变化）；
- 2 个主体：55%（直接作用、阻挡、传递）；
- 3 个主体：25%（中介、旁观受影响者、角色接力）。

相互影响数：

- 1 次：65%；
- 2 次：35%。

两次相互影响内部再分：

- 串联因果 45%；
- 两种作用竞争 30%；
- 第三主体中介/转移 25%。

困难项最低配额：

- 近似反例 ≥20%；
- 跨领域迁移 ≥25%；
- 角色互换 ≥15%；
- 组合因果 ≥20%；
- 阈值或失效边界 ≥10%。

一条记录可以同时属于多个困难类型。

## 9. 与顺序学习器的接口

每轮的正确执行顺序必须固定：

1. Agent 读取 100 条公开训练经历（含结果）；
2. Agent 输出自己的匿名角色、状态变化和结果槽位记忆；
3. 只把这些 Agent 生成的记忆加入矩阵，不加入隐藏标注；
4. 从本轮冻结评测批次读取 100 个无结果题目；
5. 连续空间检索若干已读记忆，Agent 基于取回记忆输出目标主体的预测；
6. 独立评分器读取隐藏答案计分；
7. 评测题、预测和正确答案均不写回学习记忆。

“AI 读 100 条”的含义不能偷换成程序把 100 条金标准槽位直接塞进矩阵。Agent 的整理错误也应保留，因为这正是实验需要测量的解析损失。

## 10. 指标与停止条件

主指标：

- 已知家族的主体＋结果谓词完全正确率；
- 全体题目的正确决策率，其中未知家族只有正确拒绝才算对。

辅助指标：

- 1/2/3 主体准确率；
- 1/2 次相互影响准确率；
- 跨领域、角色互换、近似反例、组合因果准确率；
- 已知规律误拒绝率；
- 未知规律强行类推率；
- Agent 角色/状态解析准确率；
- Top1/Top2 检索差距与置信度校准。

建议把“稳定 80%”定义为连续 3 个互不重复的 100 题批次都 ≥80%，且三批合计也 ≥80%。单个 100 题批次达到 80% 不算稳定。若一直未满足，则跑满 5000 条学习经历。

必须同时报告：

- 当前轮 100 题准确率；
- 最近三轮滑动准确率；
- 从第 1 轮到当前轮的累计曲线；
- 已知家族与未知家族拆分成绩。

否则，10% 的未知题可能掩盖已知规律学习，也可能被错误地当作普通预测失败。

## 11. 数据集验收门槛

在启动长跑前，先审计 300 条随机样本：

- 主体和代词指代无歧义；
- 结果能由隐藏规律推出，而不是依赖未写出的常识；
- 题干没有“因此会爆炸”一类答案泄漏；
- 近似反例确实只改了决定性条件；
- train/eval 没有近重复句；
- 至少一半实例不能靠单个实体名或结果高频词猜中；
- 隐藏角色映射与公开自然语言一致。

若这 300 条不能通过，不能用学习曲线调模型；应先修生成提示并重新冻结整套数据。

## 12. 这个设计能回答与不能回答的问题

能回答：

- 多读经历是否真的改善跨对象、跨措辞、跨领域的结果预测；
- 角色重绑定和组合因果在主体增多后是否仍然可靠；
- 模糊检索是否会被高表面相似的反例骗过；
- 面对完全陌生规律时，模型是否知道自己不知道。

不能回答：

- Agent 能否凭空发现从未见过的新物理规律；
- 正式 UFS 的完整长期规划是否已经成立；
- 长期记忆遗忘、注意力预算和情绪是否正确。

它是“硬经历记忆＋模糊类比＋角色重绑定”从几十题扩大到 1 万条后的顺序学习实验，不应被包装成完整玩家模拟。
