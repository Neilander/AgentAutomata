# 顺序类比学习器：AI每次读100条，再预测新的100条

## 结论先说

最小真实实现不是训练一个“炸弹类别分类器”，也不是让程序读取生成器藏着的因果编号。它是三层：

1. AI把已经发生完的100条经历整理成临时角色轨迹；
2. GTE把这些轨迹追加进记忆矩阵；
3. 面对没有结果的新场景，矩阵找相似旧经历，再把旧结果中的角色槽位换成当前角色。

学习只等于“多记了100条真实经历”。没有梯度训练，也没有人工写`如果是炸弹就爆炸`。

`episodic_learner.py`已经封装第2、3层；第1层必须由AI按下述固定契约完成，不能由数据生成器直接把标准答案复制给它。

## 一条记录是什么

AI读到的训练原文包含：之前状态、1—2次相互影响、当前可见状态、最终结果。AI输出：

```json
{
  "id": "train-000001",
  "slots": [
    {"slot": "p0", "description": "正在移动的轻型物体"},
    {"slot": "p1", "description": "仍然启用的爆炸装置"},
    {"slot": "p2", "description": "位于爆炸范围内的脆弱物体"}
  ],
  "bindings": {"p0": "侦察机", "p1": "黄炸弹", "p2": "玻璃塔"},
  "beforeNorm": "<p0>在<p1>上方，<p2>靠近<p1>",
  "interactions": [
    {"subject": "p0", "change": "向下移动并直接接触", "object": "p1"},
    {"subject": "p1", "change": "释放冲击并波及", "object": "p2"}
  ],
  "currentNorm": "<p0>已与<p1>接触；冲击正到达<p2>",
  "resultTemplate": "{p1}爆炸，{p0}和{p2}受到冲击",
  "effects": [
    {"slot": "p1", "property": "完整性", "operation": "变为", "value": "已爆炸"},
    {"slot": "p0", "property": "受击状态", "operation": "变为", "value": "受爆炸冲击"},
    {"slot": "p2", "property": "受击状态", "operation": "变为", "value": "受爆炸冲击"}
  ]
}
```

这里没有`detonate_family`之类的隐藏类别。`effects`只是AI看到结果后记下的状态变化，相当于“黄炸弹从完整变成爆炸”。

测试查询使用同一结构，但**绝不含**`resultTemplate`和`effects`。代码会主动拒绝误带答案的查询。

## AI怎样生成临时角色槽位

固定规则只有角色编号规则，不含因果规则：

- `p0`：第一次相互影响的发起者；
- `p1`：第一次相互影响的承受者；
- `p2`：第二次相互影响中新出现的主体或承受者；
- 同一物体在两步里必须保持同一编号；
- `description`只写预测前可观察到的性质，不能把最终结果倒填进去；
- 一主体的自变化允许`object=null`；
- 两个同时发生的影响也按原文出现顺序记录，不能偷偷按结果重排。

因此三主体链`A碰B，B再影响C`会自然成为`p0→p1→p2`。两主体双互动`A推B，B撞A`则是`p0→p1`和`p1→p0`。角色重绑定不需要知道角色名字，只依赖这个局部连续关系。

AI应该有两个隔离调用：

- **记录调用**：能看训练经历的最终结果，生成完整记录；
- **查询调用**：只能看预测点之前的公开状态，生成无结果查询。

提示词和输出JSON Schema在冻结10,000条数据之前锁定；每100条开一个新上下文，避免前一批测试题停留在上下文里。

## 记忆矩阵如何工作

每条经历保存三个向量：

- 一条“完整的角色归一化前后变化”向量；
- 第一互动向量；
- 可选的第二互动向量。

面对一个查询，先做一次`记忆矩阵 × 查询向量`，得到所有旧经历的全局相似度；再用两列互动矩阵比较第一步对第一步、第二步对第二步。默认总分为：

`0.72 × 全局相似 + 0.28 × 有序互动相似 - 互动数量不一致惩罚`

这几个权重必须在正式学习曲线前冻结。它们只决定“像不像”，不包含任何“碰炸弹会爆炸”的规则。

取相似度最高的9条经历。它们各自携带看过的状态变化；相同状态变化获得相似度加权投票。赢家的结果槽位再绑定到当前`p0/p1/p2`，得到目标场景结果。多条相似经历会互相佐证，单个偶然案例不会永远支配预测。

## 10,000条顺序实验

### 冻结数据

- 总计10,000条，生成完以后整体哈希；
- `learning_pool`固定5,000条，按冻结顺序每轮公开100条结果；
- `evaluation_pool`固定5,000条，每轮使用下一段从未测过的100条；
- 训练与评测不共享具体主体名字、表述模板或同一事件实例；
- 生成器内部的规律编号只存在于封闭评分文件，绝不能写入AI输入、归一化文本或记忆矩阵。

“从剩下的抽100条”不能真的在运行中随手抽，否则每次重跑会改变难度。正确做法是先用一个种子把5,000条评测顺序洗好，然后逐段揭开；在统计意义上仍是随机抽样，同时可复现。

### 每一轮

1. 只把新100条学习经历（含结果）交给记录AI；
2. `observe()`追加100行向量和状态变化，旧记忆保留；
3. 把本轮新的100条评测经历（不含结果）交给查询AI；
4. `predict()`只读记忆矩阵，不修改记忆；
5. 封闭评分器比较“目标角色 + property + operation + value”，而不是比较句子字面；
6. 记录总正确率、单互动/双互动、1/2/3主体、跨领域换皮、近邻反例等分桶结果。

第1轮记忆100条，第2轮200条，依此类推。到5,000条最多50轮。

### 正确率与停止

- 每题必须给出结构化结果；无法预测或拒答在主正确率里算错，防止靠大量拒答刷到80%；
- 单轮100题的波动很大，“稳定80%”定义为**连续3轮都不低于80%**；
- 同时报告最近3轮合计300题的正确率和Wilson 95%区间；
- 满足稳定条件就停，否则一定跑到5,000条；
- 达标后不允许改权重再重跑同一评测池。若发现代码bug，整次实验作废、换新种子和新哈希重建。

## 防止实验变成自导自演

必须执行以下检查：

1. **答案隔离**：查询JSON出现`effects`或`resultTemplate`时，学习器直接报错。
2. **标签隔离**：检索输入里不存在生成器的规律名、家庭编号或难度标签。
3. **实体隔离**：训练与评测用不同名字；只改名字仍能做对，才算角色重绑定。
4. **措辞隔离**：训练和评测使用不同表达模板，防止背句子。
5. **反例对照**：接触/未接触、启用/失效、越线/未越线、坚硬主体/脆弱主体必须成对出现。
6. **双互动对照**：第二步缺失、顺序颠倒或改换承受者时，答案必须可能改变。
7. **无家族标签消融**：最终结果只能由源经历的状态变化迁移；程序中不得出现按规律编号分支。
8. **无增长基线**：固定只用首批100条重复测各轮。如果增长曲线和累计学习器一样，所谓“越读越会”就是假的。
9. **随机近邻基线**：同样做角色重绑定，但随机选旧经历，证明成绩不是模板评分过宽。
10. **Top1基线**：和9邻居投票对比，判断重复经历是否真的减少了单个错误经验的影响。

## 当前实现刻意没有做什么

- `episodic_learner.py`不调用大模型，它只接收AI整理后的JSON；实际运行器必须保存每批AI原始输出，才能证明“AI真的读了”。
- 它不从零发明完全没见过的因果规律。未见规律做错是合理失败；应额外报告“评测规律是否已在学习经历中出现”的封闭审计分桶，但这个标记只能给评分器看。
- 它假定AI能稳定生成`p0/p1/p2`。正式曲线应先抽200条人工审查槽位正确率；若低于95%，需要先修读入层，不能把解析错误误判成类比学习失败。
- 目前的结构化状态变化词表仍可能被AI写成同义词。运行器应在AI记录时要求使用数据里公开的属性名和值域；这叫状态接口，不是隐藏因果分类。

## 最小验收门槛

开始50轮之前先做一次200条读入审计：主体数、互动数、槽位连续性和结果状态变化四项都至少95%。随后才冻结10,000条，跑一次不可覆盖曲线。最终至少交付：数据哈希、每轮新增记忆数、每轮100题逐题预测、累计曲线、四种基线和失败近邻证据。
