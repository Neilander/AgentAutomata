# UFS 多注意种子三回合 V6：结果

## 结论

三个不同注意种子的唯一 attempt 都从各自全新 state 目录抵达公开
`complete / one_round_imagined_to_next_round_boundary / new_round` 边界。完成率为
`3/3 = 100%`。这里的“完成”只表示完整走完一回合，不表示获胜；三局公开 outcome 均为空。

本小样本中规划确实随当时注意内容发生变化：三局分别以能源、研究、战斗机为首个房间目标，
而不是复放同一动作序列。注意遗漏还直接造成了等待格位重新暴露或改选当前可见格位的行为。

## 策略差异

1. **Seed 2026082501：能源优先。** 初始同时看到能源房关系与对应格位，于是先用灰4建立
   能源组合。下一步 C5 从当前 `baseCells` 消失，策略没有凭记忆提交，而是先走可见 C3
   通道；C5 再次暴露后才用白5补房。后续借能源结算覆盖研究和战斗成本。
2. **Seed 2026082502：研究优先。** 开局研究格明确可见、能源两端没有同时暴露，因此先放
   灰4研究，再逐步搭能源。最后白6时战斗房格位未出现在当前 `baseCells`，于是放到当前
   可见的 C1 防空；这局没有沿用第一局“末骰进战斗”的安排。
3. **Seed 2026082503：威胁与战斗优先。** 初始 C1 战斗格和 C1 起点紫船同时可见，先用白5
   建战斗房，并在第一步后按公开边界重投全部剩余骰。随机得到高骰后再搭能源和研究，
   房间阶段先兑现当前可见且阈值足够的战斗关系，再推进研究。

这些差异同时受注意种子与真实外部随机结果影响，不能把差异全部归因于注意种子。

## 注意遗漏分析

- **格位短暂消失会改变动作顺序。** 第一局能源 C5、第三局研究 C2 都发生过当前步漏看；
  玩家只保留目标意图，不提交未在当前公开 `baseCells` 暴露的 cell，待之后重新看见再行动。
- **关键格持续缺席会改变用途。** 第二局最后白6虽然适合高值战斗，但 C1 战斗格当步未暴露，
  于是改选可见的防空格。这是三条最终放骰路线不同的直接来源之一。
- **裁剪视图不是完整世界模型。** 船只、房间与天空格在相邻步之间会出现或消失；记录中的
  推断明确使用“预想”“可能”，下一步只让新的公开响应确认或否定，没有用隐藏状态补洞。
- **没有因遗漏而出现 unknown。** 这三次唯一 attempt 都能继续到完整边界，但样本太小，
  不能据此推断其他种子也不会在关键关系缺失时停止。

## 证据完整性

- 41 次 CLI 调用（含三次 `start`）分别有 stdout、stderr、机器记录；38 个游戏行动与公开
  `actionCount` 合计一致。
- 每个行动都有前置决策小节；每个 `advance` 都有独立 JSON payload。
- `PUBLIC_STDOUT_SHA256.json` 对全部 41 份原始 stdout 记录字节数与 SHA-256，可检查“逐字保存”。
- 机器记录保存请求 seed、CLI argv、state 路径、开始/结束时间、退出码、原始字节数和解析后的
  公开响应。机器记录是公开 stdout 的封装，不读取或复制 state 内部文件。

## 局限

- 三局只是观察性小样本，不能建立统计显著性或泛化到所有注意种子。
- 注意随机性与白骰外部随机性共同改变后续视图和决策，当前设计没有做因果拆分。
- “无拒绝、全完成”不是胜率指标，也不是完整宿主正确性的 oracle 验证；本实验刻意没有读取
  隐藏宿主状态、正式引擎或 fixture 作对照。
- 终点摘要仍是终点时的裁剪公开视图；只把公开 tracks/status 当作停止与进度证据。
