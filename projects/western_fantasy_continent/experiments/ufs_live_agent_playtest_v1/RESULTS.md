# 结果

## 现场进程

本次唯一 Attempt 在第 3 个玩家动作后真实终止：

1. 灰4放入双格能源房左格；脑内紫机从第0行降到第4行爆炸4。
2. 灰3放入能源房右格；脑内完成房间，另一紫机降到第3行爆炸4。
3. 灰2选择普通隧道格；系统返回 `unknown: no_rule_for:placement_room_state`，没有把
   第三个骰子或飞船移动应用到脑内 observation，也没有后续操作口。

没有为凑完整一回合重试、回滚或改走已知路径。最终 observation 仍只有前两个放置，
能源2、伤害0、研究0、挖掘0、母舰-1。

## 规划是否真的改变选择

有，至少三处可从动作前的只追加日志核对：

- 第0步预想灰4走战斗机列会让同列紫机落到母舰下降格，而且不能形成能源循环，因此
  排除；日志准确写为“风险”，没有写成必输。
- 第1步预想若不补能源房右格，已放的灰4会因双格房未填满而确定零产出，因此优先补齐。
- 第2步排除灰2研究（首格成本3，确定无收益）和灰2战斗机（预想母舰下降、战斗收益窄），
  改选隧道；但该隧道后果最终暴露为未知，原先“安全”设想未被验证。

所以这份样本证明候选成本—限制—收益与一步预想能现场影响动作，也同时暴露：玩家能
提出合法候选，不代表认知后果链已覆盖该候选。

## 盲测与审计边界

这不是 OS 级盲测。回合封卷前玩家只读规定白名单，没有读旧判断卡、旧决策、fixture、
driver、trace、formal engine、oracle 或 session 的底层实现。机器 transcript、choice 文件和
思路 JSONL 都保留顺序证据。封卷后只做确定性 replay/合同检查；由于未完成回合，没有
运行会把不完整脑内状态误当成正式回合的 formal oracle。
