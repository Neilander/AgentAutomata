# UFS 多步轨迹唤醒：真实使用验收清单

这份清单用于之后的真实 UFS 试玩，不用于再造一组人工 case。

当前结论：

| 层级 | 状态 |
|---|---|
| 受控条件下的触发侧主导机制 | `PASS` |
| 真实学习所得多步轨迹 | `NOT OBSERVED` |
| 真实局面中的自然唤醒 | `NOT OBSERVED` |
| 真实个人记忆库中的召回准确性 | `NOT OBSERVED` |
| 唤醒后的筛选 | 后续独立验收 |
| 对规划和实局结果的改善 | 后续独立验收 |

因此，目前只能说“受控机制成立”，不能说“真实可用性已经验证”或“规划已经改善”。未来任何真实试玩若要声称多步轨迹唤醒可用，都必须留下下面的证据。

## 1. 样本必须是真的

- [ ] 轨迹来自正式 UFS 反馈学习流程，不是 fixture、手写注入或旧记录的推测回填。
- [ ] 轨迹含至少两个按真实顺序保存的 `operations[]`。
- [ ] 轨迹保留真实 `memoryId`、episode、prediction ticket 和证据来源。
- [ ] 轨迹已经编译进该玩家自己的个人 GTE，并记录档案 revision/fingerprint。
- [ ] 不把 revision 9 中缺少 `operations[]` 的历史轨迹冒充多步样本。
- [ ] fresh 对照玩家不能读取学习玩家的个人记忆或 GTE。

## 2. 场景必须是真的

- [ ] checkpoint 由正式 host/gameplay 自然产生，不手改状态 JSON 来制造命中。
- [ ] 使用正式规则、正式 operation contract 和正式随机流程。
- [ ] Agent 只看到当时 attention 实际提供的公开观察；不得读取隐藏状态来生成线索。
- [ ] 不向 Agent 提供目标 trajectory ID、memory ID 或“正确答案”。
- [ ] 不替 Agent 手写本次测量用的触发句。

## 3. 触发必须自然产生

- [ ] 由 Agent 根据当前观察、当前目标或正在设想的操作自然产生线索。
- [ ] 逐条记录真实触发来源：`q_before`、`q_after` 或 `operation`。
- [ ] 不要求三路同时出现，也不对三路求和、平均或设全通道闸门。
- [ ] 非触发侧不匹配时，不得因此删除触发侧已经唤醒的候选。
- [ ] 多条路线独立唤醒同一记忆时，保留全部来源，但分别记录各自证据。
- [ ] 如果实局中没有自然出现某条路线，记为 `NOT OBSERVED`，不能补造查询后记作通过。

## 4. 只按触发侧判断“是否正确唤醒”

### `q_after` 路线

- [ ] 回忆出的 Q 后确实包含 Agent 想要的结果方向或关系。
- [ ] 能源、伤害等代价和副作用完整随轨迹返回。
- [ ] Q 前或操作不同，不单独构成唤醒失败。

### `q_before` 路线

- [ ] 回忆出的 Q 前与 Agent 当前注意到的局面确实相关。
- [ ] 后续操作或结果不同，不单独构成唤醒失败。

### `operation` 路线

- [ ] 回忆出的操作序列在类型、数量和顺序上与 Agent 正在设想的方法相关。
- [ ] 线索没有指定的参数或最终结果允许不同。

## 5. 必须经受真实个人库竞争

- [ ] 查询完整个人记忆库，不只查询受控五条记录。
- [ ] 预先记录每路候选预算/Top-K，并记录目标记忆实际名次。
- [ ] 记录所有“触发侧符合”的候选，以及触发侧本身不符合的误唤醒。
- [ ] 检查无关记忆是否挤占有限候选预算；相关轨迹未进入预算即为该次唤醒失败。
- [ ] 在真实 attention seed、自然措辞和不同局面中重复观察；不以一次命中代替稳定性证据。

## 6. 唤醒输出必须完整且只读

- [ ] 返回完整 Q 前、按序 `operations[]`、Q 后，而不是只返回摘要分数。
- [ ] 保留 `memoryId`、来源证据、代价、副作用和 `triggeredBy`。
- [ ] 唤醒本身不自动提交动作，不改变玩家档案或当前游戏状态。

## 7. 对照与机器证据

- [ ] 在同一真实 checkpoint 上做个人记忆启用/禁用的只读对照。
- [ ] 如比较学习玩家和 fresh 玩家，两者使用相同公开观察、attention seed 和可重放随机带。
- [ ] 保存原始机器日志：档案 revision/fingerprint、checkpoint 标识、线索原文及来源、候选列表和名次、`memoryId`、`triggeredBy`、GTE/overlay 版本、交给规划器的完整轨迹。
- [ ] 结论可以由日志重放或复核，不能只留下人工叙述。

## 8. 结论必须分层

每个真实样本只允许使用以下四种状态：

- `PASS`：自然触发在真实个人库中找到了触发侧相关的真实多步轨迹，非触发侧没有压制它，轨迹和来源完整返回。
- `FAIL`：满足真实样本条件，但相关轨迹未被召回、被无关候选挤出预算、触发侧不相关，或输出丢失关键内容。
- `NOT OBSERVED`：该局没有自然产生需要测量的触发或局面。
- `INVALID SAMPLE`：使用了人工线索、注入记忆、手改状态、隐藏信息或其他破坏真实性的做法。

并且必须分别报告：

1. **唤醒是否通过**：只回答相关记忆有没有被自然想起。
2. **筛选是否通过**：回答想起后能否识别当前适用性、合法性和风险；这是下一阶段。
3. **规划是否改善**：回答候选、预测、选择或真实结果是否改变；不能由唤醒通过直接推断。

## 使用规则

以后每次真实 UFS 试玩若涉及“反馈学习是否生效”或“多步记忆是否被使用”，应在实验结果中引用本清单，并为每个测量样本附一份已填写的副本或等价机器记录。在出现至少一个有效真实样本前，真实可用性状态保持 `NOT OBSERVED`。
