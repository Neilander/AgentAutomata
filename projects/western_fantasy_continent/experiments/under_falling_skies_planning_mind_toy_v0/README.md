# 规划 MindToy V0

这是一个完全隔离、只有程序版的规划实验。它借用了《Under Falling Skies》的核心回合结构，但没有复制商业美术、地图或战役内容，也没有修改正式玩家 Agent。

## 它要回答什么

之前的“高维符文游戏”只负责一件事：把需求和候选项放进同一个 768 维语义空间，用点积找出“此刻最像我需要的东西”的候选。它适合快速联想，但它不知道行动顺序、资源依赖、未来状态和随机结果，因此本身不是规划器。

本实验在它外面加了一层真正的规划程序：

1. 从任务目标、玩家价值偏好、当前假设和局面压力组成当前需求方向。
2. 用 768 维空间召回语义相关的局部行动。
3. 用确定性规则检查能源、敌机下降、房间收益等实际后果。
4. 分别展开“研究冲刺、防守优先、建设优先”三条路线，模拟本回合剩余行动。
5. 用路线结束后的整体状态比较收益，只执行第一步，然后根据真实新状态重新规划。

因此它不是一个大模型 Prompt，也不是单纯的数学排序。它是一个混合程序：

```text
规则状态机
  + 768维语义召回（想到哪些局部行动）
  + 路线假设（想用什么办法赢）
  + 有限前瞻（这些行动组合起来会怎样）
  + 执行一步后的重规划
```

V0 暂时把三条路线假设写死，目的是先单独验证规划结构。以后可以让 AI 根据游戏上下文提出假设，但不应让 AI 直接篡改规则结果。

## 为什么选择这种游戏

每回合有五颗工人骰、每列只能放一颗，放置会同时带来房间收益和敌机下降；能源、研究、防御、挖掘之间存在明显依赖，而且白骰会重掷剩余骰子。这使它比纯排行榜更像规划问题，但状态仍足够小，可以逐项审计。

实验只保留上述核心结构。战役、城市能力、机器人、角色和商业版面均不在范围内。

## 文件

- `game-engine.js`：规则状态机和可复现随机数。
- `game-config.js`：紧凑教学盘面的规则数据。
- `semantic-space.js` / `artifacts/semantic-space.json`：768 维概念、房间和假设坐标。
- `planning-model.js`：需求组合、语义召回、路线展开、整体收益和重规划。
- `players.js`：随机、一步符文、冻结需求规划、动态需求规划四种对照。
- `run-experiment.js`：3 种玩家 × 4 种方法 × 80 个种子。
- `RESULTS.md`：当前结果和严格边界。

## 运行

```powershell
powershell -ExecutionPolicy Bypass -File .\run-local.ps1
```

已有 `semantic-space.json` 可以直接离线运行。只有重新生成 768 维向量时，才需要本地 GTE 模型和 Python 运行时。
