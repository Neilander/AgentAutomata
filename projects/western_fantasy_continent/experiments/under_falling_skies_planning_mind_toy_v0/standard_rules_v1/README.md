# 正式规则引擎 V1

当前已经完成的是“地图驱动的正式规则状态机”，不是完整正式地图，也还没有接规划玩家。

## 已实现

- 五颗工人骰、白骰放置后重掷、每列一骰。
- 高骰推动敌机、AA 减一、城市受伤。
- 箭头落点、母舰立即下降落点、爆炸格。
- 房间自由结算、能源成本、房间修正。
- 多格房间、逐格研究成本、最终研究必须多格房。
- 挖掘路径和每回合最多一个未挖掘放置。
- 紫机重生、白机被击落后移出、正式出生优先级。
- 母舰移动、行效果、骷髅失败。
- 机器人安装、占格、疲劳、逐次衰减、主动移除和被埋。
- Roswell/New York/Washington 所需的无能力、机器人上限和首次掷骰设值三类城市配置能力。

## 当前不能做什么

- 不能报告正式游戏胜率：真实天空、基地和城市组件尚未录入。
- 不能评价规划玩家：当前只有随机冒烟玩家，用于发现状态机卡死。
- 合成地图位于 `fixtures/synthetic-map.js`，只覆盖规则形状，不代表任何商业版图。

## 运行

```powershell
node test-standard-engine.js
node run-synthetic-smoke.js
```

收到真实组件图片后，先录入地图并通过 `map-contract.js`，再接现有 768 维召回和路线规划器。

## 基地 A / B 可视化录入

直接双击打开 `base-map-editor.html`。录入器固定按五列显示基地板，支持：

- A / B 板分别录入，并可按图片增加或删除行。
- Shift 多选，把相邻格子标成同一个多格房间。
- 记录房间类型、修正、能源消耗、解锁深度和挖掘路径顺序。
- 自动检查重复路径序号、同房间字段不一致等错误。
- 保存到浏览器、继续导入编辑，或导出 `ufs_base_map_entry_v1` JSON。

录入器只生成 `base` 部分，不会修改正式规则代码。用户确认 A/B 板后，再把导出结果与天空、城市数据合并为 `ufs_standard_map_v1`。

## 天空与城市可视化录入

直接双击打开 `sky-city-map-editor.html`。它负责正式地图剩余部分：

- 四块天空板的上下顺序、简单／威胁面；每块默认按实体组件固定显示 4 行。
- 五列天空格中的爆炸数字、左右箭头与母舰下降图标。
- 每行右侧母舰轨道的多个效果，以及唯一的骷髅失败行。
- Roswell 的最大伤害、初始／最大能源、机器人上限和研究轨道费用。
- 保存到浏览器、复制、导入和导出 `ufs_sky_city_entry_v1` JSON。
- 可导入之前的 `ufs_base_map_entry_v1`；基地数据只作为附件保留，不会被天空录入覆盖。

纯数据逻辑位于 `sky-city-map-model.js`。运行 `node test-sky-city-map-model.js` 可验证全局行拼接、箭头目标、母舰侧轨、骷髅行、天空板换序和往返导入。

## Roswell A+B 已核对数据

- `fixtures/roswell-base-ab.js`：用户录入并确认的 30 格、25 个房间，完整 30 格物理蛇形连接，以及从开局挖掘机位置开始的 20 格未来挖掘路径（含起点）。
- `test-roswell-base-ab.js`：检查房间数量、路径顺序、逐格解锁距离和首次挖掘。
- `render-roswell-base-ab.js`：生成 `artifacts/roswell-base-ab-review.svg`，用于在接正式地图前人工核对。

完整黄色通道从 A 右上开始：第一排向左、第二排向右；挖掘机开局停在 A 第三排右侧。未来路径继续沿 A 第三排向左，进入 B 后依次向右、向左、向右蛇形前进，最终结束在 B 右下。

## Roswell 威胁 0 完整地图

- `fixtures/roswell-threat-0-map.js`：合并 Roswell 未受损面、基地 A+B、四块天空简单面和从下到上的 16 格研究费用。
- 城市参数为最大伤害 7、初始能源 2、能源上限 7、机器人上限 2；研究轨道最后一格费用 11，仍要求多格研究室。
