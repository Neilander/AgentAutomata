# 五日正式试玩输入与学习结论审计

日期：2026-07-23

## 结论

两轮旧“正式盲测”不能证明玩家已经学会五日章节的核心系统。

原因有两类：

1. 五日章节没有接入项目已有的正式战斗模拟。六个事件挑战、三个战斗终局和荣誉决斗都以标量门槛或分数比较结算，因而没有角色技能、站位、目标选择、状态、治疗、护盾和战斗语义信号可供玩家学习。
2. 五日适配器把评测目标 `discover_new_capabilities` 发给了玩家 Agent。Run 1 和 Run 2 的每个决策请求都含有该目标，Agent 分别有 13/23 和 13/29 次主动选择它。它在招募、队伍协作、新区域、支线和资源转移上的探索行为因此受到评测脚手架直接推动。

旧档案保留为污染证据，不得继续称为“证明学习成功”的证据。

## 实际战斗实现审计

项目已有正式战斗入口：

- `game_data/combat-sim.js`
- `simulateTeams(leftTeam, rightTeam, options)`
- `simulateWaveTeams(leftTeam, waves, options)`

该运行时支持四人编队、前后排、角色技能与被动、终结技、伤害类型、治疗、护盾、控制、持续伤害、战斗日志和语义信号。

五日程序没有调用它。当前标量结算点包括：

- 守炉甲胄
- 军需车正面袭击
- 擂台冠军
- 旁支剑士比剑
- 断角兽狩猎
- 营地夜袭
- 正面迎击、守城、伏击三个战斗终局
- 荣誉决斗

因此旧试玩只能说明 Agent 会读取并优化显示数字，不能说明它学会战斗、角色用途、阵容搭配或针对敌方构成进行准备。

## 玩家请求逐字段审计

### 未发现的直接答案字段

两轮 decision request 的 `observation.actions` 均未包含：

- `internalId`
- `outcome`
- `reasons`
- 锁定条件
- 未来节点

行动 ID 为不透明 ID。初始画面没有直接列出王炉门的三种解法。这部分边界有效。

### 确认存在的污染

| 污染 | Run 1 | Run 2 | 影响 |
|---|---:|---:|---|
| 每次 decision request 暴露 `discover_new_capabilities` | 23/23 | 29/29 | 直接诱导寻找新交互 |
| Agent 实际选择该目标 | 13/23 | 13/29 | 招募、协作、资源转移和支线探索不能算自然发现 |
| `open_novice` 高探索画像与“尝试新选项可能发现策略”先验 | 23/23 | 29/29 | 单一高探索路线不能代表普通玩家群体 |
| 回复合同要求写 `affordance` | 23/23 | 29/29 | Agent 被强制用可行动机会的语言解释，不等于游戏自然形成该概念 |
| 每个行动后强制归因 | 23/23 | 29/29 | 归因文本证明它能复述反馈，不自动证明长期迁移学习 |
| 行动点事件带 `actionPointMark`，刷图行动不带 | 22/23 个决策画面为混合显示 | 26/29 个决策画面为混合显示 | 免费刷图成本是界面明示，不是玩家自行推导 |

玩家画像、可见成本和结构化归因本身可以是正式模拟的一部分；问题是旧报告把这些脚手架推动出来的行为写成了游戏自然教会玩家。

### 确认存在的结果文案泄漏

- Run 1 明说“守炉甲胄的挑战门槛降低”。
- Run 1 失败信息用“当前战力不足以压倒它”解释守炉结果。
- 当前旧代码曾明说“下次正面路线门槛降低”。
- Run 1 的贵族身份行动在事后日志恢复了 `[贵族]` 条件名。
- Run 2 的恐怖身份行动在事后日志恢复了 `[恐怖]` 条件名。
- Run 2 的情报日志宣称“四条可利用弱点持续可见”，但玩家态势板实际只显示名单，没有显示四条弱点内容。这不是答案泄漏，而是错误反馈。

当前程序已把前三类设计师解释改成现场物理现象，并继续保留旧原始档案作为污染证明。

## 旧学习结论逐条处理

| 原结论 | 审计结论 | 可保留的最小事实 |
|---|---|---|
| 玩家学会刷图不耗行动点 | 作废为“学习” | 界面成本已经明示；Agent据此使用免费行动 |
| 玩家学会装备必须显式穿戴 | 只证明观察和复用 | 装备后显示精确战力变化，Agent随后重复使用穿戴/一键穿戴 |
| 玩家学会新队友能打开队伍协作 | 污染 | 协作按钮出现时，Agent正使用暴露的探索目标和高探索画像 |
| 玩家学会镇民支持可转成情报 | 污染 | Agent看见新出现的明确按钮后使用了资源；不能证明跨情境自主发现 |
| 玩家从失败学会证据能说服剑士 | 有行为链，但不足以证明一般化 | 两次比剑失败后收集证据并选择新出现的“三份证据”行动；仍受探索目标影响，且没有新情境迁移测试 |
| 玩家学会身份词条能开交涉路线 | 作废 | 事后日志恢复了身份条件名，没有无提示跨场景迁移证据 |
| 玩家根据一对一情报强化主角 | 可保留为对明示情报的行为响应 | NPC 明说一对一后，Agent把新饰品给主角；这不是隐藏规则发现 |
| 玩家学会阵容/战斗针对 | 作废 | 五日版没有运行正式战斗，只有显示战力比较 |

## 已完成的边界修正

- decision request 过滤评测目标 `discover_new_capabilities`。
- Agent 返回评测目标时程序直接拒绝。
- decision request 不再发送知识检索器的调试审计。
- 回复合同不再强迫 Agent 使用 `affordance` 术语，只要求意图、证据或比较。
- 守炉失败不再报告“当前战力不足”。
- 卡冷却阀只报告铜管和甲胄动作变化，不报告“门槛降低”。
- 军需车失败只报告暗沟、土坡和守卫视线，不报告“路线门槛降低”。
- 新增 `verify-formal-player-input-boundary.js` 锁定以上边界。

## 下一次有效验证的前提

1. 先把五日所有战斗节点接到 `game_data/combat-sim.js`，战后只把玩家可见语义信号送入认知循环。
2. 冻结一版输入合同后从零开始新跑，不能续用两轮污染会话。
3. 使用多个持久画像；不能只用高探索 `open_novice`。
4. “学会”必须要求在没有评测目标、没有结果文案答案、没有明确结果按钮标签的新情境中迁移成功。
5. Agent 的归因陈述只能作为假设；必须由后续行为和对照情境验证。
