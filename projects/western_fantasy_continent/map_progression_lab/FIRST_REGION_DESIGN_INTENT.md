# 第一地区设计目的树

这份文件与第一地区运行代码放在同一目录，是地图调整时必须先读的设计契约。
它记录的是因果结构，不是某一版敌人数值。修改 `map-progression-cognition-core-phase2-midlock.js`
或 `map-progression-encounters.js` 前，先判断改动属于“不可变目的”还是“可调实现”。

```text
第一地区：让玩家珍惜完整英雄，并学会主动取得、换上、验证新角色
|
+-- A. 开局认知
|   +-- 完整英雄稀缺；民兵只能承担极端、残缺的功能
|   +-- Main 1-3 允许当前队伍稳定推进并建立装备基础认知
|   `-- Main 2 解锁法师到角色名单，但不自动换入队伍
|
+-- B. 核心锁钥链（不可改变顺序）
|   +-- Main 3 后：监狱出现，玩家看见“游侠”及其持续单体输出价值
|   +-- 监狱第一次：多数状态失败，形成“我想拿到这个角色”的目标
|   +-- Main 4-5：不需要监狱、营地或游侠也能继续推进
|   +-- Main 5 后：军械营地出现，提供可见的监狱攻坚装备
|   +-- 再战监狱：装备钥匙明显提高成功率
|   +-- 监狱首通：游侠加入名单，不自动入队
|   +-- 玩家手动换上游侠
|   `-- Main 7：高生命单体战验证游侠持续输出价值
|
+-- C. 支线契约（不可改变）
|   +-- 监狱与营地是可选支线，不授予主线通行许可
|   +-- 两者失败后都可重试，首通核心奖励只能领取一次
|   +-- 忽略支线的玩家仍可推进；后续只能制造摩擦，不能形成硬锁
|   `-- 幸运提前通过监狱是合法旁路，后续角色验证仍必须成立
|
+-- D. 玩家必须亲自完成的行为（不可改变）
|   +-- 挑战监狱
|   +-- 取得并装备攻坚装备
|   +-- 营救游侠
|   +-- 把游侠换入队伍
|   `-- 在真实战斗贡献中看见游侠价值
|
+-- E. 可调实现
|   +-- 敌人组成、生命、攻击、防御和技能
|   +-- 掉落等级、数量和概率
|   +-- 提示措辞与视觉表现
|   +-- 监狱首次/营地后通过率的具体目标区间
|   `-- 验证关的压力强度（但必须位于可取得游侠之后）
|
`-- F. 验收
    +-- 结构：不存在 Main -> Camp -> Prison -> Ranger -> earlier Main 的循环依赖
    +-- 机械：Main 4-5 的基础队可推进；营地装备显著提高监狱胜率
    +-- 角色：带游侠的合理队伍在 Main 7 明显优于相近的非游侠队伍
    +-- 认知：知识受限 Agent 能看见监狱、理解奖励、失败/取钥匙、重试、营救、手动换人
    `-- 证据：每次设计改动都必须产生新的玩家模拟记录，不能只用静态胜率代替
```

## 调整红线

以下改动看似能“修好胜率”，实际会破坏地图目的：

- 把需要游侠的关放到游侠可取得之前。
- 要求先通监狱才能继续 Main 4-5。
- 营救后自动把游侠塞进队伍。
- 只在文字里宣布游侠很强，却没有真实贡献差异。
- 用敌方临时削弱掩盖锁钥关系，或者让不拿游侠的路线永久卡死。

机器可检查版本见 `first-region-design-intent.json`。
