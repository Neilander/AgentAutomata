# Distillation State

Goal: convert experience research and the current game type into traits a good game of this type should have.

## Method: Loop Analysis

Use when the research reveals a repeated player loop.

Example loop for loot games:

```text
goal -> drop perception -> improvement -> verification -> new goal
```

Important requirements:

- The player needs a visible goal.
- The player needs to perceive drops as meaningful.
- The player needs to understand how a drop improves something.
- The player needs a place to verify the improvement.
- Failure should tell the player where the build is weak.
- Verification should produce the next goal.

## Method: System-Role Analysis

Use when analyzing a build system.

A build ecosystem can contain roles such as:

- core engine: the thing the build is really built around;
- style assistant: components that strengthen or stabilize a specific style;
- general utility hand: broadly useful supports that solve survival, resource, or convenience problems.

When judging a character, relic, item, or skill, ask whether it is an engine, assistant, utility, bridge, or payoff.

## Method: Progression-Layer Analysis

Use when analyzing growth and player cognition.

Example layer sequence:

1. Profession combo creates the first visible improvement.
2. Equipment base stats create the next improvement.
3. Equipment affixes create more directed improvement.
4. Artifacts/relics unlock, and players study artifact plus profession combos.
5. Artifact/relic growth becomes its own layer.
6. Players return to farming equipment affixes with deeper understanding.

The purpose is not to lock this exact sequence. The purpose is to keep player cognition layered, so players are not asked to understand every system at once.
